Edit Distance vs Set, Vector, and N-Gram Similarity

Levenshtein distance, Jaccard similarity, cosine similarity, and n-gram or q-gram similarity are often used interchangeably in fuzzy matching systems, yet they measure fundamentally different geometric relationships.

The difference begins before any formula is evaluated.

Levenshtein:
string
->
ordered sequence

Jaccard:
object
->
set of features

Cosine:
object
->
weighted vector

q-gram similarity:
string
->
overlapping local substrings
->
set, multiset, or vector.

Once a string is converted from an ordered sequence into a set or vector of features, some information is intentionally discarded. That loss can make similarity dramatically more robust to reordering, long documents, and large-scale retrieval—but it can also collapse strings whose sequence structure is crucial.

Consider:

ABCD
BCDA.

Levenshtein sees a sequence shift that requires edits.

A character-set representation sees:

{A,B,C,D}
=
{B,C,D,A}

and therefore reports perfect set similarity.

Neither answer is universally correct.

They answer different questions.

The central principle of this comparison is:

changing the representation
changes the neighborhood geometry.

This article develops that principle from first principles. It compares Levenshtein distance with Jaccard and Dice set similarity, multiset overlap, cosine similarity, term-frequency and TF-IDF vectors, character n-grams, q-gram profiles, MinHash-style sketches, and scalable filter-and-verify architectures. Particular attention is given to the mathematical relationship between q-gram distance and edit distance, including Ukkonen's q-gram bound.

Set No No Jaccard / Dice
Vector / bag Usually no Yes or weighted Cosine / vector distance

3. Every representation answers a different question

Character sequence asks:

How can one ordered character sequence
be transformed into another?

Character set asks:

Which character types occur
in both objects?

Character-count vector asks:

Are their symbol-frequency profiles similar?

q-grams ask:

Do they share local ordered fragments?

4. More information is not always better

Preserving global order makes Levenshtein highly informative about exact sequence structure.

It also makes the metric sensitive to:

  • block movement;
  • token reordering;
  • long inserted regions;
  • document rearrangement.

5. Discarding information creates invariance

A bag-of-words representation ignores word order.

That is useful when:

word ordering changes
but topic remains the same.

It is disastrous when:

word ordering determines meaning.

6. There is no free invariance

ignore a distinction
->
gain robustness to that distinction

but also

lose ability to detect
when that distinction matters.

7. Levenshtein's sequence geometry

Classic Levenshtein distance permits:

insertion

deletion

substitution.

For:

X = x1...xm

Y = y1...yn,

the recurrence is:

D(i,j)
=
min(
 D(i-1,j) + 1,
 D(i,j-1) + 1,
 D(i-1,j-1) + [xi != yj]
).

8. Levenshtein preserves complete sequence order

The algorithm searches for an optimal monotone alignment between the two symbol sequences.

Characters cannot simply be rearranged for free.

9. Example: block reordering

X:
ABCXYZ

Y:
XYZABC.

The symbol inventories are identical.

But the sequence order differs strongly.

10. Character-set similarity sees identity

set(X)
=
{A,B,C,X,Y,Z}

set(Y)
=
{A,B,C,X,Y,Z}.

Therefore:

Jaccard = 1.

11. Levenshtein does not

Moving the block:

ABC

to the end is not one primitive edit.

It must be represented using deletions, insertions, or substitutions.

12. This illustrates representation mismatch, not algorithm error

If block order matters, Levenshtein is more informative.

If the application only cares which symbols occur, the set model may be more appropriate.

13. Set representation

Map an object X to a finite set of features:

F(X).

Features may be:

  • characters;
  • words;
  • q-grams;
  • tokens;
  • attributes;
  • document shingles.

14. Jaccard similarity

For sets:

A
and
B,

define:

J(A,B)
=
|A ∩ B|
/
|A ∪ B|.

15. Jaccard range

0 <= J <= 1.

With:

J = 1

for identical sets and:

J = 0

for disjoint nonempty sets.

16. Jaccard distance

A corresponding set distance is:

dJ(A,B)
=
1 - J(A,B).

For finite sets, Jaccard distance is a mathematical metric.

17. Jaccard deliberately ignores duplicate features

Consider:

X:
red red red blue

Y:
red blue.

As sets:

A = {red,blue}

B = {red,blue}.

Therefore:

J = 1.

18. Frequency information disappeared

The first object contains:

red x3

while the second contains:

red x1.

Set representation intentionally discards that difference.

19. This can be useful for presence/absence data

If the question is:

Which feature types occur?

multiplicity may be irrelevant.

20. It can be disastrous for behavioral counts

For log events:

RETRY x3

and:

RETRY x300000

should often not be considered identical.

21. Dice similarity

For sets:

Dice(A,B)
=
2|A ∩ B|
/
(|A|+|B|).

22. Historical Dice coefficient

Lee R. Dice's 1945 ecological association paper is one of the foundational sources for this overlap form.

See Dice, 1945.

23. Jaccard and Dice contain the same ordering information for fixed representations

Given:

J
=
|A∩B|/|A∪B|,

Dice is:

D
=
2J
/
(1+J).

Conversely:

J
=
D
/
(2-D).

24. Therefore they rank pairs identically when computed from the same two sets

The numerical scales differ.

The underlying intersection/union information does not.

25. Do not compare raw thresholds directly

Jaccard >= 0.8

and:

Dice >= 0.8

are not equivalent acceptance rules.

26. Convert thresholds analytically if necessary

For example, if:

J = 0.8,

then:

Dice
=
1.6 / 1.8
≈
0.8889.

27. Containment differs from symmetric resemblance

Suppose:

A

is a short set of features and:

A ⊂ B

where B is much larger.

Jaccard can be low because the union is dominated by B.

28. Containment coefficient

An asymmetric measure can be:

C(A,B)
=
|A ∩ B|
/
|A|.

This asks:

How much of A
is contained in B?

29. Broder's document resemblance and containment

Andrei Broder formalized resemblance and containment for near-duplicate document detection using shingle sets and sampling.

See On the Resemblance and Containment of Documents.

30. Symmetry matters

J(A,B)
=
J(B,A).

But:

C(A,B)

need not equal:

C(B,A).

31. Containment is useful for plagiarism or inclusion-style questions

A short document can be almost completely contained in a much larger document even though their symmetric Jaccard resemblance is modest.

32. This is analogous to full-string versus substring matching

Full-string edit distance asks whether two entire strings are close.

Containment asks whether most of one representation occurs inside another.

33. A similarity formula must match the query direction

Do not use symmetric resemblance when the true question is:

Is A contained in B?

34. Multisets

A multiset retains feature multiplicity.

Let:

c_A(g)

be the number of occurrences of feature g in object A.

35. Multiset intersection count

|A ∩ B|_multi
=
Σ_g
min(
 c_A(g),
 c_B(g)
).

36. Multiset union count

|A ∪ B|_multi
=
Σ_g
max(
 c_A(g),
 c_B(g)
).

37. Multiset Jaccard

J_multi(A,B)
=
Σ_g min(c_A(g),c_B(g))
/
Σ_g max(c_A(g),c_B(g)).

38. This distinguishes repeated features

For:

X:
red red red blue

Y:
red blue,

multiset intersection has size:

2

and multiset union:

4.

Therefore:

J_multi = 0.5.

Even after choosing q-grams, for example, one must decide:

multiset?

weighted vector?

40. Vector representation

Choose a feature vocabulary:

V
=
{f1,f2,...,fd}.

Represent object X as:

x
=
(x1,x2,...,xd)

where each coordinate stores a feature weight.

41. Binary vectors

x_i =
1 if feature i occurs
0 otherwise.

This is essentially a set representation written algebraically.

42. Count vectors

x_i
=
number of times feature i occurs.

This preserves multiplicity.

43. Weighted vectors

Coordinates can instead store:

  • normalized frequency;
  • TF-IDF;
  • business importance;
  • learned weights.

44. Vector-space retrieval

Salton, Wong, and Yang's 1975 work is a foundational treatment of vector-space representations for automatic indexing.

See A Vector Space Model for Automatic Indexing.

293. Reference pseudocode: Jaccard

function jaccard(A, B):

    if A and B are empty:
        return 1

    intersection =
        size(A intersect B)

    union =
        size(A union B)

    return
        intersection / union

294. Reference pseudocode: Dice

function dice(A, B):

    if A and B are empty:
        return 1

    common =
        size(A intersect B)

    return
        2 * common
        /
        (size(A) + size(B))

295. Reference pseudocode: multiset Jaccard

function multiset_jaccard(countA,
                          countB):

    intersection = 0
    union = 0

    for each feature g
        in keys(A) union keys(B):

        intersection +=
            min(
              countA[g],
              countB[g]
            )

        union +=
            max(
              countA[g],
              countB[g]
            )

    if union == 0:
        return 1

    return
        intersection / union

296. Reference pseudocode: cosine

function cosine(x, y):

    dot = 0
    norm_x = 0
    norm_y = 0

    for feature g:

        dot +=
            x[g] * y[g]

        norm_x +=
            x[g]^2

        norm_y +=
            y[g]^2

    if norm_x == 0
       or norm_y == 0:
        handle zero-vector policy

    return
        dot
        /
        (
          sqrt(norm_x)
          *
          sqrt(norm_y)
        )

298. Reference pseudocode: q-gram extraction

function qgrams(S, q):

    grams = []

    if q <= 0:
        error

    if len(S) < q:
        return grams

    for i in 0..len(S)-q:

        grams.append(
            S[i : i+q]
        )

    return grams

function qgram_profile(S, q):

    profile =
        empty frequency map

    for g in qgrams(S, q):

        profile[g] += 1

    return profile

300. Reference pseudocode: q-gram L1 distance

function qgram_distance(X, Y, q):

    px =
        qgram_profile(X,q)

    py =
        qgram_profile(Y,q)

    distance = 0

    for g in
        keys(px) union keys(py):

        distance +=
            abs(
              px[g] - py[g]
            )

    return distance

348. Final interpretation

The most important distinction between edit distance and set, vector, and n-gram similarity is not the mathematical formula used at the final step. It is the representation of the object before that formula is applied.

Levenshtein distance operates directly on an ordered sequence. Every insertion, deletion, and substitution participates in a global alignment, so long-range order remains part of the geometry. This is ideal when those edits genuinely define the differences the application cares about.

Jaccard and Dice instead compare sets of features. They intentionally forget feature multiplicity and order. This makes them robust to rearrangement and useful for overlap-oriented problems, but two distinct strings can become identical after set conversion. Their score means:

shared feature types
relative to feature inventory,

not:

minimum sequence transformation.

Vectors retain more information. Count vectors preserve multiplicity, TF-IDF vectors incorporate corpus-level rarity, and cosine similarity compares the direction of weighted feature profiles rather than absolute sequence length. This makes vector-space methods particularly powerful for information retrieval, where a long document and a short document can discuss the same subject with similar feature proportions.

Character and token n-grams occupy an important middle ground. They discard global order while preserving local adjacency. This allows strings and documents to survive local edits, movement, and partial rearrangement more gracefully than full sequence alignment, while still retaining substantially more structure than unordered sets of individual characters or words.

But “n-gram similarity” is not one metric. A q-gram representation can be converted into:

These systems can rank the same candidate pairs differently because they preserve different information.

Ukkonen's q-gram result reveals an especially important relationship with edit distance. If d_q is the L1 distance between q-gram count profiles and d_edit is unit-cost edit distance, then:

d_q(X,Y)
<=

Therefore:

This allows q-grams to serve not merely as an alternative similarity representation but as a computational filter for exact edit-distance search. A candidate whose q-gram lower bound already exceeds the target threshold can be rejected before dynamic programming is run.

In such a pipeline, q-grams provide scalability while Levenshtein retains final semantics. The two techniques are collaborators rather than competitors.
