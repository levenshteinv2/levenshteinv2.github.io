Tree & Graph Edit Distance: Models, Algorithms, Complexity & GED

Tree and Graph Edit Distance

Edit distance is not limited to strings. The same fundamental idea—measuring dissimilarity by the minimum cost of transforming one object into another—extends to hierarchical structures such as trees and to relational structures such as graphs. The resulting measures are known as tree edit distance (TED) and graph edit distance (GED).

These measures preserve the central philosophy of Levenshtein distance:

distance
=
minimum cost
of a valid transformation

but the geometry of the objects changes completely.

A string has one linear order:

a → b → c → d

A tree has hierarchical ancestry and, in many formulations, sibling order:

        root
       /    \
      A      B
     / \
    C   D

A graph may contain arbitrary connectivity:

A ─── B
│   ╱ │
│ ╱   │
C ─── D

As a consequence, replacing one-dimensional sequence alignment with structural alignment changes both the mathematical definition of an edit and the complexity of finding an optimal edit script.

Classical string edit distance can be solved by dynamic programming in quadratic time. Classical ordered tree edit distance historically required cubic or higher polynomial time in the worst case, although important recent results have broken that barrier for unweighted trees. General graph edit distance is harder still: exact computation is NP-hard even under simple uniform edit-cost models.

The central lesson is therefore:

string edit distance
≠
tree edit distance
≠
graph edit distance

They belong to the same family of transformation-based similarity measures, but their state spaces, admissible mappings, algorithms, and complexity regimes are fundamentally different.

From sequences to structured objects

For strings:

x = x₁x₂...xₘ
y = y₁y₂...yₙ

an alignment must preserve the natural left-to-right order of positions.

For trees, a valid correspondence typically must preserve:

  • one-to-one node matching;
  • ancestor relationships;
  • and, for ordered trees, left-to-right sibling order.

For general graphs, even ancestry disappears. A candidate correspondence between vertices must instead be evaluated according to the connectivity induced between matched vertices.

This progression can be viewed as a loss of structural constraints:

STRING
│
│ fixed total order
▼
TREE
│
│ partial hierarchical order
▼
GRAPH
│
│ arbitrary relational structure
▼
GENERAL STRUCTURAL MATCHING

The fewer constraints available, the larger the correspondence space usually becomes.

Why flattening structure into a string can be wrong

Suppose two rooted trees have identical preorder traversals:

root A B

but different topology.

Tree 1

      root
      /  \
     A    B

Tree 2

      root
       |
       A
       |
       B

Their preorder sequences are identical:

root, A, B

so ordinary string edit distance between the traversals is:

0

Yet the trees are structurally different.

Tree edit distance captures this difference because the parent-child relationship of B has changed.

This illustrates a fundamental principle:

A serialization preserves structure only if the structural information itself is encoded into the serialization.

Flattening XML, JSON, abstract syntax trees, biological structures, or scene graphs into label sequences can therefore destroy precisely the information that a structural distance is intended to measure.

Tree edit distance

The classical tree edit distance problem is defined on rooted, ordered, labeled trees.

Let:

T₁ = (V₁,E₁,r₁,λ₁)

T₂ = (V₂,E₂,r₂,λ₂)

where:

  • V is the node set;
  • E is the parent-child edge set;
  • r is the root;
  • λ(v) is the label of node v;
  • children of every node have a fixed left-to-right order.

The tree edit distance is the minimum total cost of a valid sequence of tree-edit operations that transforms:

T₁
into
T₂

The three classical tree edit operations

Node relabeling

Change:

label(u) = a

to:

label(u) = b

without changing tree topology.

Node deletion

Deleting a node in classical TED does not necessarily delete its entire subtree.

Suppose:

       P
       |
       X
     / | \
    A  B  C

Deleting:

X

produces:

       P
     / | \
    A  B  C

The children of the deleted node are reattached to its parent while preserving their relative order.

This is one of the most important differences between classical tree edit distance and many application-specific notions of "delete a tree node."

Node insertion

Insertion is the inverse operation.

Starting with:

       P
     / | \
    A  B  C

one may insert:

X

between:

P

and a consecutive sequence of its children:

       P
       |
       X
     / | \
    A  B  C

More generally, the inserted node becomes the parent of an appropriate consecutive subsequence of existing children in an ordered-tree formulation.

Tree-node deletion is not subtree deletion

The distinction is worth making explicit:

classical TED node deletion:

       A
       |
       B
      / \
     C   D

delete B

       A
      / \
     C   D

versus:

subtree deletion:

       A
       |
       B
      / \
     C   D

delete subtree at B

       A

These define different edit systems and therefore different distances.

A software library implementing one should never be assumed to implement the other.

Weighted tree edit distance

Let:

c_del(a)

c_ins(b)

c_ren(a,b)

be the costs of deleting, inserting, and relabeling nodes.

Then:

TED(T₁,T₂)
=
minimum total cost
over all valid edit scripts

Unit-cost tree edit distance uses:

c_del = 1

c_ins = 1

c_ren(a,b) =
    0 if a=b
    1 otherwise

Weighted TED allows the cost model to encode domain knowledge.

Example

For syntax trees one might define:

identifier → identifier:
0.2

integer_literal → float_literal:
0.4

if_statement → while_statement:
2.0

if those transformations have different semantic significance.

However, once weights are introduced, algorithms and complexity results derived specifically for unit-cost TED may no longer apply.

Tree mappings: another definition of TED

Tree edit distance can equivalently be described through a structural node mapping.

Let:

M
⊆
V₁ × V₂

be a set of matched node pairs.

A classical ordered-tree mapping satisfies several constraints.

One-to-one correspondence

For:

(u,v)
and
(u',v')
in M

we require:

u = u'
iff
v = v'

so one node cannot match multiple nodes.

Ancestor preservation

If:

u₁
is an ancestor of
u₂

then their matched nodes must satisfy:

v₁
is an ancestor of
v₂

and conversely under the standard mapping formulation.

Left-to-right order preservation

If:

u₁
lies to the left of
u₂

in the ordered tree, their images must preserve the same relative order.

Cost of a tree mapping

For a valid mapping:

M

the cost can be written schematically as:

cost(M)
=
Σ matched nodes
    relabel_cost

+
Σ unmatched nodes in T₁
    deletion_cost

+
Σ unmatched nodes in T₂
    insertion_cost

and:

TED(T₁,T₂)
=
min_M cost(M)

This formulation is useful because it turns the problem from:

search over edit scripts

into:

search over valid structural correspondences

while preserving the same optimum under the classical edit model.

Why ancestor preservation matters

Consider:

T₁:

A
|
B
|
C

and:

T₂:

A
|
C
|
B

A label-only assignment could pair:

A ↔ A
B ↔ B
C ↔ C

at zero relabeling cost.

But the ancestry relations are reversed for:

B
and
C

so this is not a valid classical tree mapping.

Tree edit distance therefore measures structural compatibility, not merely optimal label assignment.

Why sibling order matters

For ordered trees:

root
├── A
└── B

and:

root
├── B
└── A

are structurally different because:

A before B

has become:

B before A

Classical insert/delete/relabel TED does not contain a primitive sibling-swap operation.

Consequently reordering may require multiple edits.

Ordered versus unordered trees

An ordered tree assigns significance to sibling order.

An unordered tree does not.

Ordered

root
├── A
└── B

differs from:

root
├── B
└── A

Unordered

Those two trees represent the same topology and labeling modulo sibling permutation.

Removing order makes the problem harder, not easier

This can initially seem counterintuitive.

One might expect:

fewer constraints
=
easier matching

but fewer constraints also mean more possible correspondences must be considered.

For ordered trees, sibling order eliminates enormous numbers of mappings automatically.

For unordered trees, permutations among sibling sets must be considered.

Zhang, Statman, and Shasha showed that computing edit distance between unordered labeled trees is NP-complete even for binary trees over an alphabet of size two.

Thus:

ordered rooted TED:
polynomial-time solvable

unordered TED:
NP-complete in general

under the corresponding classical formulations.

Rooted versus unrooted trees

A rooted tree has a distinguished node:

r

which determines:

  • parent-child direction;
  • ancestor relations;
  • subtree boundaries.

An unrooted tree has no distinguished root.

Comparing unrooted trees may therefore involve considering alternative root placements or using algorithms specifically designed to avoid explicitly enumerating every rooting.

This produces another distinct algorithmic problem.

Node-labeled versus edge-labeled trees

Classical TED is commonly stated for node-labeled trees.

Other formulations label edges instead:

parent
  |
 "contains"
  |
 child

or attach attributes to both.

The edit operations must then specify whether costs apply to:

  • nodes;
  • edges;
  • both;
  • or transformations induced by edge contraction and splitting.

Results for one formulation should not automatically be transferred to another without verifying their equivalence.

Tree edit distance as dynamic programming

The central reason ordered TED remains tractable is that subtrees and forests have reusable optimal substructure.

A tree can be decomposed into ordered forests:

F =
T₁ T₂ ... T_r

where each:

T_i

is a subtree.

The algorithm recursively evaluates distances between subforests rather than enumerating all possible node mappings directly.

The tree analogue of string-prefix DP

String edit distance works over:

prefix x[1..i]
versus
prefix y[1..j]

Tree edit distance generalizes this idea to:

forest prefix
versus
forest prefix

The recurrence again considers:

  • delete;
  • insert;
  • match/relabel.

But removing a tree node can expose several children, so the state boundaries are structurally more complicated than string prefixes.

Postorder numbering

Many classical algorithms number tree nodes by postorder.

For:

        A
       / \
      B   C
     / \
    D   E

a postorder is:

D
E
B
C
A

and the nodes may be numbered:

D = 1
E = 2
B = 3
C = 4
A = 5

Leftmost-leaf descendants

For each node:

i

define:

l(i)

as the postorder index of its leftmost leaf descendant.

For the example:

l(D) = 1
l(E) = 2
l(B) = 1
l(C) = 4
l(A) = 1

These values identify contiguous postorder intervals corresponding to subtrees.

Keyroots

The Zhang–Shasha algorithm exploits a set of nodes called keyroots.

Informally, a node is a keyroot when it is:

  • the root;
  • or has a leftmost-leaf descendant not already represented by a later node in the relevant decomposition.

Equivalent descriptions use nodes with a left sibling together with the tree root.

Rather than solving a forest-distance problem independently for every node pair, the algorithm computes only the necessary keyroot combinations.

Zhang–Shasha forest recurrence

For a pair of keyroot-defined forests, define:

FD[i][j]

as the minimum cost of transforming the relevant forest prefix ending at:

i

into the forest prefix ending at:

j

A simplified recurrence has the familiar edit-distance shape:

FD[i][j]
=
min(
    FD[i-1][j]
        + delete(i),

    FD[i][j-1]
        + insert(j),

    structural_match_case
)

When:

i
and
j

are roots of the currently considered subtrees, the match case is:

FD[i-1][j-1]
+
relabel(i,j)

Otherwise the algorithm combines:

distance between preceding forests

+

previously computed
distance between subtrees
rooted at i and j

This reuse of subtree distances is what makes tree dynamic programming feasible.

Why tree DP has an extra complexity dimension

For strings there is essentially one meaningful way to reduce a prefix:

remove the last character

For trees there are many possible structural decomposition paths:

leftmost path
rightmost path
heavy path
subtree decomposition
...

The choice of decomposition affects how many subproblems are generated.

This is why much of the history of exact TED algorithms is really a history of better decomposition strategies.

Tai's tree-to-tree correction algorithm

Kuo-Chung Tai's 1979 work established one of the foundational algorithms for tree-to-tree correction.

It demonstrated that ordered tree edit distance could be solved through dynamic programming, but its worst-case running time was high.

For equal-size trees, the classical complexity progression is often summarized approximately as:

For trees:

Its number of leaves is small even though its depth is large.

The:

Bushy trees

Depth is small even though the number of leaves is large.

Again:

Decomposition strategies

A decomposition strategy determines which path of a subtree is used to split the problem into smaller forest-distance computations.

Common choices include:

left path

right path

heavy path

A heavy path follows a child whose subtree contains the largest number of nodes.

By choosing paths carefully, algorithms can reduce repeated work.

Demaine–Mozes–Rossman–Weimann

Demaine, Mozes, Rossman, and Weimann developed an optimal decomposition-strategy algorithm for classical ordered tree edit distance.

For two equal-size trees, the resulting worst-case bound is:

O(n³)

within the decomposition framework studied there.

For unequal sizes:

m ≤ n

their analysis gives a more refined bound involving:

Θ(
    n m²
    (
        1 + log(n/m)
    )
)

for decomposition-strategy algorithms in the corresponding formulation.

Why O(n³) became a long-standing barrier

The decomposition framework covers essentially all classical fast TED algorithms of that family.

Demaine and colleagues established matching upper and lower bounds inside that framework.

Therefore breaking cubic time required something fundamentally different from merely selecting a better left, right, or heavy path.

RTED: robust tree edit distance

Different classical decomposition strategies can perform very differently depending on tree shape.

A strategy that is excellent for:

deep path-like trees

may perform poorly for:

bushy balanced trees

and vice versa.

RTED, developed by Mateusz Pawlik and Nikolaus Augsten, chooses its decomposition strategy dynamically based on the actual input trees.

The objective is:

do not require the caller
to predict the tree shape
for which one classical
strategy will be best

LRH strategies

RTED formalized a family of:

Left
Right
Heavy

or:

LRH

decomposition strategies.

It computes an input-dependent strategy that is optimal within that family and is no worse asymptotically on an instance than the competing LRH choices analyzed in the framework.

APTED

Later work by Pawlik and Augsten generalized the strategy framework and addressed memory consumption.

APTED—All Path Tree Edit Distance—uses an optimal strategy in a broader all-path class and improves practical memory behavior relative to RTED.

This matters because:

theoretically acceptable
time complexity

does not guarantee:

acceptable memory behavior

for large XML, JSON, syntax, or biological trees.

Practical TED and theoretical TED are different optimization targets

Classical algorithms optimize:

number of subproblems

while implementations must also optimize:

  • cache locality;
  • memory allocation;
  • matrix reuse;
  • tree traversal representation;
  • label-comparison cost;
  • parallelism.

For typical small and medium trees, APTED-style algorithms may be much more relevant than algorithms based on asymptotically fast matrix multiplication despite having weaker asymptotic exponents.

The modern complexity frontier for tree edit distance

The complexity picture changed substantially after the classical cubic era.

Crucially, one must distinguish:

weighted TED

from

unweighted TED

because they now have different best-known complexity regimes.

Fine-grained hardness for weighted TED

Bringmann, Gawrychowski, Mozes, and Weimann showed that a truly subcubic algorithm for weighted tree edit distance would imply major improvements for other central problems such as All-Pairs Shortest Paths under the relevant alphabet and cost regimes.

Thus the classical statement:

TED appears cubic

was strengthened into a conditional fine-grained statement:

general weighted TED
is unlikely to admit
O(n^(3-ε))

for fixed ε > 0

under the APSP-style hardness framework.

This lower bound does not apply unchanged to unweighted TED

This distinction became decisive.

If every:

insertion
deletion
relabeling

has unit cost, additional combinatorial structure becomes available.

Xiao Mao broke the classical cubic barrier for unweighted rooted tree edit distance.

The original result achieved:

O(
    n^2.9546
)

time by reducing parts of TED computation to structured bounded-difference min-plus products.

2025: a much faster unweighted TED bound

More recent work by Nogler, Polak, Saha, Vassilevska Williams, Xu, and Ye substantially improved the unweighted complexity.

For rooted ordered unweighted TED, their 2025 result gives:

Õ(
    n^((3+ω)/2)
)

where:

ω

is the exponent of matrix multiplication.

With the matrix-multiplication bounds used in the analysis, this is reported as at most approximately:

O(
    n^2.6857
)

up to the suppressed factors and exact exponent assumptions.

Weighted TED and APSP equivalence

The same 2025 work established a much tighter connection between weighted tree edit distance and All-Pairs Shortest Paths.

Weighted TED was shown fine-grained equivalent to APSP in the studied setting.

Combining the reduction with the fastest relevant APSP algorithms gives a weighted TED running time of the form:

n³
/
2^Ω(sqrt(log n))

This is asymptotically faster than:

n³

but it is still:

n^(3-o(1))

rather than:

n^(3-ε)

for a fixed positive constant ε.

Mildly subcubic versus truly subcubic

The distinction mirrors the one seen for string edit distance.

Mild or subpolynomial improvement

n³
/
2^sqrt(log n)

Truly subcubic

n^(3-ε)

for some fixed:

ε > 0

Unweighted TED now has truly subcubic algorithms.

General weighted TED remains tied to the APSP frontier.

Bounded tree edit distance

As with string edit distance, a small distance parameter:

k

can radically change TED complexity.

The bounded problem asks:

TED(T₁,T₂) ≤ k ?

or computes the exact value under the promise:

TED(T₁,T₂) ≤ k

Why bounded TED is harder than bounded string ED

For strings, an alignment with at most:

k

edits remains inside:

O(k)

matrix diagonals.

Trees do not have one global sequence diagonal.

An edit can affect:

  • hierarchical depth;
  • forest boundaries;
  • subtree correspondences;
  • multiple sibling ranges.

Consequently the elegant:

O(n+k²)

string-edit structure does not transfer directly.

Akmal–Jin bounded TED

For unweighted bounded TED, Akmal and Jin developed an:

O(
    n k² log n
)

algorithm.

This makes the algorithm nearly linear in:

n

for constant:

k

but still multiplies the input-size term by a polynomial in the distance parameter.

From nk² to n + poly(k)

A major theoretical objective was to separate:

input-reading work

from:

distance-dependent work

and obtain:

Õ(
    n + poly(k)
)

rather than:

n · poly(k)

Das, Gilbert, Hajiaghayi, Kociumaka, Saha, and Saleh achieved such a result through tree kernelization techniques.

Tree-edit kernelization

The high-level goal is to transform:

T₁,T₂

into much smaller trees:

T₁',T₂'

such that, when the original distance is at most:

k

the relevant edit distance is preserved.

Schematically:

large trees
    │
    ├── identify repeated /
    │   irrelevant structure
    │
    ▼
small kernel
depending mainly on k
    │
    ▼
expensive exact algorithm
only on the kernel

2025 low-distance TED

Kociumaka and Shahali further improved the bounded regime.

Their 2025 algorithm computes bounded tree edit distance in:

O(
    n
    +
    k⁶ log k
)

for both the weighted and unweighted settings covered by their formulation.

The result combines:

  • linear-time preprocessing;
  • kernelization;
  • analysis of periodic tree structures;
  • efficient computation on the resulting kernel.

Why n + k⁶ log k matters

Suppose:

n = 10,000,000

but:

k = 3

Then:

k⁶ log k

is independent of the enormous input size apart from the initial linear scan.

This gives the same conceptual pattern seen throughout parameterized edit-distance theory:

+

pay heavily only
for the small region
where changes occur

Exact TED is not always necessary.

Approximation permits a value:

satisfying, for example:

D
≤

or another specified guarantee.

Boroujeni, Ghodsi, Hajiaghayi, and Seddighin developed a:

Thus the same exact-versus-approximate distinction seen in Approximate Edit Distance Algorithms also appears for structured objects.

Graph edit distance

Tree edit distance still benefits from hierarchical constraints.

Graph edit distance removes most of them.

Let a labeled graph be:

G =
(
    V,
    E,
    μ,
    ν
)

where:

  • V is a vertex set;
  • E is an edge set;
  • μ assigns vertex labels or attributes;
  • ν assigns edge labels or attributes.

Graphs may be:

  • directed or undirected;
  • simple or multi-edge;
  • labeled or unlabeled;
  • attributed;
  • weighted;
  • connected or disconnected.

A GED definition is incomplete unless the graph model and edit operations are stated.

Classical graph edit operations

A common graph edit model contains:

Vertex insertion

add a vertex

Vertex deletion

remove a vertex

Vertex substitution

change vertex label / attributes

Edge insertion

add an edge

Edge deletion

remove an edge

Edge substitution

change edge label / attributes

Each operation has an associated cost.

Why tree structure is the boundary between tractability and combinatorial matching

Trees eliminate cycles.

More importantly, rooted ordered trees provide:

  • unique parent relationships;
  • well-defined subtrees;
  • nested interval structure under traversals;
  • ancestor constraints;
  • sibling order.

These properties make dynamic-programming decomposition possible.

General graphs may contain:

  • cycles;
  • multiple alternative paths;
  • symmetries;
  • dense connectivity;
  • many structurally interchangeable vertices.

The clean nested-subproblem structure disappears.

Tree symmetry can already be dangerous

When sibling order is discarded, even trees develop a large permutation space.

For a node with:

d

children, there may be:

d!

possible child correspondences.

This helps explain why unordered TED jumps from polynomial ordered-tree algorithms to NP-completeness.

Graph symmetry amplifies the same phenomenon

Suppose a graph contains many vertices with identical:

  • labels;
  • degrees;
  • local neighborhoods.

Then enormous numbers of candidate assignments can initially appear equally plausible.

Exact GED algorithms may have difficulty pruning until enough global structure has been exposed.

Labels can dramatically reduce complexity in practice

Consider a graph where every vertex has a unique label:

invoice_482
product_91
...

The correspondence may be almost predetermined.

Compare this with a graph containing 100 vertices all labeled:

Many assignments remain plausible.

Thus practical GED complexity depends strongly on:

+

+

+

+

Summary

Tree and graph edit distance extend the edit-distance principle from linear sequences to structured objects. The extension is conceptually simple—define valid edit operations and minimize their total cost—but computationally profound because the algorithm must determine not only which elements differ but how the structures themselves correspond.

Classical tree edit distance operates on rooted ordered labeled trees and permits node insertion, deletion, and relabeling. Unlike subtree deletion, deleting an internal node normally promotes its children to the deleted node's parent. An equivalent mapping formulation requires matched nodes to preserve one-to-one correspondence, ancestry, and left-to-right order. These structural restrictions are precisely what make dynamic programming possible.

The historical ordered-TED algorithms progressed from Tai's high-degree polynomial dynamic programming to the shape-sensitive Zhang–Shasha algorithm, then through increasingly sophisticated path-decomposition methods to the cubic Demaine–Mozes–Rossman–Weimann framework. RTED and APTED subsequently made decomposition more robust and memory-conscious for practical workloads.

Modern complexity theory has revealed that weighted and unweighted TED behave differently. Fine-grained reductions tie weighted tree edit distance closely to All-Pairs Shortest Paths. The 2025 APSP-equivalence result yields a weighted TED algorithm of roughly n³ / 2^Ω(sqrt(log n)), while continuing to suggest that a fixed-exponent truly subcubic weighted algorithm would require a breakthrough for APSP.

Unweighted tree edit distance has a substantially better frontier. Mao first broke the cubic barrier, and 2025 work reduced rooted ordered unweighted TED to Õ(n^((3+ω)/2)), reported as at most roughly O(n^2.6857) under the corresponding matrix-multiplication bound. This is a genuine polynomial-exponent improvement over the classical cubic regime.

Low-distance trees admit another acceleration. Parameterized algorithms progressed from O(nk² log n) toward n+poly(k) through structural kernelization. The 2025 low-distance algorithm achieves O(n+k⁶ log k) for the covered weighted and unweighted models, demonstrating that extremely large trees can in principle be compared almost linearly when only a small number of edits separates them.

Ordering itself is a source of tractability. Once sibling order is discarded, the correspondence space grows dramatically: unordered labeled tree edit distance is NP-complete even for binary trees over a two-symbol alphabet. This is an important reminder that removing structural constraints may make a matching problem computationally harder rather than easier.

Graph edit distance generalizes the transformation paradigm further. Vertices and edges may be inserted, deleted, or substituted, and the distance is the minimum cost of an edit path leading to a graph isomorphic to the target. Unlike ordered trees, general graphs provide no ancestor hierarchy or global order that cleanly restricts correspondence.

The core difficulty of GED is that vertex matches are not independent. Mapping v₁ to u₁ changes the cost of mapping v₂ to u₂ because the algorithm must verify whether corresponding edges exist and whether their attributes agree. This creates pairwise assignment interactions and connects GED naturally to quadratic assignment, maximum common subgraph, integer programming, and combinatorial search.

Exact GED is NP-hard even for simple uniform-cost settings. Classical A*-based algorithms search partial vertex mappings using admissible lower bounds, while depth-first and branch-and-bound methods reduce memory pressure. Integer-programming formulations provide another exact route. In all cases, effective lower and upper bounds are essential because the raw correspondence space may contain factorially many assignments.

Approximate GED replaces the full global optimization with more manageable problems. Bipartite matching assigns vertices according to local structural costs and can be solved in polynomial time, typically around cubic assignment complexity, but it cannot fully represent pairwise edge consistency. Quadratic-assignment approximations recover more global structure at the price of a harder optimization problem. Learned graph embeddings offer still greater scalability but should not be confused with GED unless a formal relationship has been established.

Tree edit distance and graph edit distance also should not be conflated with one another merely because a tree is a graph. Their primitive operations differ. Classical TED deletion reconnects a deleted node's children to its parent, whereas ordinary graph vertex deletion removes incident edges. Consequently, applying generic GED to graph representations of trees generally produces a different distance from classical TED.

The broader principle is that an edit distance is defined by three components: the representation, the admissible transformations, and the cost model. Changing any one of them changes the mathematical problem. A perfectly computed distance can therefore still be the wrong measure if the representation or edit semantics do not correspond to the application.

For sequences, the natural structural model is linear and Levenshtein distance is often appropriate. For hierarchical data such as XML or syntax trees, tree edit distance retains ancestry and ordering information. For molecules, scene relations, or arbitrary relational objects, graph edit distance may be the appropriate abstraction. As the structural freedom increases from strings to trees to graphs, the computational problem moves from highly constrained dynamic programming toward general combinatorial optimization.
