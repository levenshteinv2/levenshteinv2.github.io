Levenshtein & Edit Distance Glossary: Terms and Definitions

Levenshtein & Edit Distance Glossary

This glossary defines the mathematical, algorithmic, and engineering terminology used in the study of Levenshtein distance, edit distance, approximate string matching, sequence comparison, and related applications. Definitions distinguish concepts that are frequently conflated, including distance versus similarity, code point versus grapheme cluster, edit distance versus sequence alignment, and lexical similarity versus semantic similarity.

Core notation

The following notation appears frequently in edit-distance literature and throughout Levenshtein.net.

Symbol Meaning
Σ An alphabet: the set of symbols from which sequences are constructed.
Σ* The set of all finite strings over alphabet Σ, including the empty string.
x, y Two sequences or strings being compared.
m = |x| Length of the first sequence.
n = |y| Length of the second sequence.
d(x,y) A distance function applied to x and y.
k A maximum permitted edit distance or error threshold.
D[i][j] A dynamic-programming state, commonly representing the optimal edit cost between two prefixes.
w Machine-word size in analyses of bit-parallel algorithms.
q Length of a q-gram.

Glossary index: A · B · C · D · E · F · G · H · I · J · L · M · N · O · P · Q · R · S · T · U · V · W

A

Affine gap penalty

A sequence-alignment cost model in which opening a gap and extending an existing gap have different costs. A common formulation for a gap of length ℓ is:

gap_cost(ℓ)
=
gap_open
+
(ℓ - 1) × gap_extend

This differs fundamentally from ordinary unit-cost Levenshtein distance, where a run of five deletions normally costs exactly five independent edits. Affine gaps are particularly important in biological sequence alignment. See Sequence Alignment and Gap Models.

Alignment

A positional representation showing which elements of two sequences correspond to one another. Matches and substitutions align two symbols; insertions or deletions usually appear as gaps.

source:  c a - t
         | *   |
target:  c u r t

An alignment can encode an edit script, but the two concepts are not identical: an edit script is an ordered transformation, while an alignment is a correspondence representation.

Alphabet

A set of symbols from which strings or sequences are constructed, conventionally denoted Σ. Examples include binary alphabets, ASCII characters, Unicode code points, DNA bases, phonemes, or application-specific tokens.

Alphabet size can affect random-match probabilities, automaton structure, indexing strategies, and algorithm performance.

Approximate edit distance

An approximation to the exact minimum edit distance. Approximation algorithms deliberately trade exactness for lower running time, lower memory use, streaming capability, or improved scalability.

This should not be confused with approximate string matching, where the matching itself allows errors but the distance test may still be exact. See Approximate Edit Distance Algorithms.

Approximate string matching

The problem of locating strings or substrings that match a pattern within a specified error model. Under Levenshtein distance, a common acceptance condition is:

d(pattern, candidate) ≤ k

Unlike pairwise distance computation, approximate matching also involves locating candidates within a text, dictionary, or collection. See Approximate String Matching.

Automaton

A computational model consisting of states and transitions. In approximate matching, an automaton can represent all strings satisfying a distance constraint relative to a pattern.

Automata are useful because search can become state traversal rather than independent pairwise distance computation.

B

Backtrace / backtracking

The process of reconstructing an optimal edit script or alignment from dynamic-programming states. Starting from the final DP cell, the algorithm follows predecessor states whose transition costs reproduce the optimal value.

Multiple predecessors can tie, so backtracking may recover one of several different optimal edit scripts.

Banded dynamic programming

A dynamic-programming optimization that evaluates only states near a relevant diagonal rather than filling the complete matrix.

If two strings must be within a small edit threshold k, many states far from the diagonal cannot participate in an acceptable alignment.

|i - j| ≤ k

is the simplest intuition for the useful region in common thresholded settings.

Bit parallelism

A technique that packs many logical states into the bits of a machine word and updates them simultaneously using bitwise operations.

In string matching, bit parallelism can replace many scalar dynamic-programming updates with operations such as AND, OR, XOR, shifts, and integer arithmetic.

BK-tree

A metric-search tree introduced by Burkhard and Keller for best-match searching. Child edges are labeled by the distance between the child object and its parent.

Triangle inequality allows branches to be pruned during radius queries. BK-trees are particularly natural for discrete integer-valued metrics such as standard Levenshtein distance, although their effectiveness depends strongly on the dataset and distance distribution.

Bounded edit distance

A version of edit-distance computation in which the algorithm only needs to determine whether:

d(x,y) ≤ k

rather than necessarily computing an arbitrarily large exact distance. Knowing the bound can enable pruning, early termination, banded computation, and parameter-sensitive algorithms. See Bounded and Parameterized Edit Distance.

C

Candidate generation

The stage of a search or matching system that identifies a manageable subset of objects for more expensive similarity verification.

query
  ↓
candidate generation
  ↓
small candidate set
  ↓
exact verification

At large scale, candidate generation is often more important than small constant-factor improvements to the final Levenshtein calculation.

Character

An informal and potentially ambiguous term for a textual unit. In software, “character” might mean a byte, code unit, Unicode code point, grapheme cluster, or another representation.

A rigorous edit-distance implementation should state exactly which unit constitutes one edit.

Character Error Rate (CER)

An edit-based evaluation measure commonly used for OCR and text recognition. If S, D, and I denote substitutions, deletions, and insertions relative to a reference of N characters:

CER
=
(S + D + I) / N

The precise definition of “character” must still be specified. See OCR Evaluation and Post-Correction.

Code point

A numbered element of the Unicode code space, conventionally written in forms such as U+0061. One code point is not necessarily one user-perceived character.

Combining marks, emoji sequences, and many writing systems make this distinction essential for Unicode-aware edit distance.

Code unit

A storage unit used by an encoding. UTF-8 uses 8-bit code units, while UTF-16 uses 16-bit code units.

A single Unicode code point can require several code units. Therefore edit distance computed on code units can differ from edit distance computed on code points or grapheme clusters.

Unicode confusable

Characters or sequences that can appear visually similar despite having different Unicode identities. Confusables are relevant to spoofing, domain-name abuse, identifier security, and homoglyph attacks.

Ordinary Levenshtein distance treats them according to symbolic identity, not visual appearance. See Unicode Homoglyph and Confusable Attacks.

Cost function

A function assigning numerical costs to permitted transformations. Standard Levenshtein distance uses:

insert      = 1
delete      = 1
substitute  = 1
match       = 0

Weighted models replace these constants with symbol-dependent or operation-dependent values.

D

Damerau–Levenshtein distance

An edit-distance model that incorporates adjacent transposition in addition to insertion, deletion, and substitution.

hte → the

transpose(h,t) = 1

The unrestricted Damerau–Levenshtein formulation must be distinguished from Optimal String Alignment distance, which imposes additional restrictions. See Damerau–Levenshtein Distance.

Deletion

An edit operation that removes one sequence element.

cart
→
cat

Under standard Levenshtein distance, deletion has cost 1.

Distance

A numerical measure in which larger values generally represent greater difference. A function called a distance in software does not necessarily satisfy the mathematical axioms required of a metric.

Dynamic programming (DP)

An algorithmic technique that solves a problem by combining solutions to overlapping subproblems. Classical edit-distance computation defines states for pairs of prefixes and reuses previously computed optimal values.

D[i][j]
=
minimum edit cost
between prefixes
x[1..i] and y[1..j]

E

Edit distance

A family of sequence distances defined by the minimum cost of a valid sequence of editing operations that transforms one sequence into another.

d(x,y)
=
min cost(edit script x → y)

The term is broader than Levenshtein distance because different edit-distance models can use different operations and cost functions. See Edit Distance.

Edit graph

A graph representation of edit-distance states. A vertex commonly represents a pair of prefix positions (i,j), while edges represent insertion, deletion, match, or substitution transitions.

The edit distance can then be interpreted as the cost of a shortest path from (0,0) to (m,n).

Edit operation

One permitted elementary transformation of a sequence. Standard Levenshtein operations are insertion, deletion, and substitution.

Other models may add transpositions, token edits, block operations, or structured gap operations. See Edit Operations and Edit Scripts.

Edit script

An ordered sequence of edit operations transforming a source sequence into a target sequence.

kitten
→ sitten
→ sittin
→ sitting

An edit script can be valid without being optimal. Edit distance is defined by a minimum-cost valid script.

Embedding

A representation mapping an object into a vector or another mathematical space. Learned string or sequence embeddings can encode information that character-level edit distance does not capture, including potentially semantic or task-specific relationships.

An embedding-based distance is not automatically equivalent to edit distance and need not preserve edit-distance geometry. See Learned Edit Distance and Embeddings.

Entity resolution

The problem of determining which records refer to the same real-world entity despite variation, noise, missing information, or duplicate representations.

Edit distance can be one lexical feature, but small string distance is not proof of entity identity. See Entity Resolution and Record Linkage.

Error threshold

A maximum permitted edit distance, commonly denoted k.

accept candidate
iff
d(query, candidate) ≤ k

Threshold selection influences both computational cost and retrieval quality.

F

Filter

A computational test used to eliminate impossible or unlikely candidates before expensive exact verification.

A lossless filter may produce false positives but must not remove any candidate that actually satisfies the target distance condition.

Fine-grained complexity

A branch of complexity theory concerned not only with whether a problem is polynomial-time solvable but with whether major improvements to known exponents are possible.

For exact edit distance, fine-grained lower-bound research provides conditional evidence against strongly subquadratic algorithms in the fully general setting. See Edit Distance Complexity.

Fuzzy search

A retrieval system designed to return useful results even when the query differs from indexed terms or documents.

Edit distance can provide lexical tolerance, but production fuzzy search may additionally use tokenization, indexes, language models, popularity, field weights, and semantic signals. See Fuzzy Search with Edit Distance.

G

Gap

A position inserted into an alignment to represent the absence of a corresponding sequence element.

A C - G T
A C T G T

A gap may correspond to an insertion or deletion depending on transformation direction.

Grapheme cluster

A sequence of one or more Unicode code points approximating what a user perceives as a single character.

For example, a base letter plus a combining accent can form one grapheme cluster while containing multiple code points. Emoji can contain even more complex sequences.

Grapheme-aware distance is important when an application intends one visual or user-perceived character to count as one edit. See Unicode and Grapheme-Safe Levenshtein.

H

Hamming distance

The number of positions at which two equal-length sequences contain different symbols.

x = 101110
y = 100100

Hamming distance = 2

Hamming distance models substitutions but not insertions or deletions. It is a metric on sequences of a fixed length.

Homoglyph

A character whose visual form resembles another character. The term is often used in security discussions involving visually deceptive identifiers.

Visual resemblance is not encoded by ordinary Levenshtein distance unless the cost model explicitly incorporates it.

I

Identity of indiscernibles

A metric axiom requiring:

d(x,y) = 0
iff
x = y

Aggressive preprocessing or zero-cost transformations can violate this property on the original unnormalized string space.

Indel

A compact term referring to an insertion or deletion. It is widely used in sequence analysis and coding theory when both operations are treated as synchronization-changing errors.

Indexing

Preprocessing a collection into a data structure that reduces the work required at query time.

Approximate-matching indexes can use tries, q-grams, metric structures, automata, partitions, prefix filters, or other representations. See Indexing and Filtering for Edit Distance.

Insertion

An edit operation that adds one sequence element.

cat
→
cart

Standard Levenshtein insertion cost is 1.

J

Jaccard similarity

A set-overlap measure defined by:

J(A,B)
=
|A ∩ B|
/
|A ∪ B|

Strings must first be converted to sets or set-like representations such as token sets or q-gram sets.

Jaccard distance

For sets:

d_J(A,B)
=
1 - J(A,B)

Jaccard distance is a metric on sets, but conversion of strings to sets can discard ordering and multiplicity information.

Jaro similarity

A string-comparison measure developed for record linkage. It considers matching characters within a positional window and disagreements in their relative order.

It is especially associated with short strings and personal-name comparison.

Jaro–Winkler similarity

A modification of Jaro similarity that increases the score when strings share an initial prefix.

The prefix preference is an application-specific modeling decision rather than a universal property of string similarity. See Levenshtein vs Jaro-Winkler and Phonetic Matching.

L

Landau–Vishkin algorithm

A family of algorithms for approximate string matching that exploits a small permitted number of differences rather than evaluating the entire conventional dynamic-programming matrix.

The work of Landau and Vishkin is an important milestone in parameter-sensitive approximate matching. See Landau–Vishkin Algorithm.

Longest Common Subsequence (LCS)

A longest sequence of symbols that appears in both input sequences in the same relative order, without requiring contiguity.

If only unit-cost insertion and deletion are allowed:

d_insdel(x,y)
=
|x| + |y| - 2LCS(x,y)

This formula is not generally equal to ordinary unit-cost Levenshtein distance because Levenshtein substitutions cost 1 rather than a deletion plus insertion cost of 2.

Levenshtein algorithm

A commonly used name for algorithmic methods that compute Levenshtein distance. The phrase should not be interpreted as meaning that only one algorithm exists.

Classical dynamic programming, Wagner–Fischer, Ukkonen-style bounded methods, Myers bit vectors, and other techniques can compute or exploit the same underlying distance under different conditions.

Levenshtein automaton

A finite-state representation that recognizes strings lying within a specified Levenshtein distance of a pattern.

L(P,k)
=
{ S : d(P,S) ≤ k }

Levenshtein automata are useful for dictionary traversal, tries, finite-state lexicons, fuzzy term lookup, and approximate matching. See Levenshtein Automata.

Levenshtein distance

The minimum number of single-element insertions, deletions, and substitutions needed to transform one sequence into another under the standard unit-cost model.

d("kitten","sitting") = 3

Standard Levenshtein distance is a mathematical metric. The canonical entity definition is maintained on the Levenshtein.net homepage.

Lexical similarity

Similarity between observable word or string forms rather than their meanings.

Edit distance is fundamentally lexical or sequence-based: two strings can have small edit distance while expressing unrelated meanings.

M

Match

A correspondence between equal sequence elements. In classical Levenshtein dynamic programming:

match cost = 0

A match is commonly represented during alignment or backtracking even though it is not an edit operation.

Metric

A distance function satisfying four axioms:

  1. non-negativity;
  2. identity of indiscernibles;
  3. symmetry;
  4. triangle inequality.

Standard unit-cost Levenshtein distance satisfies these conditions. See String Metrics.

Metric space

A set of objects together with a metric defining distance between every pair of objects.

Metric-space structure makes mathematically valid pruning possible through triangle inequality and related bounds.

Myers bit-vector algorithm

Gene Myers' bit-parallel algorithm for approximate string matching. It encodes dynamic-programming relationships in machine-word bit vectors so that many pattern positions can be updated simultaneously.

The approach is especially effective when the pattern fits within one or a small number of machine words. See Myers Bit-Vector Algorithm.

N

N-gram

A contiguous sequence of n elements extracted from a larger sequence.

"string"

bigrams:
st
tr
ri
in
ng

In string-search literature, the symbol q is also widely used, giving the synonymous term q-gram.

Non-negativity

A metric property requiring:

d(x,y) ≥ 0

Conventional edit-distance cost systems therefore use nonnegative operation costs.

Normalization of a distance

A transformation intended to make distances more comparable across inputs of different lengths or scales.

A common Levenshtein normalization is:

d_norm(x,y)
=
d(x,y)
/
max(|x|,|y|)

Such post-hoc normalization is convenient but does not automatically preserve the triangle inequality or other metric properties.

Normalized edit distance

A family of edit-distance formulations that account for sequence length or edit-path length. The phrase can refer either to simple normalization of an already computed distance or to algorithms that optimize a normalized cost directly.

These formulations should be distinguished because they can have different mathematical properties.

O

Online approximate matching

Approximate searching performed directly against the text when a query arrives, without relying primarily on a persistent search index built specifically for that query.

This contrasts with indexed matching, where substantial preprocessing is performed in advance.

Optimal alignment

An alignment whose associated operation or scoring cost is optimal under the chosen model.

Multiple different alignments can have exactly the same optimal cost.

Optimal edit script

A valid edit script whose total cost is minimum among all scripts transforming the source into the target.

The numerical edit distance is the cost of such a script, but the script itself may not be unique.

Optimal String Alignment distance (OSA)

A restricted transposition-aware edit distance often confused with unrestricted Damerau–Levenshtein distance.

OSA restricts how substrings may be edited and does not have all the same mathematical properties as unrestricted Damerau–Levenshtein distance. In particular, it should not automatically be treated as a metric.

P

Parameterized edit distance

Study of edit-distance algorithms whose complexity is expressed in terms of a parameter such as the actual distance k, rather than only the full input lengths.

This is particularly valuable when:

k << min(m,n)

See Bounded and Parameterized Edit Distance.

Pattern

The sequence being searched for in a text or collection. In approximate matching, the pattern need not occur exactly; candidates may be accepted within a distance threshold.

Phonetic matching

Matching based primarily on similarity of pronunciation rather than direct character transformation.

Soundex, Metaphone, and related methods illustrate this family. A phonetic comparator can regard lexically distant strings as related if their pronunciations are similar.

Prefix filtering

A candidate-generation strategy that indexes or examines selected prefixes of ordered features and uses overlap constraints to eliminate impossible candidates.

Prefix filtering is common in scalable similarity joins and set/q-gram matching systems.

Q

Q-gram

A contiguous substring of exactly q symbols.

string = "abcd"
q = 2

q-grams:
ab
bc
cd

q-grams support filtering because a small number of edits can affect only a bounded local set of q-grams. They are therefore widely used in scalable edit-distance candidate generation.

Quadratic time

Complexity proportional to the product of the two sequence lengths or, for equal-length strings, approximately the square of length:

O(mn)

or

O(n²)

The classical full dynamic-programming solution for edit distance has this form.

R

Radius query

A search requesting every object lying within distance k of a query:

{ x : d(q,x) ≤ k }

Radius queries differ from nearest-neighbor queries, which seek the closest object or objects regardless of a predetermined radius.

Record linkage

The task of linking records that refer to the same real-world entity across datasets or sources.

String similarity is commonly used for noisy names, addresses, and identifiers, but robust linkage generally requires evidence beyond lexical similarity.

Recurrence

A formula defining a dynamic-programming state in terms of previously solved states.

For standard unit-cost Levenshtein distance:

D[i][j]
=
min(
  D[i-1][j]   + 1,
  D[i][j-1]   + 1,
  D[i-1][j-1] + cost
)

cost =
0 if x[i] = y[j]
1 otherwise

S

Semantic similarity

Similarity of meaning rather than surface form.

car
automobile

can be semantically similar despite substantial edit distance, while:

cat
car

are lexically close but semantically different. See String Similarity vs Semantic Similarity.

Sequence

An ordered collection of elements. Edit-distance algorithms are fundamentally sequence algorithms; characters are only one possible element type.

Words, phonemes, DNA bases, log events, tokens, or other symbols can also form sequences.

Sequence alignment

The problem of arranging two or more sequences to expose corresponding elements according to a scoring model.

Classical edit distance is closely related to alignment, but biological alignment commonly uses richer substitution scores and gap models. See Levenshtein vs Sequence Alignment.

Strong Exponential Time Hypothesis (SETH)

A conjecture in computational complexity used as the basis for conditional lower bounds in fine-grained complexity.

Results by Backurs and Indyk connect a strongly subquadratic general exact edit-distance algorithm with consequences that would contradict SETH. This is a conditional barrier, not an unconditional proof that quadratic time is optimal.

Similarity

A numerical measure usually defined so that larger values represent greater resemblance.

Similarity is not synonymous with distance or metric. A similarity function does not need to satisfy metric axioms.

Similarity threshold

A cutoff applied to a similarity score rather than a distance.

accept
if
similarity(x,y) ≥ t

Its interpretation depends entirely on the similarity function being used.

Space complexity

The amount of memory required by an algorithm as input size grows.

A complete Levenshtein DP matrix uses:

O(mn)

memory, while distance-only computation can normally be reduced to:

O(min(m,n))

String metric

A mathematical metric whose domain consists of strings or string-derived representations. Levenshtein distance and Hamming distance under their proper domains are examples.

Many useful string comparators are not metrics. See String Metrics.

Subsequence

A sequence obtained by deleting zero or more elements while preserving the relative order of the remaining elements.

ACE

is a subsequence of

ABCDEF

A subsequence need not occupy contiguous positions.

Substring

A contiguous segment of a string.

"cde"

is a substring of

"abcdef"

This differs from a subsequence, whose elements need not be adjacent.

Substitution

An edit operation replacing one sequence element with another.

cat
→
cut

Standard Levenshtein substitution cost is 1.

Surrogate pair

A pair of UTF-16 code units consisting of a high surrogate followed by a low surrogate. Together they encode one Unicode code point outside the Basic Multilingual Plane.

high surrogate
+
low surrogate
=
one supplementary Unicode code point

A surrogate pair contains two UTF-16 code units but represents one Unicode code point. A Levenshtein implementation that indexes UTF-16 code units directly can therefore expose one supplementary character as two edit positions. This distinction is part of the runtime string model described in Levenshtein Implementations: Correctness, Memory & Performance and the Unicode comparison model described in Unicode & Grapheme-Safe Levenshtein.

Symmetry

A metric property requiring:

d(x,y) = d(y,x)

Standard Levenshtein distance is symmetric. Directional weighted edit models need not be.

T

Threshold k

Conventional notation for the maximum permitted number or cost of edits in bounded matching:

d(x,y) ≤ k

Small k often enables algorithms substantially different from unrestricted full-distance computation.

Time complexity

The asymptotic amount of computational work required as input size grows.

Classical dynamic programming for two strings of lengths m and n requires:

O(mn)

time. Specialized algorithms can perform better under bounded distance, approximation, bit-parallel hardware, or other assumptions.

Token-level edit distance

Edit distance in which the sequence elements are tokens or words rather than characters.

[the, quick, fox]
→
[the, fox]

can be one token deletion even though several characters disappear.

Translation Edit Rate (TER)

An edit-based machine-translation evaluation measure representing the amount of editing required to transform a system output into a reference translation.

Classical TER formulations include insertions, deletions, substitutions, and shifts, so TER is not simply ordinary character-level Levenshtein distance. See Translation Edit Rate and MT Evaluation.

Transposition

The exchange of the order of symbols, commonly an adjacent pair:

ab
→
ba

Classical Levenshtein distance does not treat transposition as a primitive operation. Damerau-style models do.

Triangle inequality

A metric axiom requiring:

d(x,z)
≤
d(x,y) + d(y,z)

For edit distance, one intuitive proof is that a script from x to y can be concatenated with a script from y to z. The optimal direct transformation cannot cost more than that valid two-stage transformation.

Triangle inequality enables exact metric-space pruning.

Trie

A prefix tree used to store strings by shared prefixes.

Combining a trie or related finite-state dictionary structure with a Levenshtein automaton allows entire groups of dictionary terms to be explored or rejected together.

U

Ukkonen algorithm

A name associated with Esko Ukkonen's distance-sensitive and threshold-aware algorithms for edit distance and approximate string matching.

The central idea is that when the true distance is small, the algorithm should avoid performing work proportional to the entire dynamic-programming matrix. See Ukkonen Algorithm.

Unicode scalar value

A Unicode code point other than a surrogate code point. Unicode scalar values therefore include the ranges U+0000–U+D7FF and U+E000–U+10FFFF, while excluding U+D800–U+DFFF.

The distinction matters in programming-language implementations. For example, a Rust char represents a Unicode scalar value, whereas UTF-16 APIs may expose individual surrogate code units. Iterating over Unicode scalar values avoids treating UTF-8 bytes or UTF-16 surrogate halves as independent characters, but it still does not make extended grapheme clusters into single sequence elements.

For the implementation relationship between scalar values, code units, code points, and grapheme clusters, see Levenshtein Implementations: Correctness, Memory & Performance and Unicode & Grapheme-Safe Levenshtein.

Unicode normalization

Standardized transformation of Unicode text into canonical or compatibility-related forms.

Common forms are:

Form General role
NFC Canonical decomposition followed by canonical composition
NFD Canonical decomposition
NFKC Compatibility decomposition followed by composition
NFKD Compatibility decomposition

Canonically equivalent strings can otherwise receive different code-point-level edit distances. Compatibility normalization is more aggressive and can erase distinctions that an application may need to preserve.

Unicode text segmentation

The process of identifying boundaries between grapheme clusters, words, or sentences in Unicode text.

Grapheme segmentation is especially relevant when an edit operation is intended to correspond to a user-perceived character rather than a code unit or code point.

V

Varshamov–Tenengolts code

A family of codes associated with correction of insertion/deletion-type synchronization errors, especially the classical single-deletion setting.

These codes belong to the coding-theory lineage closely connected to Levenshtein's work on insertion and deletion channels. See Varshamov–Tenengolts and Levenshtein Codes.

Verification

The exact comparison stage applied after candidate generation or filtering.

index/filter
   ↓
candidate
   ↓
exact distance verification
   ↓
accept / reject

In a lossless search architecture, filters reduce work while exact verification preserves correctness.

W

Wagner–Fischer algorithm

The classical dynamic-programming method associated with the string-to-string correction problem.

The algorithm computes a table of optimal prefix-to-prefix transformation costs using insertion, deletion, and symbol-change transitions.

D[i][j]
=
min(
    D[i-1][j]   + delete_cost,
    D[i][j-1]   + insert_cost,
    D[i-1][j-1] + replace_or_match_cost
)

See Wagner–Fischer Algorithm.

Weighted edit distance

An edit-distance model in which operations do not all have identical costs.

cost(substitute e,r) = 0.3
cost(substitute e,q) = 1.2

Weighted costs can model keyboard geometry, OCR confusion probabilities, phonetic similarity, biological substitutions, or other domain knowledge.

Weighted Levenshtein distance

A Levenshtein-style edit model in which insertion, deletion, or substitution costs depend on the operation or symbols involved.

Not every arbitrary weighted model remains a mathematical metric. See Weighted Levenshtein Distance.

Word Error Rate (WER)

A standard edit-based evaluation measure for automatic speech recognition. If:

S = word substitutions
D = word deletions
I = word insertions
N = number of reference words

then:

WER
=
(S + D + I) / N

WER demonstrates that edit-distance concepts apply to arbitrary symbolic sequences, not only character strings. See Word Error Rate and ASR Evaluation.

Concepts that should not be conflated

Concept A Concept B Critical distinction
Edit distance Levenshtein distance Edit distance is a broader family; Levenshtein is one specific operation-and-cost model.
Levenshtein distance Levenshtein algorithm The distance is the mathematical quantity; algorithms are methods for computing or exploiting it.
Distance Metric A function called a distance is not necessarily a mathematical metric.
Distance Similarity Distance generally grows with difference; similarity generally grows with resemblance.
Edit script Edit distance A script is a transformation sequence; the distance is the minimum script cost.
Edit script Alignment A script describes operations; an alignment represents positional correspondence.
Approximate edit distance Approximate string matching The former approximates the numerical distance; the latter searches while allowing differences.
Substring Subsequence A substring is contiguous; a subsequence need not be.
Code unit Code point One Unicode code point can occupy multiple encoding code units.
Code point Unicode scalar value A Unicode scalar value is a Unicode code point excluding the surrogate-code-point range U+D800–U+DFFF.
UTF-16 code unit Surrogate pair A surrogate pair consists of two UTF-16 code units that together represent one supplementary Unicode code point.
Code point Grapheme cluster One user-perceived character may contain several code points.
Levenshtein distance Damerau–Levenshtein distance Classical Levenshtein has no primitive transposition operation.
Damerau–Levenshtein Optimal String Alignment OSA is a restricted model and should not be treated as identical to unrestricted Damerau–Levenshtein distance.
Lexical similarity Semantic similarity Similar spelling does not imply similar meaning.
String similarity Entity identity A similar name is evidence, not proof that two records refer to the same entity.
Candidate generation Verification Generation finds plausible candidates; verification checks the exact condition.

The edit-distance conceptual stack

RAW DATA
   ↓
NORMALIZATION
   ↓
SEGMENTATION
   ↓
SEQUENCE REPRESENTATION
   ↓
ALLOWED EDIT OPERATIONS
   ↓
EDIT COST FUNCTION
   ↓
VALID EDIT SCRIPTS
   ↓
OPTIMAL EDIT SCRIPT
   ↓
EDIT DISTANCE
   ↓
THRESHOLD / SIMILARITY TRANSFORMATION
   ↓
CANDIDATE SEARCH
   ↓
APPLICATION DECISION

This hierarchy is important because changing any earlier layer can change every result below it. A Levenshtein implementation can be algorithmically correct and still be inappropriate if it compares bytes when the application intends grapheme clusters, uses unit costs where errors are strongly asymmetric, or interprets lexical similarity as semantic or entity-level equivalence.
