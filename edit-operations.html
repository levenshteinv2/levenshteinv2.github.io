Edit Operations & Edit Scripts: Insertion, Deletion, Substitution

Edit operations are elementary transformations used to describe how one sequence can be changed into another.

In standard Levenshtein distance, the permitted edit operations are:

  • insertion,
  • deletion,
  • substitution.

An edit script is an ordered sequence of these operations. The minimum cost of any valid script transforming the source sequence into the target sequence defines the Levenshtein distance.

source sequence
      ↓
edit operations
      ↓
target sequence

minimum valid script cost
      =
Levenshtein distance

The operation model becomes meaningful only after the sequence representation has been defined. One edit can act on bytes, Unicode code points, grapheme clusters, words, phonemes, biological symbols, or another application-defined unit.

What Is an Edit Operation?

Let Σ be an alphabet and Σ* the set of finite sequences over that alphabet.

An edit operation makes a local change to a sequence.

Operation Effect Example Standard Cost
Insertion Add one sequence element ct → cat 1
Deletion Remove one sequence element cart → cat 1
Substitution Replace one sequence element cat → cut 1

A match is often represented in an alignment, but it is not normally counted as an edit because it does not change the sequence.

match(a,a)       cost = 0
insert(a)        cost = 1
delete(a)        cost = 1
substitute(a,b)  cost = 1

Insertion

An insertion adds one sequence element.

ct
↓ insert a
cat

At the chosen representation level, insertion increases sequence length by one.

If the sequence elements are words rather than characters:

[the, cat]
↓ insert "black"
[the, black, cat]

the same abstract operation applies to a different kind of sequence.

Deletion

A deletion removes one sequence element.

cart
↓ delete r
cat

Deletion decreases sequence length by one element at the selected representation layer.

Substitution

A substitution replaces one sequence element with another.

cat
↓ substitute a → u
cut

A substitution preserves sequence length.

Under standard unit-cost Levenshtein distance:

substitution cost = 1

but generalized edit-distance models can assign another cost.

Transformation Direction Matters

Edit operations are interpreted relative to a transformation direction:

source → target

Consider:

cat → cart

From source to target, the change is an insertion of r.

Reversing the direction:

cart → cat

changes the corresponding operation to deletion.

Forward Operation Reverse Operation
Insert a Delete a
Delete a Insert a
Substitute a → b Substitute b → a

With symmetric unit costs, reversing an optimal script produces a reverse transformation with the same total cost. This contributes to the symmetry of standard Levenshtein distance.

What Is an Edit Script?

An edit script is an ordered sequence of permitted edit operations that transforms the source into the target.

S = (o1, o2, ..., ok)

Applying those operations sequentially gives:

x
↓ o1
x1
↓ o2
x2
...
↓ ok
y

A script is valid only if applying all of its operations produces the exact target sequence.

Example: Kitten to Sitting

kitten
↓ substitute k → s
sitten
↓ substitute e → i
sittin
↓ insert g
sitting

This script contains two substitutions and one insertion.

total cost
=
1 + 1 + 1
=
3

Under standard unit-cost Levenshtein distance:

ED("kitten", "sitting") = 3

Edit Script Cost

Let c(o) denote the cost of operation o.

The cost of an edit script S is:

C(S)
=
Σ c(oi)

Standard Levenshtein distance uses:

c(insert)     = 1
c(delete)     = 1
c(substitute) = 1

The distance is the minimum script cost:

d(x,y)
=
min C(S)

over every valid script S
such that

S(x) = y

Therefore:

edit distance
≠
cost of any valid edit script

edit distance
=
cost of a minimum-cost valid edit script

A Valid Script Is Not Necessarily Optimal

Consider:

cat → cut

One valid script is:

cat
↓ delete a
ct
↓ insert u
cut

Its total cost is two.

A cheaper script is:

cat
↓ substitute a → u
cut

whose cost is one.

Both scripts are valid. Only the second is optimal under the standard unit-cost model.

Substitution Versus Delete Plus Insert

A substitution can always be represented as a deletion followed by an insertion.

uav
↓ delete a
uv
↓ insert b
ubv

Under the standard cost model:

substitution
=
1

deletion + insertion
=
2

so direct substitution is cheaper.

In a weighted model, if:

c_substitute(a,b)
≥
c_delete(a) + c_insert(b)

then using substitution provides no cost advantage over deleting a and inserting b.

See Weighted Levenshtein Distance .

Edit Scripts and Alignments

An edit script can also be represented as an alignment.

source:  c a t
         | * |
target:  c u t

Here:

| = match
* = substitution

An insertion can be shown as a gap in the source:

source:  c - t
target:  c a t

A deletion can be shown as a gap in the target:

source:  c a t
target:  c - t
Alignment Column Interpretation
a / a Match
a / b Substitution
- / b Insertion
a / - Deletion

Edit Operations in Dynamic Programming

The Wagner–Fischer Algorithm computes the minimum cost of transforming prefixes of one sequence into prefixes of another.

Define:

D[i][j]

as the minimum cost required to transform the first i source elements into the first j target elements.

Under standard unit costs:

D[i][j] =
min(
    D[i-1][j]   + 1,
    D[i][j-1]   + 1,
    D[i-1][j-1] + cost
)

cost =
    0 if source[i-1] == target[j-1]
    1 otherwise
Transition Meaning
D[i-1][j] → D[i][j] Deletion
D[i][j-1] → D[i][j] Insertion
D[i-1][j-1] → D[i][j] with unequal elements Substitution
D[i-1][j-1] → D[i][j] with equal elements Match

The visual direction of a matrix transition depends on which sequence is placed on each axis. The semantic operation should therefore be determined from the prefix-state definition rather than memorized from a particular diagram orientation.

An Edit Script Is a Path Through Prefix States

A complete edit script corresponds to a path from:

(0,0)

to:

(m,n)

in the dynamic-programming state space.

Operation Source Elements Consumed Target Elements Consumed
Deletion 1 0
Insertion 0 1
Substitution 1 1
Match 1 1

Recovering an Edit Script

Once a complete dynamic-programming matrix has been computed, an optimal edit script can be recovered by backtracking from the final state.

i = length(source)
j = length(target)

operations = []

while i > 0 or j > 0:

    if source and target elements match
       and diagonal predecessor is optimal:

        operations.append(MATCH)
        i -= 1
        j -= 1

    else if substitution predecessor is optimal:

        operations.append(SUBSTITUTE)
        i -= 1
        j -= 1

    else if deletion predecessor is optimal:

        operations.append(DELETE)
        i -= 1

    else:

        operations.append(INSERT)
        j -= 1

reverse(operations)

The script is reversed at the end because backtracking proceeds from target state toward the source state.

The Optimal Edit Script May Not Be Unique

The minimum numerical distance does not necessarily determine one unique script.

Several predecessor states can satisfy:

D[i][j]
=
D[predecessor]
+
operation cost

with the same minimum total value.

Therefore:

unique distance
≠
necessarily unique optimal alignment

This matters when software reports individual substitutions, deletions, or insertions rather than only the final distance.

Tie-Breaking Changes the Reported Script

When several optimal predecessors exist, an implementation can use a stable preference such as:

match
→ substitution
→ deletion
→ insertion

to produce deterministic output.

This does not make the mathematical optimum unique. It simply selects one representative optimal path.

A system reporting edit statistics should document its cost model, alignment rules, and tie-breaking policy.

Edit Coordinates Must Be Defined

Insertions and deletions shift later positions.

abcdef
↓ delete b
acdef

A later operation described as occurring at “position 4” can refer to:

  • the original source coordinates,
  • the current intermediate sequence,
  • the final target coordinates,
  • alignment coordinates.

APIs exposing edit scripts should define their coordinate system explicitly.

Weighted Edit Operations

Standard Levenshtein distance assigns unit costs, but application-specific models can define:

c_insert(a)

c_delete(a)

c_substitute(a,b)

For example, an OCR model could assign a lower substitution cost to character pairs that the recognizer frequently confuses.

Operation Illustrative Cost Possible Interpretation
substitute(m,n) 0.4 Frequent recognition confusion
substitute(q,z) 1.5 Less plausible confusion
delete(space) 0.3 Frequent segmentation error
insert(character) 1.0 Default insertion

The resulting algorithm minimizes total edit cost rather than simply counting operations.

Asymmetric Costs

Edit costs can be directional:

c_substitute(a,b) = 0.4

c_substitute(b,a) = 0.8

Such models can be useful when one sequence represents the output of an error-generating process relative to another.

But directional costs can produce:

d(x,y)
≠
d(y,x)

so the resulting function is no longer the ordinary symmetric Levenshtein metric.

Zero-Cost Transformations and Preprocessing

Some applications deliberately treat selected differences as irrelevant.

One approach is to assign zero cost to a particular operation.

Another is to transform the text before computing edit distance:

raw text
↓
transformation T
↓
sequence representation
↓
edit distance

If:

x ≠ y

but

T(x) = T(y)

then:

ED(T(x), T(y)) = 0

This does not establish equality of the original strings. It establishes equality in the transformed comparison space.

See Text Normalization and Transliteration .

Transposition Is Not a Classical Levenshtein Operation

Consider:

hte
the

Two adjacent symbols have exchanged positions.

Classical Levenshtein distance contains only:

insertion
deletion
substitution

so an adjacent transposition is not one primitive Levenshtein edit.

Models that explicitly include transposition produce a different edit-distance model.

See Damerau-Levenshtein Distance .

The Operation Set Defines the Distance Model

Allowed Operations Resulting Model
Substitution only Related to Hamming distance on equal-length sequences
Insertion + deletion Insert-delete distance related to longest common subsequence
Insertion + deletion + substitution Standard Levenshtein distance
Add adjacent transposition Damerau-style edit distance
Symbol-dependent costs Weighted edit distance
Gap-open + gap-extension costs Sequence-alignment models

The phrase edit distance is therefore incomplete unless the sequence representation, operation set, and cost model are known.

Insertion-Deletion Distance and Longest Common Subsequence

When substitution is not available as a primitive operation, transformation can be performed using deletions and insertions.

If L is a longest common subsequence of x and y, then under unit insertion and deletion costs:

d_insdel(x,y)
=
|x| + |y| - 2|L|

Symbols belonging to the common subsequence can remain unchanged. Other source elements are deleted, while missing target elements are inserted.

What Exactly Is One Edit Unit?

In software, the word character is often ambiguous.

One edit can act on:

  • bytes,
  • encoding code units,
  • Unicode code points,
  • extended grapheme clusters,
  • words or tokens,
  • phonemes,
  • DNA bases,
  • other application-defined sequence elements.
delete one byte
≠
delete one code point
≠
delete one grapheme cluster
≠
delete one word

The abstract edit operation is the same, but its application meaning changes with the underlying sequence representation.

Unicode Changes the Meaning of an Edit

Consider the visible character:

é

Unicode can represent it as:

U+00E9

or using a decomposed sequence:

U+0065
+
U+0301

A code-point-level edit model sees different sequence lengths in these two representations.

Likewise, one user-perceived emoji or decorated text unit can contain multiple Unicode code points.

Therefore:

Unicode code point
≠
necessarily one user-perceived character

See Unicode & Grapheme-Safe Levenshtein .

Normalization Can Change the Edit Script

Canonically equivalent Unicode text can produce different edit operations when compared before normalization.

raw representation A
vs
raw representation B
↓
edit script 1

After canonical normalization:

NFC(A)
vs
NFC(B)
↓
edit script 2

the two strings can become identical or require fewer operations.

Therefore the edit script depends on the representation and transformation policy used before comparison.

Unicode Text Transformations and Edit Operations

A Unicode transformation can intentionally produce a new valid sequence.

source Unicode text
↓
transformation T
↓
target Unicode text

Edit distance can then describe the minimum sequence changes connecting the source representation and the result.

source
↓
insert / delete / substitute
↓
result

The transformation and edit distance are separate operations:

transformation
=
produces the target representation

edit distance
=
measures a minimum relationship
between defined sequences

This distinction applies to normalization, transliteration, case transformations, and other Unicode mappings.

Continue with Unicode Text Transformations .

Character-Level Versus Token-Level Edits

Consider:

the black cat
the cat

At word level:

delete("black")

is one edit.

At character level, multiple characters and spacing must be removed.

Sequence Unit Meaning of One Deletion
Code point Remove one Unicode code point
Grapheme cluster Remove one user-perceived text unit
Word Remove one token
Phoneme Remove one phonetic unit
DNA base Remove one nucleotide symbol

Edit Operations in Word Error Rate

Automatic speech-recognition evaluation commonly applies insertion, deletion, and substitution to word sequences.

S = substitutions
D = deletions
I = insertions
N = reference words

WER =
(S + D + I)
/
N

The edit operations resemble Levenshtein distance, but the sequence elements are words rather than characters and the final error statistic includes a task-specific normalization.

See Word Error Rate and ASR Evaluation .

Edit Operations in OCR Evaluation

OCR systems can be evaluated through character-level or word-level insertions, deletions, and substitutions.

Separating error types can reveal behavior hidden by a single aggregate edit distance.

System Insertions Deletions Substitutions
System A 10 8 82
System B 40 40 20

Two systems can therefore have the same total number of edit errors while producing very different error profiles.

See OCR Evaluation and Post-Correction .

Edit Operations in Biological Sequence Alignment

Biological sequence analysis also uses insertion, deletion, and substitution concepts, but many alignment models use richer scoring systems.

A gap of length five can be modeled as:

one gap opening
+
four gap extensions

rather than five independent unit-cost deletions.

gap_cost(k)
=
gap_open
+
(k - 1) × gap_extend

This is a different model from standard Levenshtein distance.

See Sequence Alignment and Gap Models .

Edit Scripts as Explanations

A scalar distance answers:

How much minimum editing separates the two sequences?

An edit script additionally answers:

Which permitted operations form one minimum-cost explanation of the difference?

This makes edit scripts useful for:

  • error analysis,
  • visual diff interfaces,
  • correction systems,
  • sequence alignment,
  • OCR analysis,
  • ASR diagnostics,
  • debugging.

An Optimal Edit Script Is Not a Causal History

Suppose an optimal script contains:

substitute a → e

This does not prove that a real-world process literally replaced an a with an e.

It means only that substitution belongs to one minimum-cost mathematical transformation under the selected sequence representation and cost model.

optimal edit script
≠
proven causal history

The actual difference may have originated from typing behavior, OCR, speech recognition, data conversion, text normalization, or another process.

The Conceptual Hierarchy

source data
      ↓
optional transformation
      ↓
sequence representation
      ↓
allowed edit operations
      ↓
operation costs
      ↓
valid edit scripts
      ↓
minimum-cost script
      ↓
edit distance

Changing the transformation, sequence representation, permitted operations, or operation costs can change both the edit script and the final distance.

Key Distinctions

Concept Meaning
Edit operation One permitted sequence transformation step
Match Zero-cost correspondence between equal sequence elements
Edit script Ordered operations transforming source into target
Valid script Any permitted script that reaches the target
Optimal script A valid script with minimum total cost
Edit distance Cost of an optimal script
Alignment A positional representation of matches and edits
Transformation A separate function that produces a new representation

Summary

Insertion, deletion, and substitution are the elementary operations underlying standard Levenshtein distance.

An edit script combines these operations into a complete transformation from source to target, while Levenshtein distance is defined by the cost of a minimum-cost valid script.

A minimum distance does not necessarily imply a unique alignment or edit script. Tie-breaking, coordinate systems, and representation choices matter whenever individual operations are interpreted.

Weighted costs, transpositions, gap models, and other extensions create different edit-distance models.

Unicode adds another essential requirement: one edit must be defined relative to a sequence representation. Bytes, code units, Unicode code points, grapheme clusters, and words are different edit units.

Define the representation, define the permitted operations, define their costs, then interpret the edit script.
