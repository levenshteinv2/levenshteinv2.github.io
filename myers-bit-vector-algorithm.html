Myers Bit-Vector Algorithm

The Myers bit-vector algorithm is a word-parallel method for computing and exploiting unit-cost edit distance. Introduced by Gene Myers in 1999, it transforms the classical dynamic-programming matrix into compact bit-vector state so that many edit-distance cells can be advanced simultaneously using a small sequence of Boolean, shift, addition, and arithmetic operations. When the pattern fits inside a machine word, an entire dynamic-programming column can effectively be updated with a constant number of machine-word operations for each scanned text symbol.

The algorithm is closely connected to Levenshtein distance, but an important historical distinction must be preserved: Myers' original 1999 formulation addresses approximate substring matching under unit-cost insertion, deletion, and substitution. The same bit-vector machinery can be adapted to global pairwise edit distance and has subsequently become a major building block in high-performance sequence-alignment and string-matching software.

The problem solved in Myers' original paper

Let:

P = p₁p₂...pₘ
T = t₁t₂...tₙ

where P is a pattern of length m and T is a text of length n.

Given an error threshold k, the classical approximate string-matching problem is to report every text position j for which some suffix ending at j is within edit distance k of the pattern:

min over g of d(
    P,
    T[g..j]
)
≤
k

Here d is unit-cost Levenshtein distance:

insertion     cost 1
deletion      cost 1
substitution  cost 1
match         cost 0

This is a search problem rather than merely a pairwise-distance problem. The algorithm scans the text from left to right and maintains enough information to know the best edit distance of the pattern against a suffix ending at every text position.

The classical dynamic-programming formulation

Define:

C[i][j]

as the minimum edit distance between pattern prefix:

P[1..i]

and a suffix of:

T[1..j]

ending at position j.

The recurrence is the familiar Levenshtein recurrence:

C[i][j]
=
min(
    C[i-1][j-1]
        + mismatch(pᵢ,tⱼ),

    C[i-1][j]
        + 1,

    C[i][j-1]
        + 1
)

mismatch(a,b) =
    0 if a = b
    1 otherwise

For approximate substring matching, the top boundary is:

C[0][j] = 0
for every j

rather than:

C[0][j] = j

as in ordinary global pairwise edit distance.

This boundary condition means arbitrary text before the beginning of a candidate occurrence is free.

The output condition is:

C[m][j] ≤ k

so the bottom cell of each text column tells whether an approximate occurrence ends at position j.

The bottleneck in ordinary dynamic programming

The standard algorithm evaluates approximately:

m × n

cells.

Thus:

Time:
O(mn)

and a conventional column-by-column implementation requires:

O(m)

working memory if only the current and preceding columns are retained.

Myers' key contribution is not simply to compress the integers stored in one column. The deeper insight is that the differences between neighboring dynamic-programming values are highly constrained and can therefore be encoded compactly and updated in parallel.

The fundamental delta property

For the unit-cost Levenshtein recurrence, differences between adjacent DP cells are always one of:

-1
0
+1

Define the vertical difference:

Dv[i,j]
=
C[i,j] - C[i-1,j]

and the horizontal difference:

Dh[i,j]
=
C[i,j] - C[i,j-1]

Then:

Dv[i,j] ∈ {-1,0,+1}

Dh[i,j] ∈ {-1,0,+1}

for every interior matrix position.

This property is extraordinarily important. A conventional DP column stores full integer values:

0
1
2
2
3
4
...

but Myers instead represents the changes between adjacent values:

+1
+1
 0
+1
+1
...

Each vertical difference requires only three logical states.

The relocatable dynamic-programming matrix

Because the top boundary in the original substring-matching formulation satisfies:

C[0][j] = 0

the complete set of values in column j can be reconstructed from its vertical differences:

C[1,j]
=
C[0,j] + Dv[1,j]

C[2,j]
=
C[1,j] + Dv[2,j]

...

C[m,j]
=
C[0,j]
+
sum from i=1 to m of Dv[i,j]

Therefore the vector:

Dv_j =
(
Dv[1,j],
Dv[2,j],
...
Dv[m,j]
)

contains enough information to represent the column relative to its known top value.

Myers calls this a relocatable representation of the dynamic-programming matrix: absolute values are replaced by local differences.

Encoding a complete column with two bit vectors

Because every vertical difference is only:

-1, 0, or +1

two bit vectors are sufficient.

Define:

Pv[i] = 1
iff
Dv[i] = +1

Mv[i] = 1
iff
Dv[i] = -1

When:

Pv[i] = 0
and
Mv[i] = 0

the vertical difference is zero.

The pair:

(Pv, Mv)

therefore represents the complete vertical delta state of one dynamic-programming column.

Pv bit Mv bit Vertical difference
1 0 +1
0 0 0
0 1 -1
1 1 Not a valid state

Why the machine word matters

Let:

w = number of bits in one machine word

For a common machine:

w = 32
or
w = 64

If:

m ≤ w

then every pattern position fits into one bit of a single machine word.

Instead of performing scalar work separately for:

pattern position 1
pattern position 2
pattern position 3
...
pattern position m

the CPU can manipulate all those logical positions simultaneously.

64 pattern positions
        ↓
one 64-bit word
        ↓
a small sequence of machine operations

This is bit parallelism.

The pattern-equality masks

Every DP cell needs to know whether:

pᵢ = tⱼ

If these comparisons were performed individually for every i, Myers would lose the benefit of word-level parallelism.

Instead, the pattern is preprocessed.

For every symbol c, create a bit mask:

Peq[c]

such that bit i is set exactly when pattern position i contains c:

Peq[c][i] = 1
iff
pᵢ = c

Example

Let:

P = "banana"

using the least significant bit for pattern position 1.

Then conceptually:

positions:
6 5 4 3 2 1

pattern:
a n a n a b

The equality mask for a contains ones at positions 2, 4, and 6:

Peq['a'] = 101010

For n:

Peq['n'] = 010100

and for b:

Peq['b'] = 000001

When text symbol tⱼ arrives, the complete pattern-equality vector is obtained with one lookup:

Eq = Peq[tⱼ]

No loop over the pattern is required.

Initialization

Before scanning any text symbol, the pattern is being compared against the empty text suffix.

Its distance is:

Score = m

because all m pattern symbols would have to be deleted.

The initial vertical deltas are all:

+1

because:

C[i,0] = i

so:

Pv = 111...111
Mv = 000...000
Score = m

For a pattern occupying exactly m bits:

MASK = (1 << m) - 1

Pv = MASK
Mv = 0

Why Myers keeps a separate Score

The bit vectors encode differences, not the absolute bottom DP value.

The search nevertheless needs:

C[m,j]

after every text character.

Let:

Score_j = C[m,j]

Then:

Score_j
=
Score_(j-1)
+
Dh[m,j]

Since:

Dh[m,j] ∈ {-1,0,+1}

the score changes by at most one after scanning each text symbol.

Myers therefore maintains:

Pv
Mv
Score

rather than reconstructing the complete column and summing its vertical differences every time.

Horizontal delta vectors

During one scanning step, Myers also constructs bit-vector encodings of horizontal differences:

Ph[i] = 1
iff
Dh[i,j] = +1

Mh[i] = 1
iff
Dh[i,j] = -1

Again:

Ph[i] = 0
and
Mh[i] = 0

means:

Dh[i,j] = 0

The calculation of a new column proceeds conceptually in two stages:

previous vertical deltas
        ↓
new horizontal deltas
        ↓
new vertical deltas

The local DP-cell relationship

Each DP cell can be regarded as receiving:

  • one vertical delta from its left edge;
  • one horizontal delta from its upper edge;
  • one equality bit describing whether the pattern and text symbols match.

and producing:

  • one horizontal delta along its lower edge;
  • one vertical delta along its right edge.

The scalar recurrence has therefore been transformed into a local finite-state relationship among:

-1
0
+1
match / mismatch

Myers then derives Boolean formulas that apply this relationship to every row of a word simultaneously.

The Xv intermediate vector

One of the intermediate logical masks is:

Xv = Eq | Mv

Conceptually, Xv summarizes information required to determine the next vertical differences from the horizontal input state.

It combines:

symbol equality
+
negative vertical deltas

into one bit vector.

The difficult part: Xh

The horizontal counterpart is more subtle because a dependency appears to propagate along the pattern dimension.

Myers derives:

Xh =
(
    (
        (Eq & Pv)
        + Pv
    )
    ^ Pv
)
| Eq

or in conventional programming notation:

Xh = (((Eq & Pv) + Pv) ^ Pv) | Eq

This expression is the conceptual heart of the algorithm.

Why integer addition appears inside a string algorithm

The dynamic-programming dependency appears to require propagation through runs of pattern positions.

Myers observes that ordinary binary addition already contains a hardware mechanism capable of propagating information through runs of bits:

carry propagation

Suppose an equality bit begins inside a run of set Pv bits.

The expression:

(Eq & Pv) + Pv

causes binary carries to propagate across that run.

The subsequent XOR:

^ Pv

reveals which positions were affected by the carry propagation.

Finally:

| Eq

restores equality positions that need to remain explicitly represented.

The algorithm therefore turns a sequential-looking dynamic-programming dependency into a machine-word addition whose carry hardware performs the propagation in parallel.

A key interpretation of the carry trick

The expression:

(((Eq & Pv) + Pv) ^ Pv) | Eq

is not an arbitrary bit hack.

It is a compact implementation of a precise logical statement:

A position belongs to Xh when an equality condition can propagate to that position through an appropriate uninterrupted run of positive vertical-delta states.

The integer adder is being used as a parallel prefix-propagation mechanism.

Computing Ph and Mh

Once Xh is available, the horizontal delta masks are:

Ph =
Mv
|
~(Xh | Pv)

Mh =
Pv & Xh

where:

Ph = horizontal +1 states
Mh = horizontal -1 states

Any position present in neither mask has horizontal delta zero.

Updating the bottom score

The highest pattern bit corresponds to row:

m

Define:

LAST =
1 << (m - 1)

If:

Ph & LAST != 0

then:

Dh[m,j] = +1

so:

Score += 1

If:

Mh & LAST != 0

then:

Dh[m,j] = -1

so:

Score -= 1

Otherwise the bottom-row horizontal delta is zero and the score does not change.

Shifting the horizontal state

The horizontal deltas produced at row i become inputs to the vertical update for row i+1.

They must therefore be shifted by one bit:

Ph <<= 1
Mh <<= 1

For Myers' original approximate substring-matching boundary:

C[0,j] = 0

the horizontal difference in the top row is:

Dh[0,j] = 0

so a zero is shifted into the first position.

This boundary detail is important because the corresponding global pairwise-distance adaptation uses a different incoming top-row delta.

Computing the next vertical state

After shifting the horizontal vectors:

Pv =
Mh
|
~(Xv | Ph)

Mv =
Ph & Xv

The resulting:

(Pv, Mv)

is the relocatable vertical-delta representation of the newly scanned text column.

The complete one-word update

For the original approximate-search boundary and:

m ≤ w

one scanning step is conceptually:

Eq = Peq[text[j]]

Xv = Eq | Mv

Xh =
    (((Eq & Pv) + Pv) ^ Pv)
    | Eq

Ph =
    Mv | ~(Xh | Pv)

Mh =
    Pv & Xh

if Ph & LAST:
    Score += 1
else if Mh & LAST:
    Score -= 1

Ph <<= 1
Mh <<= 1

Pv =
    Mh | ~(Xv | Ph)

Mv =
    Ph & Xv

if Score <= k:
    report match ending at j

The remarkable feature is that there is no loop over the m pattern positions inside this scanning step.

A safer finite-width version

In mathematical pseudocode, bitwise NOT implicitly affects an unbounded number of bits. Real machine words are finite.

For clarity, an implementation can explicitly mask all states to the m active bits:

MASK =
(1 << m) - 1

Pv = MASK
Mv = 0
Score = m

for symbol in text:

    Eq =
        Peq.get(symbol, 0)
        & MASK

    Xv =
        (Eq | Mv)
        & MASK

    Xh =
        (
            (((Eq & Pv) + Pv) ^ Pv)
            | Eq
        )
        & MASK

    Ph =
        (
            Mv
            | ~(Xh | Pv)
        )
        & MASK

    Mh =
        (Pv & Xh)
        & MASK

    if (Ph & LAST) != 0:
        Score += 1
    else if (Mh & LAST) != 0:
        Score -= 1

    Ph =
        (Ph << 1)
        & MASK

    Mh =
        (Mh << 1)
        & MASK

    Pv =
        (
            Mh
            | ~(Xv | Ph)
        )
        & MASK

    Mv =
        (Ph & Xv)
        & MASK

Explicit masking is particularly valuable in languages whose integers have arbitrary precision, because:

~x

does not naturally behave like a fixed-width machine-word complement.

A small worked scanning example

Let:

P = "abc"

so:

m = 3

and:

MASK = 111₂

The precomputed equality masks are:

Peq['a'] = 001
Peq['b'] = 010
Peq['c'] = 100

Initialization:

Pv    = 111
Mv    = 000
Score = 3

Now scan text character:

'a'

Then:

Eq = 001

and:

Xv
=
Eq | Mv
=
001

Next:

Xh
=
(((001 & 111) + 111) ^ 111)
| 001

Within the active three-bit state, the result is:

Xh = 111

Therefore:

Ph = 000
Mh = 111

The highest pattern bit is set in Mh, so:

Score:
3 → 2

which is correct:

d(
    "abc",
    "a"
)
=
2

for the best suffix ending at that text position.

A complete score trace

For:

P = "abc"

T = "zaxcabc"

the original substring-search state produces the following bottom scores:

Text prefix processed Current symbol Score Interpretation
z z 3 No useful pattern agreement yet
za a 2 abc → a requires two deletions
zax x 2 Best suffix remains two edits away
zaxc c 1 abc → axc is one substitution
zaxca a 2 No distance-1 suffix ends here
zaxcab b 1 Suffix ab requires one deletion
zaxcabc c 0 Exact suffix abc

If:

k = 1

the algorithm reports positions whose scores are:

1
or
0

as approximate occurrence endpoints.

Why Score is not a global prefix distance in the original algorithm

The boundary:

C[0,j] = 0

means the algorithm can begin matching the pattern at any text position without paying for preceding text.

Therefore after scanning:

"zabc"

the original search formulation reports:

Score = 0

because the suffix:

"abc"

is an exact match.

But the global Levenshtein distance:

d("abc","zabc")

is:

1

because the leading z must be inserted.

This is one of the most important distinctions when implementing Myers' algorithm.

Original Myers search versus global Levenshtein distance

Property Original Myers search Global pairwise distance
Question Does a suffix ending here match the pattern approximately? What is the distance between two complete sequences?
Top DP boundary C[0,j] = 0 C[0,j] = j
Leading target text Free Penalized
Top horizontal delta 0 +1
Primary original use Approximate text matching Pairwise edit distance

The global pairwise adaptation

For global Levenshtein distance, the top row is:

C[0,j] = j

so:

Dh[0,j] = +1

rather than zero.

In a common one-word adaptation, this boundary is introduced when shifting Ph:

Ph =
((Ph << 1) | 1)
& MASK

Mh =
(Mh << 1)
& MASK

The inserted low bit represents the +1 horizontal delta at the top boundary.

Reference global-distance pseudocode

function myers_global(pattern, target):

    m = length(pattern)

    if m == 0:
        return length(target)

    require m <= word_size

    MASK =
        (1 << m) - 1

    LAST =
        1 << (m - 1)

    Peq = build_equality_masks(pattern)

    Pv = MASK
    Mv = 0
    Score = m

    for c in target:

        Eq =
            Peq.get(c, 0)
            & MASK

        Xv =
            (Eq | Mv)
            & MASK

        Xh =
            (
                (((Eq & Pv) + Pv) ^ Pv)
                | Eq
            )
            & MASK

        Ph =
            (
                Mv
                | ~(Xh | Pv)
            )
            & MASK

        Mh =
            (Pv & Xh)
            & MASK

        if (Ph & LAST) != 0:
            Score += 1

        else if (Mh & LAST) != 0:
            Score -= 1

        Ph =
            ((Ph << 1) | 1)
            & MASK

        Mh =
            (Mh << 1)
            & MASK

        Pv =
            (
                Mh
                | ~(Xv | Ph)
            )
            & MASK

        Mv =
            (Ph & Xv)
            & MASK

    return Score

This version returns the ordinary unit-cost Levenshtein distance between the complete pattern and target, provided the bit-width and boundary assumptions are implemented correctly.

Why confusing the two boundaries causes subtle bugs

Consider:

pattern = "abc"
target  = "zabc"

Expected results are:

approximate substring search:
0

global pairwise distance:
1

If an implementation uses the original Myers top boundary while claiming to compute global distance, it can silently undercount leading target characters.

Conversely, a global initialization used in approximate substring search can incorrectly penalize text preceding the occurrence.

Complexity when the pattern fits in one word

Assume:

m ≤ w

and that Boolean word operations, shifts, and integer addition take constant time.

Then the algorithm performs only a constant number of word operations for each scanned text symbol.

The scan is therefore:

O(n)

after preprocessing the pattern-equality masks.

Myers' original analysis notes that the basic scanning loop can be expressed using only a small fixed number of bit operations per text symbol.

This is why the method can be dramatically faster than scalar:

O(mn)

dynamic programming when m is at most the machine-word width.

The more general complexity

When:

m > w

the pattern state must span:

b =
ceil(m / w)

machine words.

Updating an m-bit logical vector then requires:

O(ceil(m/w))

word operations.

The basic algorithm therefore has a scanning complexity of:

O(
    n · ceil(m/w)
)

often written asymptotically as:

O(nm/w)

under the word-RAM model.

This corresponds to a factor of approximately:

w

fewer logical DP-state updates than scalar dynamic programming.

Bit parallelism does not magically remove all dependence on m

The statement:

Myers runs in O(n)

is only appropriate when the pattern fits into a constant number of machine words.

For unrestricted pattern length:

m >> w

the algorithm must process multiple words per text character.

A more accurate general description is:

O(
    n · ceil(m/w)
)

for the basic multiword representation.

Why w is not just a theoretical symbol

On a 64-bit machine:

w = 64

A pattern of:

m = 32

fits easily in one word.

A pattern of:

m = 64

still fits in one word.

A pattern of:

m = 65

requires at least two words.

Thus one extra pattern symbol can cross a block boundary and materially change implementation structure.

Multiword blocks

For long patterns, divide the pattern into blocks of at most w positions:

pattern

┌─────────┬─────────┬─────────┐
│ block 0 │ block 1 │ block 2 │
│   w     │   w     │   ...   │
└─────────┴─────────┴─────────┘

Every block maintains its own:

Pv
Mv
Score boundary information

But the blocks are not completely independent.

Horizontal delta information leaving one block must become the input boundary condition for the next block.

Therefore a correct multiword implementation must propagate:

-1
0
or
+1

between neighboring blocks.

The block abstraction

Myers generalizes the one-word calculation by viewing a rectangular region of the DP matrix as a transformation:

input deltas
    ↓
w-cell block
    ↓
output deltas

A one-word bit-vector update can compute an entire:

1 × w

block of dynamic-programming cells efficiently.

This block abstraction makes the bit-vector method composable with other algorithms that compute only selected regions of a DP matrix.

Connection to Ukkonen

The Ukkonen algorithm reduces work by computing only the region of the matrix that can contain sufficiently low-cost states.

Myers reduces work in another dimension:

Ukkonen:
compute fewer DP states

Myers:
compute many remaining states
in parallel using machine words

These principles can be combined.

Myers' paper uses the bit-vector block machinery to accelerate zone-based dynamic-programming methods and derives an expected-time approximate-matching algorithm of:

O(kn/w)

for the corresponding large-pattern setting analyzed there.

Myers versus Ukkonen

A particularly important feature of Myers' basic algorithm is that its central scan does not have a multiplicative dependency on k.

Earlier bit-vector approximate-matching techniques frequently maintained state for every permitted error level. Myers instead encodes the DP matrix itself.

Why independence from k matters

Suppose:

pattern length = 50
word size      = 64

and compare:

k = 1

versus

k = 10

In the basic one-word Myers scan, the same bit-vector state update is performed.

The threshold is used to decide:

Score ≤ k ?

but the bit-vector transition itself does not require maintaining ten separate error levels.

This was a major conceptual difference from preceding bit-parallel automaton-state algorithms.

Relationship to Levenshtein automata

Earlier bit-vector approximate-matching algorithms can be viewed as representing the active state set of a k-difference automaton.

Myers changes the representation target:

earlier approach:
bit-vector representation
of automaton states

Myers:
bit-vector representation
of DP differences

Both solve closely related approximate-matching problems, but Myers' representation removes a direct multiplicative dependence on the allowed number of errors in the basic algorithm.

Finite-state approaches are treated separately in Levenshtein Automata.

Why the algorithm is exact

Bit parallelism is sometimes mistaken for approximation.

Myers' algorithm does not approximate the Levenshtein recurrence.

It computes an exact representation of the same dynamic-programming state transitions.

The transformation is:

integer DP matrix
        ↓
neighbor differences
        ↓
{-1,0,+1}
        ↓
two-bit-vector encoding
        ↓
Boolean/arithmetic identities
        ↓
exact DP evolution

The speedup comes from representation and hardware parallelism, not from changing the distance definition.

Why Pv and Mv are enough

Suppose the vertical differences of a column are:

+1
 0
-1
+1
-1
 0

Then:

Pv = 001001-like pattern
Mv = 010100-like pattern

with bit positions assigned consistently.

Every zero difference is implicit:

zero_mask =
~(Pv | Mv)

within the active pattern width.

Thus three states per position are encoded without storing a third explicit bit vector.

The significance of adjacent differences being bounded

The entire method depends on the special structure of unit-cost edit distance.

If neighboring DP values could differ by arbitrary amounts:

-37
+12
+98
...

two masks would not be sufficient.

The bounded-difference lemma converts a numerical DP matrix into finite-state local information.

This is why the standard Myers algorithm does not generalize trivially to arbitrary weighted edit costs.

Why arbitrary weighted Levenshtein is difficult

Suppose substitution costs can be:

0.17
0.82
4.0
...

and insertion and deletion costs vary by symbol.

Then adjacent DP differences are no longer necessarily restricted to:

-1
0
+1

The compact Pv/Mv encoding loses its defining property.

Other bit-parallel formulations exist for richer scoring systems, but they require different representations and should not be called the standard Myers 1999 bit-vector algorithm without qualification.

For general weighted costs, see Weighted Levenshtein Distance.

Transposition is not part of the classical Myers state

The standard Myers recurrence implements the unit-cost operations:

insertion
deletion
substitution

It does not make adjacent transposition a primitive operation.

Therefore:

ab
ba

has standard Levenshtein cost:

2

rather than a one-edit transposition cost.

A Damerau–Levenshtein or Optimal String Alignment implementation requires additional state structure.

See Damerau–Levenshtein Distance.

Alphabet preprocessing in practice

For a small fixed alphabet such as DNA:

{A,C,G,T}

Peq can be a tiny direct array.

For ASCII, a fixed array with 128 or 256 entries is also straightforward.

Unicode requires more care.

Allocating one bit vector for every possible Unicode code point is generally wasteful.

A practical implementation may instead store masks only for symbols actually appearing in the pattern:

map<symbol, bitmask>

and return zero for any text symbol absent from the map.

Peq construction pseudocode

function build_peq(pattern):

    Peq = empty map

    for i = 0 to length(pattern)-1:

        c = pattern[i]

        Peq[c] =
            Peq.get(c, 0)
            |
            (1 << i)

    return Peq

This preprocessing depends only on the pattern and can be reused when the same pattern is compared against many texts.

Pattern reuse

If one query is searched against many targets:

pattern
    ↓
build Peq once
    ↓
target 1
target 2
target 3
...
target N

the equality-mask construction cost is amortized across all comparisons.

This makes Myers particularly attractive in workloads such as:

  • read-to-candidate verification;
  • dictionary lookup;
  • batch fuzzy matching;
  • one-query-to-many-record comparison.

Unsigned arithmetic is important

The carry-propagation expression:

(Eq & Pv) + Pv

depends on predictable machine-word addition.

In languages such as C and C++, unsigned arithmetic is usually the appropriate representation because overflow is defined modulo:

2^w

for a w-bit unsigned word.

Using signed overflow can introduce undefined or implementation-dependent behavior in some languages.

Bitwise NOT requires special care

Expressions such as:

~(Xh | Pv)

set every bit outside the active pattern region as well.

For a pattern shorter than the machine word, unused high bits should not be allowed to contaminate state.

A clear approach is:

value & MASK

after relevant operations.

This is essential in arbitrary-precision integer languages where:

~x

conceptually has infinitely many leading one bits.

The highest active bit

The bottom DP row corresponds to:

bit m-1

when zero-based bit numbering is used.

Therefore:

LAST =
1 << (m-1)

must be computed carefully.

Common bugs include:

  • using bit m instead of m-1;
  • using the machine-word high bit rather than the pattern high bit;
  • failing when m = 0;
  • overflowing a signed shift into the sign bit.

The empty-pattern case

For global edit distance:

d("", target)
=
length(target)

There is no valid:

1 << (m-1)

when:

m = 0

so the empty-pattern case should normally be handled before entering the bit-vector algorithm.

Pattern length exactly equal to word width

The expression:

(1 << m) - 1

can itself be invalid in fixed-width languages when:

m = w

because shifting a w-bit value by exactly w bits can be undefined or invalid.

Production implementations therefore commonly special-case the full-word mask:

if m == w:
    MASK = ALL_ONES
else:
    MASK = (1 << m) - 1

This is an engineering issue rather than an algorithmic one, but it matters for correctness.

Finding the distance versus finding the alignment path

The compact bit-vector state gives distance information efficiently.

It does not automatically preserve every predecessor decision needed to reconstruct:

insert
delete
substitute
match

along an optimal path.

A full Wagner–Fischer matrix stores enough information for straightforward backtracking.

The Myers bit-vector scan deliberately compresses away much of that history.

The original algorithm does not directly return an edit script

The output of the basic approximate-matching algorithm is primarily:

match endpoints
+
their edit scores

rather than:

complete optimal edit paths

Later systems combine Myers-style scoring with additional algorithms or recomputation strategies to reconstruct alignments.

Edlib as an important modern implementation

The Edlib library is a prominent practical implementation based on Myers' bit-vector method. It extends the original algorithmic framework to support additional alignment modes and optimal-path reconstruction while retaining bit-vector edit-distance computation.

This provides an instructive example of the distinction between:

historical Myers algorithm
and
modern systems built around Myers' core primitive

A mature implementation can combine Myers with banding, Hirschberg-style reconstruction, and workload-specific engineering.

Global, prefix, and infix alignment modes

Different boundary conditions correspond to different alignment questions.

Mode Conceptual question
Global Transform the complete pattern into the complete target.
Prefix / semiglobal Align the pattern while allowing selected terminal gaps to be free.
Infix / substring search Find a substring of the target that best matches the pattern.

The central bit-vector transition can remain closely related while the boundary conditions and interpretation of Score change.

Why boundary conditions are part of the algorithm

It is not enough to copy these lines:

Xv = Eq | Mv
Xh = (((Eq & Pv) + Pv) ^ Pv) | Eq

and assume the result computes the desired distance.

The full mathematical problem also depends on:

  • initial Pv and Mv;
  • initial Score;
  • top horizontal boundary state;
  • how blocks are connected;
  • which score is reported.

Two implementations can use the same core formulas while solving different alignment problems.

Limited regular-expression extension

Myers also notes that the equality-mask mechanism can support limited pattern expressions.

Normally:

Peq[c][i] = 1
iff
pattern[i] = c

but a pattern position can instead represent a set of acceptable symbols.

Then:

Peq[c][i] = 1
iff
c belongs to allowed_symbols[i]

A wildcard position can therefore set the corresponding bit in every relevant equality mask.

The dynamic-programming core does not need to know why the equality condition is true.

Why Peq is an abstraction boundary

The bit-vector algorithm only needs:

Eq[i] =
does text symbol c match pattern position i?

Therefore the definition of “match” can be supplied by preprocessing.

This separates:

symbol matching semantics
from
edit-distance state evolution

within the restrictions of the algorithm's unit-cost framework.

Unicode representation still matters

Myers operates on abstract sequence elements.

A software implementation must decide whether one pattern position corresponds to:

  • one byte;
  • one UTF-8 code unit;
  • one UTF-16 code unit;
  • one Unicode code point;
  • one grapheme cluster;
  • one token.

Bit parallelism does not solve Unicode representation problems.

Canonical-equivalence example

The visible character:

é

may appear as:

U+00E9

or:

U+0065
U+0301

At code-point level these are different sequences and therefore produce different Peq structures unless normalization is performed first.

The algorithm can be perfectly implemented and still compute the wrong application-level distance if preprocessing uses the wrong sequence unit.

See Unicode and Grapheme-Safe Levenshtein.

Token-level Myers

Nothing in the mathematical bit-vector representation requires ASCII characters.

If tokens are mapped to stable symbolic IDs:

[the, quick, brown, fox]

can be treated as a sequence of four symbols.

Peq then maps token IDs to bit masks instead of characters.

This makes the same basic approach applicable to short token sequences, subject to the unit-cost edit model and pattern-length constraints.

Why word-level bit parallelism can be powerful

Consider a query containing:

40 tokens

on a machine with:

w = 64

The entire token-level pattern state can fit inside a single 64-bit word.

A text token can then advance all forty pattern positions through bit operations just as a character advances a character-level pattern.

CPU-level reasons Myers is fast

The algorithm has several practical properties favorable to modern processors:

  • small working state;
  • few branches in the core loop;
  • heavy use of register-resident bit operations;
  • contiguous sequential text scanning;
  • small equality-mask tables for small alphabets;
  • no full DP matrix allocation;
  • high arithmetic intensity relative to memory traffic.

For short patterns, the active state can remain almost entirely inside CPU registers.

Register-resident computation

For:

m ≤ 64

a typical implementation may need only a handful of 64-bit values in the hot loop:

Pv
Mv
Eq
Xv
Xh
Ph
Mh
Score

This is very different from repeatedly loading and storing integer rows of a dynamic-programming matrix.

Memory complexity

For a one-word pattern, the dynamic state is constant-size:

O(1)

machine words, excluding the pattern-equality table.

For a general pattern:

ceil(m/w)

words are required per logical bit vector or per active block representation.

Thus the working DP state is proportional to:

O(m/w)

machine words rather than:

O(m)

full integer DP cells.

Peq memory

With a direct table over alphabet size:

σ

and:

b = ceil(m/w)

blocks, the equality-mask structure can conceptually require:

O(σb)

machine words.

For large sparse alphabets, a hash map or compressed table over only pattern symbols can reduce this substantially.

The relation to the Four Russians technique

The Four Russians method accelerates dynamic programming by grouping cells into blocks and precomputing the result of all possible boundary configurations for small blocks.

The Masek–Paterson algorithm is a foundational example of this philosophy.

Myers observes that a machine word can itself compute a block of dynamic-programming state directly:

table lookup over tiny block
versus
bit arithmetic over w-cell block

This removes the need for large precomputed block tables in important settings and improves cache behavior.

Why carry propagation resembles a parallel prefix computation

The most sophisticated part of Myers is:

((Eq & Pv) + Pv)

Binary addition can propagate a carry through an arbitrarily long contiguous run of one bits inside the machine word.

From the viewpoint of algorithm design, this means:

many dependent logical positions
        ↓
hardware carry chain
        ↓
one integer addition instruction

This is a recurring pattern in bit-parallel algorithm design: reinterpret arithmetic hardware as a massively parallel finite-state operator.

Why a naive per-bit translation misses the point

One could conceptually calculate the same Pv/Mv transitions one bit at a time:

for i = 1 to m:
    calculate delta state at i

but then:

time per text character = O(m)

and the benefit disappears.

Myers' accomplishment is deriving expressions whose machine-word semantics compute the same logical recurrence without explicitly iterating through the bits.

Correctness structure

The correctness argument can be understood in several layers.

1. Classical DP correctness

The matrix recurrence computes exact unit-cost edit distance for the chosen boundary conditions.

2. Delta equivalence

A complete DP column can be represented by its neighboring differences together with one absolute boundary value.

3. Bounded delta values

Every horizontal and vertical difference is one of:

-1
0
+1

4. Bit-vector encoding

The P and M masks exactly encode positive and negative deltas.

5. Boolean cell identities

The formulas for Ph, Mh, Pv, and Mv reproduce the scalar cell transition.

6. Carry-propagation identity

The integer-addition expression for Xh exactly performs the necessary propagation across runs of positive vertical states.

7. Score invariant

After scanning text position j:

Score = C[m,j]

because it is updated by the bottom horizontal difference.

Together, these invariants establish that the bit-vector representation computes the same result as the corresponding dynamic program.

A useful invariant for debugging

For every scanned text column, a reference implementation can reconstruct the vertical deltas from a conventional DP matrix and verify:

Pv[i] = 1
iff
C[i,j] - C[i-1,j] = +1

Mv[i] = 1
iff
C[i,j] - C[i-1,j] = -1

and:

Score = C[m,j]

This is a powerful way to validate a new Myers implementation on short random inputs.

Common implementation mistakes

Using the wrong boundary semantics

Original Myers approximate matching and global pairwise distance do not use identical top-row boundaries.

Forgetting to mask bitwise NOT

This is especially dangerous in Python-like arbitrary-precision integer semantics.

Using signed arithmetic

Carry propagation and shifts should have clearly defined finite-width behavior.

Incorrect LAST bit

The score update depends on exactly the bit corresponding to pattern row m.

Using a one-word algorithm for m > w

Silently truncating pattern bits produces incorrect results.

Ignoring cross-block horizontal carries

Multiword blocks are connected dynamic-programming regions, not independent words.

Assuming the algorithm directly returns an alignment path

The basic bit-vector scan computes scores, not complete predecessor history.

Applying standard Myers to arbitrary weighted edit costs

The -1/0/+1 delta representation depends on the unit-cost model.

Applying byte-level matching to Unicode text unintentionally

The sequence unit must be chosen before bit-vector encoding.

Performance engineering considerations

A high-quality implementation should consider:

  • using the shorter suitable sequence as the bit-vector pattern where alignment semantics allow;
  • precomputing Peq once per reusable pattern;
  • using fixed-width unsigned words;
  • avoiding allocations inside the scanning loop;
  • keeping block arrays contiguous;
  • specializing small alphabets;
  • minimizing dictionary/hash lookup overhead in the hot loop;
  • using threshold or band information when available;
  • batching independent comparisons for higher-level parallelism.

Historical context

Bit-parallel approximate matching predates Myers' 1999 paper. Earlier methods, including work by Wu and Manber, represented active states of approximate-matching automata with bit vectors.

Myers introduced a different representation based directly on the dynamic-programming matrix's horizontal and vertical differences. Because those differences are restricted to -1, 0, and +1, a whole column of DP state can be encoded using positive and negative bit masks.

The paper's crucial technical step is the derivation of a constant-size word-operation sequence for advancing this representation, including the integer-addition carry-propagation formula for Xh.

The result was published as A Fast Bit-Vector Algorithm for Approximate String Matching Based on Dynamic Programming in the Journal of the ACM, volume 46, issue 3, pages 395–415, in May 1999.

Common conceptual mistakes

“Myers is an approximate algorithm”

No. It solves approximate matching, but its Levenshtein computations are exact.

“Myers always computes global edit distance”

No. The original 1999 formulation is approximate substring matching with:

C[0,j] = 0

Global distance requires different boundary treatment.

“Myers is O(n) for every pattern length”

No. That statement assumes the pattern occupies one constant-size machine word. General basic complexity depends on:

ceil(m/w)

“k determines the number of basic Myers states”

Not in the core 1999 DP-delta algorithm. Its principal bit-vector scan is independent of k.

“Bit vectors approximate the matrix”

No. They encode its local differences exactly.

“The addition in Xh is only an optimization trick”

It is more fundamental: the carry chain implements the propagation required by the DP-state logic.

“Myers supports any edit-cost model”

No. The standard representation relies critically on the unit-cost neighboring-delta structure.

A rigorous implementation checklist

  1. Define the alignment problem.
    Global pairwise distance, prefix alignment, or substring/infix matching?
  2. Define the sequence element.
    Byte, code point, grapheme cluster, token, or another symbol?
  3. Confirm the edit model is compatible.
    Classical Myers assumes unit-cost insertion, deletion, and substitution.
  4. Determine machine-word width.
  5. Handle m = 0 explicitly.
  6. Handle m = w safely.
  7. Use unsigned finite-width arithmetic where appropriate.
  8. Mask unused high bits.
  9. Build Peq according to the actual sequence alphabet.
  10. Use the correct top-boundary shift.
  11. Implement cross-block delta propagation for m > w.
  12. Differential-test against Wagner–Fischer.
  13. Test global and substring semantics separately.
  14. Do not infer an edit script from Score alone.

Summary

The Myers bit-vector algorithm is one of the most elegant transformations of classical edit-distance dynamic programming. Rather than storing every integer DP value, it observes that horizontal and vertical differences between neighboring cells in the unit-cost matrix are always -1, 0, or +1. A complete column can therefore be represented by two masks: Pv for positive vertical differences and Mv for negative ones.

Pattern equality is also converted into bit vectors through the precomputed Peq table. The difficult sequential dependency between pattern positions is then resolved using a remarkable arithmetic identity: binary addition propagates carries through runs of set Pv bits, allowing the necessary horizontal DP dependency to be computed for an entire machine word in parallel.

When the pattern fits inside one machine word, one text character can advance the complete DP state with a fixed sequence of word operations. For longer patterns, the state is divided into ceil(m/w) blocks, giving the basic word-parallel complexity O(n ceil(m/w)), commonly written O(nm/w).

The original algorithm should nevertheless be understood precisely. Myers' 1999 formulation solves approximate substring matching with a zero-cost text-prefix boundary; it is not automatically identical to a global pairwise Levenshtein implementation. Boundary initialization, horizontal input deltas, block propagation, bit masking, sequence representation, and output interpretation are all part of the algorithm's correctness.

Its scientific importance goes beyond practical speed. Myers demonstrates how algebraic structure inside a dynamic-programming matrix can be exposed, encoded as finite local differences, and mapped directly onto machine arithmetic. It is therefore a foundational example of bit-parallel algorithm design as well as one of the most important practical algorithms for exact edit-distance matching.
