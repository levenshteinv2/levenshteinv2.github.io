Damerau–Levenshtein Distance

Damerau–Levenshtein distance extends classical Levenshtein distance by adding one additional primitive edit operation: the transposition of two adjacent sequence elements. Under the standard unit-cost model, insertion, deletion, substitution, and adjacent transposition each cost one, and the distance between two strings is the minimum total number of these operations required to transform one string into the other.

The additional operation appears small, but it changes both the mathematical model and the algorithms needed to compute it correctly. A simple dynamic-programming recurrence can detect isolated adjacent swaps, but that recurrence computes a restricted distance known as Optimal String Alignment, or OSA, rather than unrestricted Damerau–Levenshtein distance. The two functions agree on many ordinary spelling errors but differ when a substring participates in more than one edit.

This distinction is not merely terminological. Unrestricted unit-cost Damerau–Levenshtein distance is a metric. Optimal String Alignment distance is not: it can violate the triangle inequality. Algorithms, metric indexes, thresholds, theoretical guarantees, and software APIs must therefore distinguish the two models explicitly.

Definition

Let:

x = x₁x₂...xₘ
y = y₁y₂...yₙ

be finite sequences over an alphabet:

Σ

The standard Damerau–Levenshtein edit operations are:

  1. insert one symbol;
  2. delete one symbol;
  3. substitute one symbol for another;
  4. transpose two adjacent symbols.

Under the classical unit-cost model:

cost(insert)       = 1
cost(delete)       = 1
cost(substitution) = 1
cost(transposition)= 1
cost(match)        = 0

The Damerau–Levenshtein distance is:

d_DL(x,y)
=
minimum number of allowed edit operations
in any edit script transforming x into y

Adjacent transposition

The fourth primitive operation has the form:

... a b ...
      ↓
... b a ...

where:

a
and
b

occupy adjacent positions.

Example

form
→
from

The middle pair:

o r

is transposed:

f o r m
  ↓
f r o m

Therefore:

d_DL(
    "form",
    "from"
)
=
1

Classical Levenshtein distance does not contain transposition as a primitive operation. It normally requires:

o → r
r → o

or an equivalent two-edit script, giving:

d_L(
    "form",
    "from"
)
=
2

Adjacent does not mean arbitrary transposition

Damerau–Levenshtein distance permits swapping:

positions i and i+1

not arbitrary positions:

i and j

in one operation.

For example:

abcd
→
dbca

cannot move:

d

directly from the fourth position to the first at cost one.

It would require a sequence of adjacent transpositions or another combination of edit operations.

A distance allowing arbitrary symbol swaps, substring movement, or block permutation is a different edit model.

Historical origin

Fred J. Damerau's 1964 work on spelling-error detection studied four important single-error classes:

  • a wrong letter;
  • a missing letter;
  • an extra letter;
  • a single transposition.

The first three correspond closely to:

substitution
deletion
insertion

while the fourth motivates adjacent transposition.

The modern term Damerau–Levenshtein distance combines this transposition-aware error model with the minimum-edit-distance framework associated with Levenshtein.

A mathematically important later development was the 1975 work of Roy Lowrance and Robert A. Wagner, who extended the string-to-string correction problem to include adjacent character interchange and derived a dynamic-programming algorithm under explicit edit-cost conditions.

Levenshtein versus Damerau–Levenshtein

Operation Levenshtein Damerau–Levenshtein
Insertion Yes Yes
Deletion Yes Yes
Substitution Yes Yes
Adjacent transposition No Yes

Because every Levenshtein edit script is also a valid Damerau–Levenshtein edit script:

d_DL(x,y)
≤
d_L(x,y)

for the standard unit-cost models.

A useful relationship between the two distances

Every adjacent transposition can be simulated by at most two Levenshtein substitutions:

ab
→
bb
→
ba

or by another two-edit Levenshtein transformation.

Therefore an optimal Damerau–Levenshtein script of length:

k

can be converted into a Levenshtein script of length at most:

2k

giving:

d_L(x,y)
≤
2 d_DL(x,y)

Hence:

ceil(
    d_L(x,y) / 2
)
≤
d_DL(x,y)
≤
d_L(x,y)

for standard unit-cost distances.

This bound is useful when a Levenshtein value is already known and a quick theoretical range for Damerau–Levenshtein distance is required.

Basic bounds

Because insertions and deletions are required to compensate for sequence-length differences:

d_DL(x,y)
≥
||x|-|y||

As substitutions can replace every aligned symbol and insertions can supply any excess target symbols:

d_DL(x,y)
≤
max(
    |x|,
    |y|
)

under unit costs.

Thus:

||x|-|y||
≤
d_DL(x,y)
≤
max(|x|,|y|)

The central complication: two different transposition distances

A great deal of software and documentation uses the label:

Damerau-Levenshtein

for two different functions.

They are:

  1. Optimal String Alignment distance, the restricted variant;
  2. unrestricted Damerau–Levenshtein distance, the true minimum edit distance under the four primitive operations.

The difference appears when a substring needs to participate in more than one edit operation.

Optimal String Alignment distance

Optimal String Alignment distance permits:

  • insertion;
  • deletion;
  • substitution;
  • adjacent transposition;

but imposes a restriction commonly described as:

no substring may be edited more than once.

This restriction makes a very simple dynamic-programming recurrence possible.

OSA recurrence

Let:

D[i][j]

be the OSA distance between:

x₁...xᵢ

and:

y₁...yⱼ

Initialize:

D[0][0] = 0

D[i][0] = i

D[0][j] = j

The ordinary Levenshtein candidates are:

deletion:
D[i-1][j] + 1

insertion:
D[i][j-1] + 1

match/substitution:
D[i-1][j-1]
+
[xᵢ != yⱼ]

If:

i > 1
j > 1

xᵢ     = y_(j-1)
x_(i-1)= yⱼ

the final two symbols are reversed relative to one another, so one additional candidate is:

D[i-2][j-2] + 1

for a transposition.

Thus:

D[i][j]
=
min(
    deletion,
    insertion,
    match_or_substitution,
    optional_transposition
)

OSA pseudocode

function optimal_string_alignment(a, b):

    m = length(a)
    n = length(b)

    D =
        matrix(
            m+1,
            n+1
        )

    for i = 0..m:
        D[i][0] = i

    for j = 0..n:
        D[0][j] = j

    for i = 1..m:

        for j = 1..n:

            if a[i-1] == b[j-1]:
                cost = 0
            else:
                cost = 1

            D[i][j] =
                min(
                    D[i-1][j] + 1,
                    D[i][j-1] + 1,
                    D[i-1][j-1] + cost
                )

            if i > 1
               and j > 1
               and a[i-1] == b[j-2]
               and a[i-2] == b[j-1]:

                D[i][j] =
                    min(
                        D[i][j],
                        D[i-2][j-2] + 1
                    )

    return D[m][n]

OSA complexity

The OSA matrix has:

(m+1)(n+1)

cells and constant work per cell.

Therefore:

Time:
O(mn)

A full matrix uses:

Space:
O(mn)

but distance-only implementations can reduce memory because the recurrence needs only a small number of previous rows, including the row two positions back for transposition.

The example that separates OSA from true Damerau–Levenshtein

Consider:

x = "ca"
y = "abc"

Unrestricted Damerau–Levenshtein distance is:

2

because:

ca
→
ac
→
abc

using:

1. transpose c and a
2. insert b

Therefore:

d_DL(
    "ca",
    "abc"
)
=
2

OSA does not permit the required interaction of edits after the transposition.

Its minimum is:

3

for example:

ca
→
a
→
ab
→
abc

Thus:

d_OSA(
    "ca",
    "abc"
)
=
3

The fundamental ordering

Because unrestricted Damerau–Levenshtein permits every edit script available to OSA, while OSA adds transposition possibilities beyond ordinary Levenshtein:

d_DL(x,y)
≤
d_OSA(x,y)
≤
d_L(x,y)

under the standard unit-cost definitions.

The inequalities may be equal for most ordinary pairs, but they are not identities.

Why OSA is not a metric

A metric must satisfy triangle inequality:

d(x,z)
≤
d(x,y)
+
d(y,z)

Consider:

x = "ca"
y = "ac"
z = "abc"

Under OSA:

d_OSA(
    "ca",
    "ac"
)
=
1

because one transposition is sufficient.

Also:

d_OSA(
    "ac",
    "abc"
)
=
1

because one insertion is sufficient.

But:

d_OSA(
    "ca",
    "abc"
)
=
3

Therefore:

3
>
1 + 1

and:

d_OSA(
    "ca",
    "abc"
)
>
d_OSA(
    "ca",
    "ac"
)
+
d_OSA(
    "ac",
    "abc"
)

Triangle inequality fails.

Consequently OSA should not be used as though it were a metric inside algorithms whose correctness depends on metric geometry.

Why unrestricted Damerau–Levenshtein is a metric

For unit symmetric edit costs, unrestricted Damerau–Levenshtein distance satisfies all four metric axioms.

1. Non-negativity

Every permitted operation has nonnegative cost:

1

and therefore:

d_DL(x,y)
≥
0

2. Identity of indiscernibles

No edits are needed when:

x = y

so:

d_DL(x,x) = 0

Conversely, transforming two distinct strings requires at least one positive-cost edit:

x != y
⇒
d_DL(x,y) > 0

3. Symmetry

Every edit has an inverse of equal cost.

insert
↔
delete

substitute a→b
↔
substitute b→a

transpose ab→ba
↔
transpose ba→ab

Therefore reversing an optimal script from:

x → y

produces an equally costly script:

y → x

so:

d_DL(x,y)
=
d_DL(y,x)

4. Triangle inequality

Take an optimal script:

x → y

of cost:

d_DL(x,y)

and an optimal script:

y → z

of cost:

d_DL(y,z)

Concatenating them produces a valid script:

x → y → z

whose total cost is:

d_DL(x,y)
+
d_DL(y,z)

The optimal direct transformation from:

x → z

cannot cost more than that valid script.

Thus:

d_DL(x,z)
≤
d_DL(x,y)
+
d_DL(y,z)

and unit-cost unrestricted Damerau–Levenshtein distance is a true metric.

Why the OSA restriction destroys triangle inequality

The preceding triangle-inequality proof relies on one crucial fact:

two valid edit scripts
can always be concatenated
into another valid edit script

OSA removes that closure property.

A valid transformation:

x → y

and another valid transformation:

y → z

may compose into a sequence that violates the rule that no substring may be edited more than once.

Therefore the composition argument behind triangle inequality no longer works.

This gives a deeper explanation of why OSA is not a metric rather than treating the counterexample as an isolated anomaly.

Why unrestricted computation is more difficult

The ordinary Wagner–Fischer recurrence works because the final edit of an optimal transformation depends only on immediately adjacent prefix states.

For OSA, an adjacent transposition also has a local predecessor:

D[i-2][j-2]

because the transposition is allowed only as one isolated operation on the final pair.

Unrestricted Damerau–Levenshtein distance is harder.

Consider a transformation where:

one character is transposed

and

characters between the transposed endpoints
are inserted or deleted

The optimal predecessor may occur far earlier in the matrix.

A correct recurrence therefore needs information about previous occurrences of the symbols involved.

The Lowrance–Wagner insight

Lowrance and Wagner showed that, under the appropriate edit-cost condition, one can restrict attention to a structured family of optimal edit traces.

For insertion cost:

W_I

deletion cost:

W_D

and adjacent swap cost:

W_T

their key condition is:

2W_T
≥
W_I + W_D

The unit-cost Damerau–Levenshtein model has:

W_I = 1
W_D = 1
W_T = 1

so:

2 · 1
≥
1 + 1

holds exactly.

This allows a quadratic-time algorithm for the standard distance.

Why the cost condition matters

If transpositions become too cheap relative to insertions and deletions, optimal edit traces can develop long chains of interacting crossings.

The simple structural characterization used by the Lowrance–Wagner dynamic program no longer suffices.

Thus one should not assume that:

arbitrary weighted
insertion/deletion/substitution/transposition

automatically has the same:

O(mn)

algorithm as standard unit-cost Damerau–Levenshtein distance.

The weighted extended string-to-string correction problem has a more complicated complexity landscape.

General weighted swaps can fundamentally change complexity

Once the edit costs are generalized beyond the classical regime, the problem is no longer merely:

replace every +1
with a custom weight

The geometry of optimal edit scripts changes.

Historical complexity work on the extended string-to-string correction problem demonstrated that some cost regimes remain polynomial while more general formulations can become computationally much harder.

This is an important example of a broader principle:

Changing the edit operation set or cost system can change not only the numerical distance but also the computational complexity of finding it.

The unrestricted O(mn) algorithm

For standard unit costs, a correct unrestricted Damerau–Levenshtein algorithm keeps additional information about the most recent occurrences of characters.

Let:

last[c]

store the most recent row position in the source string where character:

c

has appeared.

During each matrix row, another variable records the most recent column in the target where the current source character matched.

These values locate the only earlier pair of matching symbols needed to construct the relevant transposition candidate in constant time.

Unrestricted pseudocode

function damerau_levenshtein(a, b):

    m = length(a)
    n = length(b)

    INF =
        m + n

    H =
        matrix(
            m + 2,
            n + 2
        )

    H[0][0] = INF

    for i = 0..m:

        H[i+1][0] = INF
        H[i+1][1] = i

    for j = 0..n:

        H[0][j+1] = INF
        H[1][j+1] = j

    last =
        map with default value 0

    for i = 1..m:

        last_match_col = 0

        for j = 1..n:

            i1 =
                last[b[j-1]]

            j1 =
                last_match_col

            if a[i-1] == b[j-1]:

                cost = 0
                last_match_col = j

            else:

                cost = 1

            substitution =
                H[i][j]
                +
                cost

            insertion =
                H[i+1][j]
                +
                1

            deletion =
                H[i][j+1]
                +
                1

            transposition =
                H[i1][j1]
                +
                (i - i1 - 1)
                +
                1
                +
                (j - j1 - 1)

            H[i+1][j+1] =
                min(
                    substitution,
                    insertion,
                    deletion,
                    transposition
                )

        last[a[i-1]] =
            i

    return H[m+1][n+1]

Why the sentinel border exists

The unrestricted algorithm uses a matrix larger than the ordinary Levenshtein matrix:

(m+2)
×
(n+2)

with an artificial sentinel value:

INF

along the outer border.

For unit costs:

INF = m+n

is safely greater than any relevant optimal distance.

The sentinel prevents nonexistent previous occurrences from accidentally producing attractive transposition candidates.

The meaning of the transposition term

The most difficult line in the algorithm is:

H[i1][j1]
+
(i-i1-1)
+
1
+
(j-j1-1)

It summarizes a potentially nonlocal transformation.

Conceptually:

H[i1][j1]

is the best cost before the two symbols involved in the crossing/transposition structure.

The term:

i-i1-1

accounts for source characters between the two relevant occurrences that must effectively be deleted.

The:

1

is the transposition itself.

The term:

j-j1-1

accounts for target characters between the corresponding positions that must effectively be inserted.

Thus the transition compresses a pattern of:

delete intermediate symbols
        ↓
transpose matching endpoints
        ↓
insert intermediate target symbols

into one dynamic-programming candidate.

Why last occurrence information is enough

Naively, computing an unrestricted transposition candidate could require examining many earlier positions:

all previous occurrences
of b[j]

×
all previous occurrences
of a[i]

for every matrix cell.

That would destroy the quadratic bound.

The Lowrance–Wagner structural result shows that under the relevant cost condition, only the most recent compatible occurrences need to be considered for the optimal restricted trace used by their algorithm.

The:

last

table and:

last_match_col

variable allow those positions to be retrieved in:

O(1)

time per matrix cell.

Time complexity

There are:

mn

interior matrix cells.

For each cell, the unrestricted algorithm performs:

  • constant-time character comparisons;
  • constant-time last-occurrence lookups;
  • four candidate calculations;
  • one minimum operation.

Therefore:

Time:
O(mn)

for the standard unit-cost model.

Classical space complexity

The straightforward Lowrance–Wagner-style implementation stores:

O(mn)

matrix values.

Unlike ordinary Wagner–Fischer, reducing this matrix to only two rows is not immediate because transposition candidates may refer back to rows associated with earlier occurrences of specific characters.

The last-occurrence dependency is more global than the:

previous row
+
current row

dependency of ordinary Levenshtein distance.

Reduced-space algorithms

Later algorithms observed that it is unnecessary to retain every historical row.

For each alphabet character, it is sufficient to preserve selected rows associated with its latest relevant occurrence.

For alphabet size:

s

and strings of lengths:

m
and
n

reduced-space algorithms can compute the distance using memory on the order of:

O(
    s · min(m,n)
    +
    m
    +
    n
)

while retaining:

O(mn)

time.

For fixed small alphabets, this becomes linear in the input lengths.

Why alphabet size appears in reduced-space algorithms

Ordinary Levenshtein DP only needs spatially adjacent matrix rows.

Unrestricted Damerau–Levenshtein may need the row associated with the previous occurrence of:

a particular character

Rather than retaining every row:

row 1
row 2
...
row m

one can preserve selected information indexed by:

character

Hence memory depends partly on:

|Σ|

Consider:

x = "hte"

h → t

for:

h t
→
t h

as one adjacent transposition:

d_DL(
    "hte",
    "the"
)
=
1

This is exactly the kind of local typing error for which the transposition-aware model is attractive.

Why most typo examples do not reveal the OSA problem

Suppose a misspelling contains one isolated adjacent transposition:

hte
→
the

Both:

OSA

and:

unrestricted DL

return:

1

The difference appears only when edit operations interact.

Consequently, a test suite containing only ordinary isolated typos can make an OSA implementation appear to be a correct unrestricted Damerau–Levenshtein implementation.

The pair:

"ca"
"abc"

should therefore be treated as a canonical regression test.

Relationship to weighted Levenshtein distance

Damerau–Levenshtein changes the operation set.

Weighted Levenshtein Distance changes the cost model.

The two ideas can be combined:

insert:
W_I

delete:
W_D

substitute:
W_S

transpose:
W_T

or with symbol-dependent costs.

But once weights are generalized, the metric and algorithmic properties must be reanalyzed.

Weighted adjacent transpositions

A keyboard model might define:

transpose adjacent characters:
0.5

while:

ordinary substitution:
1.0

to reflect a belief that adjacent swaps are especially plausible typing errors.

Relationship to edit distance variants

Damerau–Levenshtein belongs to the broader family described in Edit Distance Variants.

=

Adjacent transposition and human typing

One of the strongest motivations for Damerau–Levenshtein distance is keyboard input.

A user intending:

the

may type:

because two keystrokes were entered in reversed order.

Classical Levenshtein interprets this as two symbol differences.

Damerau–Levenshtein interprets it as one transposition event.

If the application wants the score to approximate human error events rather than raw symbol replacements, the latter model can be more faithful.

But transpositions are not always one real-world error

The modeling assumption should still be questioned.

In some domains:

ab → ba

may represent:

  • two independent substitutions;
  • a structural reorder;
  • a severe error;
  • an impossible event.

Adding transposition automatically because it reduces numerical distance is not scientifically justified.

The operation should be included only when adjacent order reversal corresponds to a meaningful primitive error in the application.

Edit script reconstruction

Computing the numerical distance is different from recovering the actual sequence of edits.

With a full dynamic-programming matrix, each cell can record which transition produced its optimum:

Starting at the final state, follow predecessor pointers until:

Reverse the resulting operation list to obtain a forward edit script.

Transposition traceback contains nonlocal jumps

For unrestricted DL, a transposition predecessor may be:

A traceback system must therefore store or reconstruct:

  • the earlier matching target occurrence;
  • intermediate deletions;
  • the transposition;
  • intermediate insertions.

Treating the transposition transition as merely:

would reconstruct OSA-style transpositions rather than the full Lowrance–Wagner structure.

3. SUBSTITUTE

When OSA can still be appropriate

OSA is not inherently wrong.

It is a different distance.

It can be attractive when:

  • transpositions are expected to be isolated;
  • strings are short;
  • the metric property is not required;
  • implementation simplicity is important;
  • the restricted model matches the intended application.

The problem occurs when OSA is described or used as though it were unrestricted DL.

When unrestricted DL is preferable

Use unrestricted Damerau–Levenshtein when:

  • the mathematical definition truly requires arbitrary sequences of the four edit operations;
  • transposed symbols may participate in later edits;
  • metricity matters;

Common misconceptions

"Damerau–Levenshtein is Levenshtein with one extra if statement"

That describes the common OSA recurrence, not unrestricted Damerau–Levenshtein distance.

"OSA and Damerau–Levenshtein always give the same answer"

No.

DL("ca","abc") = 2

OSA("ca","abc") = 3

"Any swap counts as one transposition"

No. The primitive operation swaps adjacent symbols only.

"OSA is a metric because all edit operations cost one"

No. Its restriction on repeated editing breaks closure under concatenation and triangle inequality can fail.

"Unrestricted DL has to be slower than quadratic"

No. Standard unit-cost DL has an O(mn) Lowrance–Wagner-style algorithm.

"Weighted DL is always metric"

No. Metric properties depend on the cost system.

"If two names have distance one, they are the same entity"

No. String distance measures sequence edits, not identity.

"Normalization keeps all properties of the original metric"

Not automatically. Triangle inequality must be reconsidered for the normalized function.

  1. Decide whether the required function is OSA or unrestricted DL.
  2. Define the sequence unit.

  3. Confirm that transposition means adjacent transposition.
  4. Use the canonical "ca" versus "abc" test.
  5. Verify symmetry for the standard unit-cost implementation.

  7. Do not apply metric pruning to OSA.
  8. Audit weighted costs before reusing the standard algorithm.

Implementation checklist

  1. Map sequence symbols to compact IDs when practical.
  2. Initialize the unrestricted matrix with a safe sentinel border.
  3. Initialize the last-occurrence structure to zero/no occurrence.
  4. Reset the current row's last matching target column before each inner loop.

  10. Benchmark memory traffic as well as arithmetic runtime.

Why this distance remains important

Damerau–Levenshtein distance occupies an important position between very simple positional comparison and more elaborate probabilistic or domain-specific sequence models.

Compared with ordinary Levenshtein distance, it captures a common class of local ordering errors with only one additional primitive operation.

Compared with unrestricted language or probabilistic models, it remains:

  • mathematically clean;
  • exact;
  • interpretable;
  • computable in quadratic time under the standard model;
  • metric when unrestricted and unit-cost.

Its greatest conceptual challenge is not the definition of transposition itself. It is maintaining the distinction between a genuinely unrestricted edit metric and restricted approximations that happen to agree on many common examples.

Summary

Damerau–Levenshtein distance extends classical Levenshtein distance by treating the transposition of two adjacent sequence elements as one primitive edit alongside insertion, deletion, and substitution. Under the standard unit-cost model, the distance is the minimum number of these four operations required to transform one sequence into another.

Adding transposition can materially change results. For example, form → from has Levenshtein distance 2 but Damerau–Levenshtein distance 1. More generally, because the Damerau model contains every ordinary Levenshtein operation, d_DL(x,y) ≤ d_L(x,y). A transposition can be simulated by at most two Levenshtein edits, yielding the useful unit-cost bound ceil(d_L/2) ≤ d_DL ≤ d_L.

The most important distinction is between Optimal String Alignment distance and unrestricted Damerau–Levenshtein distance. OSA uses a simple extension of Wagner–Fischer in which a reversed final pair can be reached from D[i-2][j-2] with one transposition. That algorithm is quadratic and useful, but it restricts substrings from participating repeatedly in edits. Consequently it can produce different values from true DL.

The canonical example is "ca" versus "abc". Unrestricted Damerau–Levenshtein gives 2 through ca → ac → abc, whereas OSA gives 3. The same example also exposes a deeper distinction: OSA does not satisfy triangle inequality and is not a metric.

Unrestricted unit-cost Damerau–Levenshtein distance is a metric. Non-negativity and identity follow from positive edit costs; symmetry follows because every edit has an equal-cost inverse; and triangle inequality follows because valid unrestricted edit scripts can be concatenated. These properties make true DL suitable for metric reasoning and metric indexes in ways that OSA is not.

Computing unrestricted DL requires more than the local OSA transposition recurrence. The classical Lowrance–Wagner method retains the most recent occurrences of characters and uses them to construct nonlocal transposition candidates. Under the standard unit-cost model, this gives O(mn) time. The classical implementation uses O(mn) space, while later algorithms reduce memory substantially by preserving only character-dependent historical rows.

The Lowrance–Wagner result also reveals why weighted transpositions need special care. Their quadratic algorithm relies on a relationship between swap, insertion, and deletion costs; arbitrary cost systems can produce more complex interacting edit traces. Weighted Damerau–Levenshtein is therefore a distinct theoretical problem rather than a mechanical replacement of every unit cost by an arbitrary number.

Finally, the sequence representation remains part of the model. An adjacent transposition over UTF-8 bytes, Unicode code points, grapheme clusters, words, or biological symbols represents a different operation. A scientifically correct implementation must define this representation before assigning meaning to the numerical distance.

The core lesson is simple but important: Damerau–Levenshtein distance is not merely Levenshtein distance with an extra transposition condition. The unrestricted metric has a richer dependency structure, stronger mathematical properties, and a different algorithm from the restricted OSA recurrence that is frequently mislabeled with the same name.
