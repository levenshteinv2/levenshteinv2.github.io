String Similarity vs Semantic Similarity: Edit Distance, Embeddings & Meaning

String similarity and semantic similarity answer different questions.

String similarity compares observable representations: characters, tokens, q-grams or other symbolic sequences. Semantic similarity attempts to compare the meanings expressed by words, phrases, sentences, documents or concepts.

Levenshtein distance belongs to the first category. It measures the minimum edit cost required to transform one represented sequence into another.

It does not contain an intrinsic model of synonymy, negation, semantic roles, world knowledge, factual truth or real-world identity.

surface similarity
≠
semantic similarity

This distinction becomes especially important when text is normalized, transliterated, transformed into alternative Unicode characters or represented using learned embeddings. The representation determines what kind of similarity a comparison system can observe.

Begin With the Target Variable

Before selecting a comparison algorithm, define what similar is intended to mean.

Question Primary comparison problem
Are the strings exactly equal? Exact string equality
Are they only a few typing edits apart? Edit distance
Do they share the same words? Lexical overlap
Do they discuss similar topics? Topical similarity
Do they express similar meaning? Semantic similarity
Does one statement imply the other? Entailment
Do they make the same factual claim? Factual agreement
Do they refer to the same real-world object? Entity resolution
Should both satisfy the same search intent? Retrieval relevance

These targets overlap, but they are not interchangeable.

What String Similarity Measures

String similarity operates on an observable symbolic representation.

For character-level comparison:

X = x₁x₂...xₘ
Y = y₁y₂...yₙ

standard Levenshtein distance permits insertion, deletion and substitution.

D(i,j) =
min(
    D(i-1,j) + 1,
    D(i,j-1) + 1,
    D(i-1,j-1) + [xᵢ ≠ yⱼ]
)

The result has a precise interpretation:

The minimum number of unit insertions, deletions and substitutions required to transform one represented sequence into the other.

This precision is one of Levenshtein distance's major strengths.

String Distance Does Not Contain Meaning

Consider:

car
automobile

These strings are orthographically distant while their meanings can be very close.

Now consider:

legal
illegal

The strings are close, yet the prefix can substantially change the meaning.

At sentence level:

The patient has pneumonia.

The patient does not have pneumonia.

Most of the surface form is identical, while the central proposition is reversed.

Therefore:

small edit distance
does not imply
small semantic change

Large String Distance Does Not Imply Large Semantic Difference

The reverse implication also fails.

physician
doctor

have substantially different spellings while referring to closely related concepts.

Similarly:

The server stopped responding.

The server became unresponsive.

can express nearly the same situation using very different lexical sequences.

large edit distance
does not imply
large semantic difference

There is therefore no universal monotonic conversion between Levenshtein distance and semantic similarity.

Identical Strings Can Still Have Different Meanings

Even a string distance of zero does not establish semantic identity.

Consider the word:

bank

in:

She deposited money at the bank.

They sat on the bank of the river.

The surface token is identical:

ED("bank", "bank") = 0

but context selects different lexical senses.

identical string
≠
identical meaning

Lexical Order Can Carry Meaning

Consider:

A dog chased a cat.

A cat chased a dog.

The sentences contain almost the same words, but the semantic roles are reversed.

A pure bag-of-words representation can lose this distinction completely because both sentences contain the same token multiset.

This illustrates a broader principle:

information discarded by the representation
cannot be recovered by the similarity function

Visual Similarity Is Another Separate Dimension

String similarity and semantic similarity are not the only forms of resemblance. Unicode introduces a third useful dimension: visual presentation.

Consider:

Hello
𝐇𝐞𝐥𝐥𝐨
𝑯𝒆𝒍𝒍𝒐
ℍ𝕖𝕝𝕝𝕠

A reader can recognize the same lexical content in each example, while the underlying Unicode sequences can be different.

This creates at least three distinct questions:

How similar do the strings look?

How similar are their encoded sequences?

How similar is the meaning they communicate?

These questions should not be collapsed into one score.

Styled Unicode Text Is a Useful Counterexample

Presentation-oriented Unicode transformations can replace ordinary characters with alternative Unicode characters.

ABC
↓
𝐀𝐁𝐂

This is different from merely applying a CSS font. The transformed representation can contain different Unicode code points.

At code-point level, Levenshtein distance can therefore report several substitutions even though a human reader recognizes essentially the same letters.

sequence difference:
potentially large

human-recognized lexical content:
closely related

This is not a failure of Levenshtein distance. It is evidence that sequence distance and visual or semantic interpretation are different target variables.

See Styled Unicode Text .

Transformation Changes the Comparison Space

Let T be a transformation applied before string comparison.

dT(x,y)
=
ED(
  T(x),
  T(y)
)

The resulting distance describes the transformed representations, not necessarily the raw inputs.

Examples include canonical normalization, compatibility normalization, case folding, transliteration and presentation-oriented Unicode mappings.

If:

x ≠ y

but

T(x) = T(y)

then:

dT(x,y) = 0

even though the source strings were distinct.

See Unicode Text Transformations .

Unicode Normalization Is Not Semantic Normalization

Unicode normalization establishes standardized relationships between Unicode representations.

It does not resolve synonymy, paraphrase, reference or meaning.

Unicode normalization
→ representation equivalence

semantic representation
→ modeled meaning relationships

Similarly, transliteration changes representation between writing systems but does not itself translate meaning.

transliteration
≠
translation
≠
semantic similarity

See Text Normalization and Transliteration .

What Semantic Similarity Attempts to Measure

Semantic similarity compares represented meaning rather than literal symbol sequences.

The object of comparison can be a word, phrase, sentence, document or concept.

text
  ↓
semantic representation
  ↓
semantic comparison

Unlike classical Levenshtein distance, there is no single universal semantic representation or semantic distance.

Different systems can emphasize synonymy, topical similarity, paraphrase, retrieval relevance, semantic roles or other relations.

Semantic Similarity Is Not Semantic Equivalence

Semantic similarity permits degrees.

Consider:

A:
The company increased revenue by 20%.

B:
The company increased revenue.

The sentences are semantically similar, but they are not fully equivalent because the second omits the magnitude of the increase.

semantic similarity
≠
semantic equivalence

Semantic Similarity Is Not Entailment

Similarity is usually treated as approximately symmetric.

Entailment is directional.

A:
A Labrador is running through the park.

B:
An animal is moving.

A can support B, but B does not establish that the animal is a Labrador or that it is in a park.

similarity(A,B)
≈
similarity(B,A)

but

entails(A,B)
does not imply
entails(B,A)

Semantic Similarity Is Not Contradiction Detection

Two sentences can be semantically close because they concern the same entities and relation while disagreeing about the proposition.

The contract expires tomorrow.

The contract does not expire tomorrow.

Their lexical overlap is high and a generic embedding model can also represent them as close because much of their content is shared.

But they disagree on the central claim.

semantic proximity
≠
propositional agreement

Natural Language Inference models address relations such as entailment, contradiction and neutral separately.

Semantic Similarity Is Not Factual Truth

A semantic model can determine that two statements discuss the same event or claim without knowing whether either statement is true.

semantic similarity
≠
factual verification

semantic similarity
≠
truth

Factual verification requires evidence beyond similarity between representations.

Semantic Similarity Is Not Entity Identity

Two records can contain extremely similar names while referring to different people.

Conversely, the same real-world entity can appear under aliases, transliterations, abbreviations or historical names that are lexically distant.

text similarity
≠
entity identity

Entity resolution requires additional evidence such as addresses, identifiers, dates, relationships or other attributes.

See Entity Resolution and Record Linkage .

Semantic Similarity Versus Semantic Relatedness

Consider:

car
bus

and:

car
gasoline

A car and a bus are conceptually similar because both are vehicles.

A car and gasoline are strongly related, but they are not the same kind of concept.

semantic similarity
≠
general semantic association

Distributional models can blur this boundary because words occurring in related contexts can become geometrically close even when their conceptual relationship is not synonym-like.

Symbolic Lexical Semantics

One approach to semantic comparison uses explicit lexical knowledge structures.

WordNet organizes English lexical items into synonym sets and connects them through semantic relations.

surface word
     ↓
word sense
     ↓
concept / synset
     ↓
semantic graph
     ↓
concept comparison

This representation can capture distinctions that character edit distance cannot.

Its difficult step can be selecting the correct sense from context.

Distributional Semantics

Distributional approaches infer semantic representations from patterns of language use.

A word, sentence or document can be represented as a vector:

v(x) ∈ Rᵈ

and compared geometrically.

A common similarity function is cosine:

cos(u,v)
=
(u · v)
/
(||u|| ||v||)

The vector should not be interpreted as “meaning itself.” It is a learned representation whose geometry depends on data, architecture and training objective.

Static Word Embeddings

Static embedding systems assign one vector to each vocabulary item.

word
↓
fixed vector

Systems such as word2vec and GloVe demonstrated that words with very different spellings can become close in learned vector space when they occur in related linguistic contexts.

doctor
physician

can therefore have low character similarity and high distributional similarity.

A limitation of a single static vector is polysemy:

bank

must represent financial, geographic and other senses simultaneously.

Contextual Representations

Contextual language models produce representations conditioned on surrounding text.

token
+
context
↓
context-dependent representation

Thus:

bank loan

and:

river bank

can receive different contextual representations even though the surface token bank is identical.

BERT is an important example of this contextual representation approach.

Sentence Embeddings

Token representations do not automatically provide an ideal sentence-level similarity space.

Sentence embedding systems instead attempt to encode a complete text into one vector:

sentence
↓
encoder
↓
fixed-dimensional vector

Sentence-BERT, for example, uses transformer-based encoders in a siamese/triplet architecture designed to produce sentence representations suitable for efficient semantic comparison.

Two texts can then be encoded independently:

u = f(sentence A)
v = f(sentence B)

similarity = cosine(u,v)

Bi-Encoders and Cross-Encoders Solve Different Retrieval Problems

A bi-encoder embeds each text independently.

query
↓
vector

document
↓
vector

nearest-neighbor retrieval

Document vectors can be precomputed, making large-scale semantic retrieval practical.

A cross-encoder instead evaluates both texts jointly:

[query ; document]
        ↓
transformer
        ↓
pair score

Joint encoding permits richer pair-specific interactions but requires model evaluation for every candidate pair.

A common architecture therefore uses a fast retriever followed by a more expensive reranker.

Embedding Cosine Is Not a Probability

Suppose:

cos(u,v) = 0.92

This does not mean:

92% probability
that the sentences
mean the same thing

Score distributions are model-specific.

A threshold such as:

0.80

has no universal semantic interpretation across different encoders, datasets or tasks.

The Same Cosine Formula Can Measure Different Representations

Consider:

cosine(TF-IDF vectors)

cosine(word embeddings)

cosine(sentence embeddings)

cosine(domain-specific embeddings)

The mathematical comparator can be identical while the representations contain very different information.

same similarity formula
≠
same similarity semantics

This parallels the same principle in string metrics: representation and comparator must be defined separately.

String Similarity Is More Directly Interpretable

Under ordinary unit-cost Levenshtein distance:

distance = 2

has a direct operational interpretation: two unit edits are necessary and sufficient.

A dense semantic score generally lacks such a simple decomposition.

Method Representation Typical interpretability
Levenshtein Ordered sequence High: explicit edits
Token overlap Sets or multisets High: shared lexical features
TF-IDF Weighted sparse vector Moderate/high
WordNet Lexical concept graph High: explicit relations
Dense embedding Learned vector Lower
Cross-encoder Joint learned representation Task-dependent

Semantic Models Do Not Make Surface Form Irrelevant

Exact lexical information can remain decisive.

Examples include:

CVE-2026-12345

Python 3.14

RX-8715

5 mg

50 mg

A model that smooths all of these into broad semantic neighborhoods can lose information that matters to the application.

Rare identifiers, numbers, dates, product codes and exact names often require lexical or structured comparison in addition to semantic representations.

Semantic Models Do Not Automatically Fix Typos

Typo robustness depends on tokenization, vocabulary, training data and model objective.

A misspelled rare term can break into unusual subword units and produce a degraded semantic representation.

An application can therefore use:

misspelled query
      ↓
edit-distance candidate generation
      ↓
corrected or alternative representation
      ↓
semantic retrieval

But automatic correction can also alter intent, particularly for proper nouns or uncommon identifiers.

A safer system can preserve both the original query and a high-confidence corrected form.

Hybrid Lexical and Semantic Retrieval

Lexical and semantic retrieval solve complementary problems.

query
  │
  ├── lexical branch
  │      exact terms
  │      BM25
  │      n-grams
  │      edit-distance candidates
  │
  └── semantic branch
         dense embeddings
         semantic neighbors

              ↓
        candidate union
              ↓
           reranking

The lexical branch protects rare identifiers and spelling-sensitive information.

The semantic branch can retrieve synonyms, paraphrases and conceptually relevant text that shares little surface form with the query.

Neither representation universally dominates every retrieval task.

Do Not Combine Raw Scores Without Calibration

BM25, normalized edit similarity, cosine similarity and cross-encoder scores occupy different numerical spaces.

0.8 edit similarity

0.8 embedding cosine

0.8 another model score

do not necessarily carry comparable meanings.

A hybrid system can instead use calibrated features, rank fusion or a task-specific learned reranker.

Cross-Lingual Meaning and Transliteration Are Different Problems

Consider:

good morning

buenos días

Their character edit distance is large while their meanings can be close.

Cross-lingual semantic models attempt to represent meaning across languages.

Transliteration instead maps textual representation between writing systems.

transliteration
=
script / form mapping

translation
=
language-to-language meaning transfer

semantic similarity
=
comparison of represented meaning

Unicode Representation Still Matters to Semantic Models

Semantic models do not eliminate lower-level text representation.

Before a model receives text, the application still performs operations such as decoding, normalization and tokenization.

raw Unicode text
      ↓
normalization / preprocessing
      ↓
tokenization
      ↓
semantic model

Malformed or inconsistent preprocessing can therefore affect embeddings just as it affects lexical comparison.

See Unicode and Grapheme-Safe Levenshtein Distance .

Unicode Transformation Makes the Representation Boundary Explicit

Unicode text transformations provide a useful bridge between surface form and higher-level interpretation.

source text
      ↓
Unicode transformation
      ↓
new sequence representation

The transformed string can differ substantially at code-point level while still being interpreted by a reader as closely related text.

For example:

Levenshtein

𝑳𝒆𝒗𝒆𝒏𝒔𝒉𝒕𝒆𝒊𝒏

A code-point-level edit metric sees different sequences.

A human can recognize the same lexical word.

A semantic system can also preserve related meaning despite the surface transformation, depending on its tokenizer and representation.

These are three different analyses of the same pair.

sequence relationship
       ↓
Levenshtein / string metric

visual relationship
       ↓
rendering / glyph analysis

meaning relationship
       ↓
semantic model

See Unicode Text Transformations .

Levenshtein Can Measure the Transformation Without Judging Its Meaning

Let T(x) be a Unicode transformation.

The sequence-level transformation distance can be written as:

dtransform(x)
=
ED(
  S(x),
  S(T(x))
)

where S defines the comparison sequence.

This value answers:

How much did the represented sequence change under this transformation?

It does not answer:

Did the meaning change?

Does the output look attractive?

Does it look similar?

Is it easier to read?

Does it refer to the same entity?

Those require different models or application evidence.

Styled Unicode Demonstrates Four Independent Layers

A useful conceptual model is:

1. SOURCE REPRESENTATION

Hello


2. TRANSFORMED REPRESENTATION

𝐇𝐞𝐥𝐥𝐨


3. VISUAL INTERPRETATION

recognizable styled form of "Hello"


4. SEMANTIC INTERPRETATION

same intended lexical content in ordinary use

These layers are related but not identical.

A sequence metric should report sequence difference. A rendering system determines glyph appearance. A semantic system attempts to model meaning.

See Styled Unicode Text .

Semantic Similarity Still Does Not Guarantee Lexical Equivalence

Even when two texts receive high semantic similarity, exact lexical differences may remain operationally important.

dose = 5 mg

dose = 50 mg

A system should not discard the number mismatch merely because most of the sentence is semantically related.

A useful architecture can therefore preserve separate features:

{
  edit_similarity,
  semantic_similarity,
  number_match,
  entity_match,
  date_match
}

The application can then decide which differences dominate the final decision.

A Multi-Representation Comparison Architecture

                    TEXT
                      │
          ┌───────────┼───────────┐
          │           │           │
          ↓           ↓           ↓
       lexical      semantic    structured
    representation  embedding    features
          │           │           │
          ↓           ↓           ↓
    edit / overlap   cosine /    numbers
       scores        model score  dates
                                 entities
          │           │           │
          └───────────┼───────────┘
                      ↓
                 task-specific
                    decision

This architecture avoids forcing spelling, meaning, factual details and identity into one scalar representation.

String Similarity and Semantic Similarity Form Different Geometries

Levenshtein distance creates a neighborhood based on edit operations.

small edit neighborhood
=
strings reachable by few edits

Semantic representations create neighborhoods based on the relationships learned or encoded by the semantic model.

semantic neighborhood
=
items close under the model's learned representation

These neighborhoods can intersect, but neither is a monotonic transformation of the other.

small Levenshtein distance
↛
high semantic similarity

high semantic similarity
↛
small Levenshtein distance

Target Useful starting model
Typing errors Levenshtein or Damerau-style edit distance

Common Category Errors

Assumption Why it fails
Small edit distance means similar meaning A small lexical change can reverse meaning.
Large edit distance means different meaning Synonyms and paraphrases can be lexically distant.
Identical strings mean identical concepts Polysemy depends on context.
High embedding cosine means paraphrase The meaning of the score depends on model training.
High semantic similarity means entailment Entailment is directional.
Semantic similarity means factual agreement Similar texts can contradict each other.
Semantic similarity means same entity Identity requires external or multi-field evidence.
Unicode normalization solves semantic variation It changes representation, not meaning.
Semantic models solve Unicode confusables Visual identifier security is a separate problem.
Styled Unicode is only a font change The underlying Unicode sequence can change.

Relationship to Unicode Text Transformations

Unicode text transformations make the distinction between representation and meaning especially concrete.

A transformation can alter the underlying sequence:

ordinary text
      ↓
Unicode transformation
      ↓
different Unicode sequence

while preserving recognizable lexical content for a human reader.

This means a single pair of strings can simultaneously have:

non-zero edit distance

high visual resemblance

closely related intended lexical content

There is no contradiction. Each statement refers to a different representation or target variable.

Summary

String similarity and semantic similarity are not competing implementations of one concept. They compare different representations and answer different questions.

Levenshtein distance provides an explicit measure of surface sequence transformation through insertion, deletion and substitution. Its strength is precisely that its interpretation is narrow and well defined.

Semantic methods deliberately move beyond literal character sequences. Symbolic lexical resources, distributional vectors, contextual language models and sentence embeddings can identify semantic relationships that edit distance cannot observe.

But semantic similarity should not be interpreted automatically as equivalence, entailment, factual agreement, identity or truth.

Unicode transformations reinforce the same lesson. A string can change substantially as a sequence while remaining visually recognizable and preserving its intended lexical content.

Similarity is meaningful only relative to a representation and a task.
