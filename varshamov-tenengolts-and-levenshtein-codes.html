Varshamov-Tenengolts and Levenshtein Codes

Varshamov-Tenengolts codes are among the most elegant constructions in synchronization-error coding theory. A binary VT code adds only logarithmic redundancy yet can correct an arbitrary single deletion or an arbitrary single insertion, despite the fact that the receiver is not told where synchronization was lost.

The construction is historically unusual. R. R. Varshamov and G. M. Tenengolts introduced the defining modular classes in 1965 for a single asymmetric-error channel. Vladimir Levenshtein then recognized that the same construction solves the single-deletion problem and, through the insertion/deletion relationship, also corrects a single insertion. This connection made VT codes foundational objects in the theory described in insertion-deletion codes and synchronization errors.

The core construction is remarkably compact:

choose binary words x = x1...xn

such that

1*x1
+ 2*x2
+ 3*x3
+ ...
+ n*xn

≡ a
(mod n+1).

That weighted modular checksum is sufficient to recover both:

which bit value disappeared

and enough positional information to restore the transmitted codeword.

This article develops the construction from first principles, proves the decoding mechanism, examines code cardinality and asymptotic redundancy, distinguishes perfect deletion codes from ordinary sphere packing, discusses q-ary extensions and insertion decoding, and places VT codes within the broader work of Vladimir Levenshtein.

One terminology point must be fixed at the outset:

"VT code"
has a precise classical construction.

"Levenshtein code"
is not one universally standardized
single modern code family.

The literature sometimes uses phrases such as VT-Levenshtein code or Varshamov-Tenengolts-Levenshtein code for the classical deletion-correcting construction and closely related synchronization codes. In this article, the distinction is preserved: the modular construction is attributed to Varshamov and Tenengolts, while Levenshtein's role is its deletion/insertion interpretation, decoding theory, asymptotic analysis, and subsequent development of deletion/insertion coding.

1. The single-deletion problem

Let:

x =
x1 x2 ... xn

where
xi ∈ {0,1}.

A single-deletion channel removes one unknown symbol:

x1 ... x(p-1) xp x(p+1) ... xn

                  |
                  v

x1 ... x(p-1) x(p+1) ... xn.

The receiver observes only a length-n-1 sequence.

It knows:

one symbol disappeared,

but not:

its value
or
its original position.

2. Why one deletion is harder than one erasure

An erasure might produce:

1 0 ? 1 0 1

so the missing coordinate is known.

A deletion produces:

1 0 1 0 1.

The receiver does not know whether the missing symbol occurred at position:

1
2
3
...
n.

Thus:

deletion
=
missing symbol
+
missing coordinate.

3. Why ordinary parity is insufficient

Suppose a binary code stores ordinary parity:

x1 + x2 + ... + xn
mod 2.

After one deletion, parity may reveal whether the deleted bit was:

0
or
1.

But ordinary parity gives almost no information about:

where that bit belonged.

Synchronization requires positional redundancy.

4. The VT idea: weight every bit by its coordinate

For a binary word:

x =
(x1,x2,...,xn),

define the weighted checksum:

S(x)
=
Σ(i * xi)
for i = 1...n.

Instead of reducing modulo 2, VT codes reduce modulo:

n+1.

The coordinate weights encode synchronization information.

5. Definition of a binary VT code

For:

a ∈ {0,1,...,n},

define:

VT_a(n)
=
{
x ∈ {0,1}^n :

Σ(i xi)
≡ a
(mod n+1)
}.

These are the Varshamov-Tenengolts congruence classes.

The construction was introduced by Varshamov and Tenengolts in Codes Which Correct Single Asymmetric Errors, published in 1965. A bibliographic discussion is available in N. J. A. Sloane's On Single-Deletion-Correcting Codes.

6. The VT classes partition binary space

Every binary word has exactly one residue:

Σ(i xi)
mod (n+1).

Therefore:

{0,1}^n
=
VT_0(n)
∪
VT_1(n)
∪
...
∪
VT_n(n),

and the classes are pairwise disjoint.

7. Average class size

There are:

2^n

binary length-n words and:

n+1

syndrome classes.

Hence the average class size is:

2^n
/
(n+1).

At least one VT class therefore contains at least this many codewords.

8. VT0 is the largest class

A stronger result is known:

|VT_0(n)|
>=
|VT_a(n)|

for every valid syndrome a.

Thus the zero-syndrome class is especially important when maximum codebook size is desired.

9. First examples

The first few zero-syndrome VT codes are:

VT_0(1)
=
{0}

VT_0(2)
=
{00, 11}

VT_0(3)
=
{000, 101}

VT_0(4)
=
{
0000,
1001,
0110,
1111
}.

10. Verifying VT0(4)

Take:

x = 1001.

Then:

S(x)
=
1*1
+
2*0
+
3*0
+
4*1

=
5.

Since:

5 ≡ 0
(mod 5),

the word belongs to:

VT_0(4).

11. Another member

For:

x = 0110,

we obtain:

S(x)
=
1*0
+
2*1
+
3*1
+
4*0

=
5

≡ 0
(mod 5).

12. A nonmember

Consider:

x = 0101.

Then:

S(x)
=
2 + 4
=
6

≡ 1
(mod 5).

Therefore:

0101 ∈ VT_1(4),

not:

VT_0(4).

13. Historical origin: asymmetric errors

The original Varshamov-Tenengolts construction was not introduced as a deletion code. It arose for an asymmetric binary channel.

For a one-direction bit error such as:

1 -> 0,

the weighted syndrome directly identifies the affected coordinate.

If:

x_j = 1

changes to zero, the checksum decreases by exactly:

j.

Hence:

syndrome difference
=
error position.

14. Levenshtein's key observation

Levenshtein observed that the same congruence structure corrects a single deletion.

This was not obvious because deletion corruption is more complicated:

the deleted symbol contributes
its own weighted value

AND

all later symbols
change coordinate weight.

The remarkable fact is that these two effects combine into a quantity from which the deleted bit can be reconstructed.

Levenshtein's foundational paper is discussed separately at Levenshtein's 1966 coding paper.

15. Set up the deletion decoder

Suppose:

x ∈ VT_a(n)

is transmitted.

Bit:

s = x_p

at position p is deleted.

The receiver sees:

y =
y1 y2 ... y(n-1).

16. Split the original word around the deleted position

Let:

L0
=
number of zeros left of position p

L1
=
number of ones left of position p

R0
=
number of zeros right of position p

R1
=
number of ones right of position p.

Then:

p
=
1 + L0 + L1.

17. Weight of the received word

Define:

w
=
number of ones in y.

If the deleted symbol was zero:

w = L1 + R1.

If the deleted symbol was one:

w = L1 + R1

as well, because that one no longer appears in the received sequence.

18. Received weighted checksum

Compute:

S(y)
=
Σ(i yi)
for i = 1...n-1.

Because symbols originally to the right of the deletion move left by one coordinate, every surviving 1 to the right loses one unit of checksum weight.

19. Define the checksum deficiency

Because:

S(x)
≡ a
(mod n+1),

define:

D
=
(a - S(y))
mod (n+1).

For a single deletion, the relevant deficiency falls in:

0,...,n.

20. Case 1: deleted symbol is zero

If:

s = 0,

the deleted symbol itself contributes nothing to:

S(x).

The only checksum change comes from ones to its right shifting left.

Each such one loses one unit.

Therefore:

D
=
R1.

21. Bound for a deleted zero

Since:

R1
<=
L1 + R1
=
w,

we obtain:

deleted bit = 0
=>
D <= w.

22. Case 2: deleted symbol is one

If:

s = 1,

the deleted symbol contributes:

p

to the original checksum.

Additionally, all R1 ones to its right lose one coordinate.

Thus:

D
=
p + R1.

23. Rewrite the deleted-one deficiency

Using:

p
=
1 + L0 + L1

and:

w
=
L1 + R1,

we obtain:

D
=
1
+
L0
+
L1
+
R1

=
1 + L0 + w.

Hence:

D > w.

24. The decisive decoder test

The deleted bit value follows immediately:

if D <= w:
    deleted bit = 0

if D > w:
    deleted bit = 1.

This is the heart of Levenshtein's elegant VT deletion decoder.

25. Recovering the position of a deleted zero

If:

D <= w,

then:

D = R1.

So the deleted zero belongs at a location with exactly:

D

ones to its right.

Equivalently, insert a zero immediately before the rightmost D ones, with the expected ambiguity inside a zero run producing the same reconstructed codeword.

26. Recovering the position of a deleted one

If:

D > w,

then:

D
=
1 + L0 + w.

Therefore:

L0
=
D - w - 1.

The decoder inserts a one after exactly:

D - w - 1

zeros from the left.

27. Complete binary VT deletion decoder

input:
    y of length n-1
    target syndrome a
    original length n

w =
    number_of_ones(y)

checksum =
    Σ i*y[i]

D =
    (a - checksum)
    mod (n+1)

if D <= w:

    deleted_bit = 0

    insert 0
    so that D ones
    remain to its right

else:

    deleted_bit = 1

    L0 =
        D - w - 1

    insert 1
    after exactly L0 zeros

return reconstructed codeword

28. Worked deletion example

Use:

x =
0110

x ∈ VT_0(4).

Delete the second symbol:

0 [1] 1 0

so the receiver obtains:

y =
010.

29. Compute the received weight

w
=
1.

30. Compute the received checksum

S(y)
=
1*0
+
2*1
+
3*0

=
2.

31. Compute the deficiency

D
=
(0 - 2)
mod 5

=
3.

Since:

3 > 1,

the missing bit is:

1.

32. Recover the number of zeros to the left

L0
=
D - w - 1

=
3 - 1 - 1

=
1.

Insert a one after one zero:

0 [1] 1 0

recovering:

0110.

33. A deleted-zero example

Consider:

x =
1001

∈ VT_0(4).

Delete the zero at position 2:

1 [0] 0 1

giving:

y =
101.

34. Compute the new weight

w = 2.

35. Compute the new checksum

S(y)
=
1*1
+
2*0
+
3*1

=
4.

36. Compute deficiency

D
=
(0 - 4)
mod 5

=
1.

Since:

D <= w,

the deleted bit is zero.

The value:

D = 1

means the missing zero had exactly one surviving one to its right.

Restoring it yields:

1001.

37. Why repeated symbols do not break the decoder

Suppose several possible positions inside a run appear equivalent:

00000.

Deleting any one of those zeros produces:

0000.

The physical deletion coordinate cannot be identified.

But all equivalent insertion positions reconstruct the same binary word:

00000.

Therefore:

physical error localization
is unnecessary
for codeword recovery.

38. Message recovery is the coding objective

This distinction is central:

decoder must recover
the transmitted codeword

decoder need not recover
the exact physical event history.

Multiple edit paths can correspond to one codeword without creating message ambiguity.

39. Proof that a VT class corrects one deletion

The decoder above reconstructs one word in the correct syndrome class from every one-deletion descendant.

Equivalently, for any distinct:

x,z ∈ VT_a(n),

their one-deletion descendant sets satisfy:

D_1(x)
∩
D_1(z)
=
∅.

Therefore:

VT_a(n)

is a single-deletion-correcting code.

40. Connection with LCS

Two length-n words are confusable after one deletion if they share a common subsequence of length:

n-1.

Therefore a single-deletion-correcting code must ensure:

LCS(x,z)
<=
n-2

for distinct codewords.

41. Pure insertion-deletion distance

For equal-length words:

dID(x,z)
=
2(
n - LCS(x,z)
).

Thus single-deletion correction requires:

dID(x,z)
>=
4.

This pure insdel distance is not numerically identical to classic cost-one-substitution Levenshtein distance.

42. Sloane's normalized deletion distance convention

Sloane's survey defines a deletion distance:

dd(x,z)
=
1/2
*
minimum number
of deletions + insertions
needed to transform x into z

for equal-length binary vectors.

Under that convention:

single-deletion correction
requires
dd(x,z) >= 2.

This is the same geometry expressed with a factor-of-two normalization.

43. Why terminology can cause confusion

Depending on the source, the phrase:

Levenshtein distance

can mean:

  • insert/delete/substitute distance with substitution cost one;
  • insertion/deletion distance only;
  • a normalized deletion metric used in coding theory.

A rigorous coding article should define the primitive operations and costs explicitly.

44. Single insertion correction

The same VT code also corrects one insertion.

An insertion transforms:

x ∈ {0,1}^n

into:

y ∈ {0,1}^{n+1}.

The receiver knows from the length that one extra symbol is present.

45. Conceptual insertion decoder

A simple correctness-oriented decoder is:

for every position j
in received y:

    remove y[j]

    candidate = resulting length-n word

    if candidate belongs to VT_a(n):
        record candidate

deduplicate candidates

return the unique valid codeword

Because a VT class is single-insertion correcting, the original codeword is uniquely determined.

46. Naïve insertion decoding complexity

If every deletion candidate recomputes the syndrome from scratch:

n+1 candidates
*
O(n) checksum
=
O(n²).

But prefix/suffix checksum updates or direct algebraic decoders can reduce this to linear time.

47. Insertion and deletion correction are related structurally

If two distinct codewords could both become the same sequence after one insertion, then they would be subsequences of a common supersequence.

This is tightly connected to sharing one-deletion descendants.

Levenshtein's original work formalized the deep relation between insertion and deletion correction.

48. Why VT coding is remarkable

The code corrects synchronization loss using only:

one modular weighted checksum.

There is no need to attach a full explicit index to every bit.

The code uses global arithmetic structure to recover local positional information.

49. Code cardinality

Because the classes partition binary space:

Σ_{a=0}^{n}
|VT_a(n)|

=
2^n.

The classes need not have equal sizes.

50. Small cardinality table

51. Exact general cardinality formula

Sloane gives the following exact formula:

|VT_a(n)|
=
1
----------------
2(n+1)

*
Σ
over odd d dividing n+1

[
 φ(d)
 *
 μ(
   d / gcd(d,a)
 )
 /
 φ(
   d / gcd(d,a)
 )
 *
 2^((n+1)/d)
].

Here:

  • φ is Euler's totient function;
  • μ is the Möbius function;
  • gcd is greatest common divisor.

52. Exact size of VT0(n)

For:

a = 0,

we have:

gcd(d,0) = d.

Therefore:

|VT_0(n)|
=
1
----------------
2(n+1)

*
Σ
over odd d | (n+1)

φ(d)
*
2^((n+1)/d).

53. Why number theory appears

The syndrome classes are defined by:

Σ i xi
mod (n+1).

Counting how many subsets of:

{1,2,...,n}

have a given sum modulo n+1 is a finite Fourier-analysis problem.

This brings in:

  • roots of unity;
  • discrete Fourier inversion;
  • Euler's totient function;
  • Möbius inversion;
  • Ramanujan sums.

54. Generating-function viewpoint

Associate each binary word with its selected coordinate set:

A
=
{
i :
xi = 1
}.

Then:

S(x)
=
Σ_{i in A} i.

The polynomial:

F(z)
=
Π_{i=1}^{n}
(
1 + z^i
)

encodes all subsets and their weighted sums.

55. Reduction modulo zn+1-1

Because only the sum modulo:

n+1

matters, exponents can be reduced modulo n+1.

The coefficient associated with residue a counts:

|VT_a(n)|.

56. Roots-of-unity filter

Let:

ζ
=
exp(
  2πi/(n+1)
).

The coefficient for syndrome a can be extracted using a discrete Fourier transform:

|VT_a(n)|

=
1/(n+1)
*

These are Ramanujan sums.

58. Lower bound on the largest VT code

Because:

VT_0(n)

is the largest syndrome class:

|VT_0(n)|
>=
2^n/(n+1).

59. Redundancy bound

Define binary redundancy:

=
n
-
log2 |VT_0(n)|.

Then:

r
<=
log2(n+1).

Thus a single arbitrary deletion can be corrected with only logarithmic redundancy.

60. Asymptotic rate

The code rate is:

R_n
=
log2 |VT_0(n)|
/
n.

Using the lower bound:

R_n
>=
1
-

Therefore:

=

61. Rate approaching one does not mean zero redundancy

The number of check bits still grows:

approximately log2 n.

But relative overhead:

log2 n / n

vanishes.

62. Why logarithmic redundancy is close to unavoidable

A deletion creates uncertainty over roughly:

n

possible positions.

Identifying one among n possibilities requires on the scale of:

log2 n

bits.

This is only an intuition, but it correctly predicts the redundancy scale.

63. Levenshtein's asymptotic upper bound

Let:

A(n,1)

be the largest possible size of a binary length-n single-deletion-correcting code.

Levenshtein proved:

A(n,1)
~
2^n/n

as:

n -> infinity.

64. VT codes meet the asymptotic scale

Since:

|VT_0(n)|
>=
2^n/(n+1),

and:

A(n,1)
~
2^n/n,

the largest VT class is asymptotically optimal in cardinality.

65. Asymptotically optimal does not mean proven finite-length optimal for every n

This distinction is important.

Asymptotic optimality means:

|VT_0(n)|
/
A(n,1)

->
1

in the relevant asymptotic sense.

It does not prove:

|VT_0(n)|
=
A(n,1)

for every finite n.

66. The finite-length optimality problem

The natural conjecture is:

VT_0(n)
is a largest possible
binary single-deletion code
for every n.

This remains a difficult combinatorial optimization question.

67. What is known computationally

Later computational and optimization work established VT optimality for:

n <= 10.

Albert No's 2019 study states that the VT construction is known to be optimal through block length 10 and derives stronger upper bounds for larger lengths. See Nonasymptotic Upper Bounds on Binary Single Deletion Codes via Mixed Integer Linear Programming.

68. The n = 11 gap

The same study obtains:

A(11,1)
<=
173.

The VT zero class has:

|VT_0(11)|
=
172.

Therefore:

A(11,1)
∈
{172,173}

under those bounds.

This illustrates how difficult exact optimality becomes even for modest block length.

69. Why deletion-code upper bounds are difficult

Ordinary Hamming balls have constant size for a fixed radius.

Deletion balls do not.

For one deletion:

|D_1(x)|
=
number of runs in x.

70. Run example

For:

x =
00001111,

there are two runs:

0000
1111.

Therefore:

|D_1(x)| = 2.

71. Alternating example

For:

x =
01010101,

there are eight runs.

Therefore:

|D_1(x)| = 8.

72. Consequence for sphere packing

Two codewords of equal length can consume very different amounts of descendant space.

Thus the simple Hamming argument:

number of codewords
*
constant ball size
<=
ambient space size

does not apply directly.

73. Graph formulation

Construct a graph:

G_n.

Its vertices are all binary words of length n.

Connect:

x
and
y

whenever they share a one-deletion descendant.

A single-deletion-correcting code is exactly an:

independent set

in this graph.

74. Optimal code search becomes maximum independent set

The exact finite-length problem is therefore:

find
maximum independent set
of G_n.

The number of vertices is:

2^n.

This becomes computationally difficult rapidly.

75. Hypergraph formulation

One can also define each received word of length:

n-1

as a hyperedge connecting every transmitted length-n word that could produce it.

The code must choose transmitted words so that no received descendant is assigned to more than one codeword.

This leads naturally to integer-programming and LP-relaxation bounds.

76. Perfect deletion codes

In Hamming coding theory, a perfect code partitions the ambient received space into equal-radius decoding balls.

Deletion geometry is stranger because ball sizes differ.

Levenshtein defined deletion-perfect codes using descendant sets.

77. Perfect single-deletion condition

A single-deletion-correcting code C is perfect if:

{
D_1(c) :
c ∈ C
}

forms a partition of:

{0,1}^{n-1}.

Thus every possible received length-n-1 word has exactly one parent codeword in C.

78. Every VT syndrome class is perfect

Levenshtein later proved that all binary VT classes:

VT_0(n),
VT_1(n),
...
VT_n(n)

are perfect single-deletion-correcting codes under this definition.

See On perfect codes in deletion and insertion metric.

79. Perfect classes can have different cardinalities

This initially appears paradoxical.

If each perfect code partitions the same received space, why can:

|VT_a(n)|

differ?

The answer is:

deletion balls have different sizes.

A code with fewer codewords can still cover the complete descendant space if its codewords have larger deletion balls on average.

80. Perfect does not imply maximum cardinality

Another important distinction:

perfect code
!=
largest possible code.

Perfectness concerns exact coverage of the received space.

Maximum cardinality concerns:

how many codewords
can coexist without ambiguity.

Because ball sizes vary, these objectives are not equivalent.

81. VT codes are generally nonlinear

The condition:

Σ i xi
≡ a
(mod n+1)

is not generally a linear parity-check equation over:

GF(2).

For sufficiently large n, the zero-syndrome VT code is not a binary linear subspace.

82. Why modulo n+1 is not GF(2)

A conventional binary linear code uses equations like:

Hx^T = 0

over:

GF(2).

VT arithmetic instead uses an integer congruence modulo:

n+1,

while the variables:

xi

remain binary.

This hybrid arithmetic does not generally preserve vector-space closure under XOR.

83. Small VT codes may accidentally be linear

For small values of n, some VT classes can happen to form linear sets.

That special behavior should not be generalized to the family.

84. Nonlinearity is not a weakness

Error-correcting codes do not have to be linear.

Linearity is valuable because it simplifies:

  • encoding;
  • syndrome decoding;
  • analysis.

But nonlinear codes can achieve excellent packing properties unavailable to linear codes under certain channel geometries.

85. Systematic VT encoding

A systematic encoder attempts to preserve message bits directly and choose selected check positions so the VT congruence is satisfied.

A naïve strategy is:

reserve check positions

place message bits elsewhere

compute current weighted sum

choose check bits
whose weighted coordinates
repair the syndrome modulo n+1.

86. Why powers of two are useful check positions

If positions:

1,2,4,8,...

are reserved, combinations of their weights can represent many required checksum corrections.

This yields efficient systematic encoders for suitably chosen block lengths and constructions.

87. Encoding problem versus code definition

The mathematical set:

VT_a(n)

does not itself specify:

how arbitrary k-bit messages
are bijectively mapped
to selected codewords.

A practical coding system must additionally define an encoder.

88. Fixed syndrome versus message-dependent syndrome

Classical code use typically fixes:

a.

All transmitted codewords belong to one syndrome class.

Allowing the syndrome itself to vary freely would destroy the error-correction guarantee unless additional information tells the decoder which class was intended.

89. Syndrome metadata is equivalent to redundancy elsewhere

If every codeword is allowed but the sender separately transmits:

a =
S(x) mod (n+1),

then the side channel carries about:

log2(n+1)

bits.

This is another way to see the logarithmic redundancy scale.

90. q-ary synchronization

For a q-ary alphabet:

Σ_q =
{0,1,...,q-1},

a deletion removes both:

a coordinate

and:

one of q possible symbol values.

The binary VT checksum is therefore not sufficient by itself in an obvious direct form.

91. Tenengolts' nonbinary code

G. Tenengolts gave a q-ary single-deletion/insertion construction in 1984.

See Nonbinary codes, correcting single deletion or insertion.

92. Relative-order signature

A central idea in the nonbinary construction is to transform:

x1 x2 ... xn

into a binary signature describing comparisons between neighboring symbols.

One common convention uses something like:

α_i =
1 if x_{i+1} >= x_i
0 otherwise,

with precise conventions determined by the construction.

A q-ary deletion induces controlled changes in this signature.

93. Separate position information from symbol-value information

The nonbinary decoder effectively needs two pieces of information:

where synchronization was lost

and:

what q-ary symbol disappeared.

This motivates combining:

  • a VT-type constraint on a binary auxiliary sequence;
  • a modular sum constraint on q-ary symbol values.

94. Why q-ary coding is important

Many real channels are not binary.

Most notably, synthetic DNA uses:

{A,C,G,T},

so:

q = 4.

The role of synchronization coding in that setting is developed in edit distance in DNA storage.

95. Do not encode q-ary deletion as independent bit deletions

Suppose one q-ary symbol is represented by two bits.

Deleting the entire q-ary symbol is not equivalent to deleting one unknown bit from a binary sequence.

The physical channel operates on symbol boundaries:

one q-ary coordinate disappears.

The code should model that event directly whenever possible.

The deletion interpretation of VT codes was only one part of Levenshtein's contribution.

His work studied:

  • deletion-correcting codes;
  • insertion correction;
  • binary symbol reversals;
  • asymptotic code size;
  • perfect deletion/insertion codes;
  • sequence reconstruction.

98. “Reversal” in the historical title

In this context, reversal refers to reversing a binary symbol:

0 -> 1
or
1 -> 0,

rather than reversing an arbitrary substring.

It is therefore closer to what modern terminology calls:

substitution / bit flip.

99. VT codes and classic Levenshtein distance are related but not identical objects

The familiar string metric allows:

insert
delete
substitute

each at unit cost.

VT codes are specialized for:

one insertion
or
one deletion

in their classical form.

Thus:

VT coding theory
is part of Levenshtein's synchronization work

but

VT code
is not simply
"minimum distance >= 3
under ordinary software Levenshtein distance."

100. One substitution is a different channel event

A substitution preserves word length.

A deletion does not.

Therefore the receiver can detect deletion occurrence from length if the original block length is known:

received length n-1
=>
one deletion
under the assumed channel.

A substitution leaves length equal to n and requires different diagnosis.

101. Mixed substitution/deletion codes

A system needing to correct:

one deletion
or
one substitution

may add another constraint or use a modified VT-like construction.

The precise redundancy and decoder depend on which combinations of errors must be corrected simultaneously.

102. Why channel specification matters

These are different guarantees:

correct one deletion

correct one insertion

correct one substitution

correct either insertion or deletion

correct one arbitrary
insert/delete/substitute edit.

A code should only be claimed to correct the error family actually proven.

103. Multiple deletions

The classical VT checksum is optimized for one synchronization error.

If two bits disappear, the checksum deficiency combines:

  • two unknown bit values;
  • two unknown coordinates;
  • coordinate shifts caused by both deletions.

One modular moment no longer generally determines the transmitted word.

104. Why “apply the VT decoder twice” does not solve two arbitrary deletions

After two deletions, the first decoder does not know which intermediate length-n-1 sequence ever existed.

Many possible first insertions can lead to candidate intermediate words.

Thus two-deletion decoding cannot be reduced naively to two independent one-deletion problems.

105. Higher-order checksum ideas

Generalized deletion codes often use additional invariants such as:

Σ i xi

Σ i² xi

Σ i³ xi

...

or checksums of derived sequences.

The objective is to obtain enough independent constraints to resolve multiple synchronization events.

106. Modern fixed-k deletion codes

Modern work has developed codes with:

O(k log n)

redundancy for constant numbers of deletions, matching the correct asymptotic order implied by Levenshtein's bounds.

For example, Sima and Bruck developed explicit constant-k deletion-correcting constructions with logarithmic redundancy. See On Optimal k-Deletion Correcting Codes.

107. VT is the k = 1 benchmark

Any general multiple-deletion construction should be compared against the extraordinary efficiency of the single-deletion case:

k = 1

redundancy
≈
log n

simple checksum

linear-time decoding.

Few synchronization problems admit such a clean exact solution.

108. VT list decoding

If more than one deletion occurs, a classical VT code may no longer uniquely identify the original codeword.

But one can ask:

how many VT codewords
are compatible with
the received sequence?

This leads to list decoding.

109. Unique decoding versus list decoding

UNIQUE DECODER:

received
->
one codeword

LIST DECODER:

received
->
{
candidate 1,
candidate 2,

candidate L
}.

List decoding can remain useful beyond the single-error guarantee.

110. VT list size can grow quickly

For several deletions, the number of compatible VT codewords can grow substantially.

Thus:

single-deletion perfection

does not mean:

excellent bounded-list behavior
for arbitrarily many deletions.

111. External integrity checks can resolve lists

If a list decoder produces several candidates, another layer can choose among them using:

  • a cryptographic hash;
  • an outer ECC;
  • metadata;
  • application constraints.

This is particularly relevant in storage systems.

112. Code concatenation

VT codes can be used as inner synchronization codes:

113. Why inner/outer separation is useful

VT decoding converts:

unknown-position synchronization error

into:

correctly framed symbol block

or a detectable block failure.

An outer code can then correct residual block errors or erasures using conventional coding theory.

114. DNA storage is a modern example

A DNA oligonucleotide can suffer:

insertion
deletion
substitution.

An inner synchronization code can correct local indels, while an outer code handles:

whole-strand dropout.

This reproduces the layered architecture discussed in DNA storage.

115. VT syndrome as positional hashing

There is a useful algorithmic interpretation:

VT checksum
=
compact position-sensitive hash
of the set of 1-coordinates.

It is not a general-purpose collision-resistant hash.

Its structure is specifically chosen so that one deletion produces a decodable arithmetic pattern.

116. Why modulo n+1 is natural

The checksum loss caused by one deletion lies in a range bounded by approximately:

0...n.

Modulo:

n+1

therefore preserves enough information to represent every possible deficiency without unwanted wrap ambiguity in the one-deletion derivation.

117. Why modulo n would be problematic

If the modulus were too small, distinct positional deficiencies could collapse:

D1
≡
D2
(mod m).

The receiver could lose the very positional information needed to determine the deleted bit and location.

118. Why much larger modulus is unnecessary

A larger modulus could preserve the information but would create more syndrome classes and potentially increase redundancy.

The choice:

n+1

matches the one-deletion positional range elegantly.

119. VT syndrome is global

Changing one bit can affect the total checksum regardless of where the change occurs.

This contrasts with marker-based synchronization schemes where redundancy is localized in explicit separator regions.

120. Advantage over periodic markers

A periodic marker can itself be deleted.

VT synchronization information is distributed across the entire codeword through the weighted sum.

No single explicit synchronization delimiter is required.

121. Limitation: block structure is still assumed

The decoder must know:

  • the original block length n;
  • the intended syndrome class a;
  • that the channel introduced at most the supported error pattern.

VT codes do not by themselves discover arbitrary framing in an unlimited continuous stream.

122. Stream synchronization requires additional architecture

For a long communication stream, one may combine VT blocks with:

  • block boundaries;
  • markers;
  • outer sequence numbers;
  • synchronization strings.

125. VT versus ordinary parity

ordinary parity:
Σ xi
mod 2

VT:
Σ i xi
mod (n+1).

Ordinary parity knows symbol count parity.

VT syndrome additionally encodes position.

126. VT versus full Levenshtein nearest-neighbor decoding

A brute-force edit-distance decoder would:

for every codeword c:

    compute edit distance(c, received)

choose nearest.

For a high-rate code:

|C|
≈
2^n/n,

so exhaustive codebook search is exponentially expensive.

VT arithmetic avoids this completely.

127. Encoding structure beats generic search

This is a general lesson of coding theory:

do not merely create
well-separated strings.

create well-separated strings
with algebraic/combinatorial structure
that reveals how to decode them.

128. Decoder complexity

The binary single-deletion decoder needs:

  • one pass to count ones;
  • one weighted checksum;
  • one pass or indexed insertion to restore the bit.

Therefore the classical decoding problem can be solved in:

O(n)

time.

129. Memory complexity

The decoder does not require an:

n × n

dynamic-programming matrix.

It can operate with:

O(1)

auxiliary arithmetic state plus the output buffer, depending on implementation.

130. Contrast with generic edit distance

Standard pairwise dynamic programming between two length-n strings uses:

O(n²)

time in the straightforward algorithm.

VT decoding is faster because the transmitted string is constrained to a specially designed code.

131. Coding redundancy can buy algorithmic speed

The encoder restricts transmitted data to a structured subset:

{0,1}^n
->
VT_a(n).

This structure makes the inverse problem much easier.

Thus redundancy buys:

error correction
+
decoding efficiency.

132. Error detection from received length

Under a channel known to allow:

zero or one deletion,

the length itself indicates whether a deletion occurred:

length = n
->
no deletion

length = n-1
->
one deletion.

This is another difference from substitution channels, where error occurrence cannot be detected from length alone.

133. Insertions similarly reveal themselves by length

length = n+1
->
one insertion

under the corresponding restricted model.

The decoder then knows which synchronization-error type occurred before solving its location.

134. Mixed insertion/deletion count is harder

If both one insertion and one deletion can occur simultaneously, the final length can again equal:

n.

Length alone no longer diagnoses the channel history.

More redundancy and a richer decoder are needed.

135. Why observed length does not reveal physical history in general

A final length of:

n

can result from:

  • no error;
  • one insertion + one deletion;
  • several cancelling synchronization events.

Distance concerns endpoint difference, not complete channel history.

136. Common failure mode: saying VT codes were invented for deletions

The defining congruence construction originated with Varshamov and Tenengolts for a single asymmetric error.

Levenshtein subsequently established the deletion/insertion interpretation.

137. Common failure mode: attributing the entire construction solely to Levenshtein

The correct historical attribution is:

Varshamov + Tenengolts:
modular code construction

Levenshtein:
single-deletion/insertion interpretation,
decoding theory,
bounds,
broader synchronization framework.

138. Common failure mode: excluding Levenshtein from the history

The reverse error is also misleading.

The construction's central modern significance as a deletion code comes directly from Levenshtein's work.

139. Common failure mode: treating “Levenshtein code” as one universally fixed formal definition

The phrase is used inconsistently across modern sources.

Use:

VT_a(n)

when referring to the exact modular family.

140. Common failure mode: saying VT codes are linear binary codes

They are generally nonlinear over:

GF(2).

141. Common failure mode: assuming all VT syndrome classes have equal cardinality

They partition:

2^n

words but their sizes can differ.

The zero class is largest.

142. Common failure mode: assuming perfect means maximum-size

All VT classes can be perfect under deletion-descendant coverage while having different cardinalities.

Perfect coverage and maximum packing are different notions in nonuniform deletion geometry.

143. Common failure mode: assuming finite-length optimality for every n is proven

VT codes are asymptotically optimal for one deletion.

The conjecture that:

VT_0(n)

is maximum for every finite n is a stronger statement.

144. Common failure mode: saying optimality is known only for tiny historical lengths

Modern computational work has verified binary VT optimality through:

n = 10.

145. Common failure mode: treating modulo n+1 as an arbitrary aesthetic choice

The modulus is aligned with the maximum one-deletion checksum deficiency and the number of syndrome classes required by the positional uncertainty scale.

146. Common failure mode: replacing VT syndrome with ordinary parity

Parity can reveal deleted value in some circumstances but not synchronization position.

147. Common failure mode: using Hamming distance directly after deletion

All symbols after the missing coordinate shift.

The coordinate system must first be reconstructed.

148. Common failure mode: confusing deletion with erasure

Erasure position is known.

Deletion position is not.

149. Common failure mode: treating one deletion as n independent substitution errors

That is an artifact of incorrect coordinate alignment.

In synchronization geometry it is one edit.

150. Common failure mode: claiming the decoder always identifies the physical deletion coordinate uniquely

Inside repeated runs several coordinates may be observationally equivalent.

The codeword can still be uniquely recoverable.

151. Common failure mode: applying the single-deletion decoder to two deletions

The one-deficiency identity no longer uniquely describes the channel state.

152. Common failure mode: assuming q-ary deletion correction is just binary VT with more symbols

The missing q-ary symbol value requires additional information.

153. Common failure mode: conflating VT pure-insdel geometry with software Levenshtein distance

In pure insdel geometry:

substitution
=
delete + insert
=
cost 2.

In ordinary Levenshtein:

substitution cost = 1.

154. Common failure mode: treating logarithmic redundancy as exactly log₂(n+1) in every implementation

The inequality:

r <= log2(n+1)

for the largest class is a code-cardinality statement.

Actual systematic implementations can incur integer rounding or mapping overhead.

155. Common failure mode: equating codebook cardinality with easy encoding

A large codebook does not automatically provide a convenient bijection from fixed-length user messages to codewords.

156. Common failure mode: using only asymptotic rate in practical systems

For short blocks:

log n / n

can still represent meaningful overhead.

157. Common failure mode: forgetting the intended syndrome class

The decoder must know:

a.

If syndrome class is unknown, several restored words from different classes may be possible.

158. Common failure mode: saying VT corrects arbitrary many insertions because its syndrome still exists

The classical guarantee is:

one insertion
or
one deletion.

Additional errors require stronger code structure or list-decoding assumptions.

159. Implementation: membership test

function vt_syndrome(x):

    s = 0

    for i = 1..length(x):

        s +=
            i * x[i]

    return
        s mod (length(x)+1)

Then:

x ∈ VT_a(n)

if and only if:

vt_syndrome(x) = a.

160. Implementation: deletion decoder

function decode_vt_deletion(y, n, a):

    assert length(y) == n-1

    w = 0
    checksum = 0

    for i = 1..n-1:

        w += y[i]

        checksum +=
            i * y[i]

    D =
        (a - checksum)
        mod (n+1)

    if D <= w:

        # deleted symbol was 0

        insert 0
        at a position where
        exactly D ones remain
        to the right

    else:

        # deleted symbol was 1

        L0 =
            D - w - 1

        insert 1
        after exactly L0 zeros
        from the left

    return reconstructed word

161. Implementation detail: insertion inside identical runs

If several positions satisfy the run-based condition, they can represent the same reconstructed sequence.

The implementation should therefore reason about:

resulting word

rather than treating physically equivalent positions as distinct codeword candidates.

162. Verification after decoding

A robust implementation should always verify:

length(decoded) == n

vt_syndrome(decoded) == a

deleting one symbol from decoded
can produce received y.

163. Defensive decoder

candidate =
    algebraic_vt_decode(y)

if candidate invalid:
    return FAILURE

if syndrome(candidate) != a:
    return FAILURE

if y not in D_1(candidate):
    return FAILURE

return candidate

This guards against implementation errors or channel violations.

164. Exhaustive correctness testing

For small n, test every codeword:

for x in VT_a(n):

    for position p in 1..n:

        y =
            delete(x,p)

        assert
            decode(y) == x

This directly verifies the one-deletion guarantee.

165. Exhaustive insertion testing

for x in VT_a(n):

    for position p in 0..n:

        for bit b in {0,1}:

            y =
                insert(x,p,b)

            assert
                decode_insertion(y) == x

Duplicate received strings should be deduplicated where identical insertions inside runs produce the same sequence.

166. Test both syndrome classes and lengths

Do not test only:

VT_0.

Every:

VT_a(n)

is single-deletion correcting.

A correct generic decoder should work for every:

167. Test boundary deletions

Important cases include:

delete first symbol

delete last symbol

delete first symbol of a run

delete middle of a run

delete only 1 in a sparse word

delete only 0 in a nearly-all-ones word.

168. Test checksum wrap-around

Because deficiency is computed modulo:

n+1,

and modular wrap is required.

169. Test decoder failure outside the model

Supply:

  • two deletions;
  • one deletion plus one substitution;
  • wrong target syndrome;
  • wrong original length.

The decoder should not silently claim the classical guarantee still applies.

also appears in other combinatorial settings, including certain shift-register sequence enumerations.

Sloane's survey discusses this connection and notes that the deeper structural explanation is not immediately obvious.

175. Why this is mathematically interesting

A code created for synchronization errors unexpectedly shares counting formulas with objects from:

  • periodic binary sequences;
  • shift registers;
  • number-theoretic divisor sums.

This illustrates that VT codes are not merely an engineering trick; they possess substantial combinatorial structure.

176. VT code as a partition of the hypercube

The binary hypercube:

{0,1}^n

is partitioned according to weighted subset sum:

Σ i xi
mod (n+1).

Each partition class simultaneously acts as a complete single-deletion code.

177. This is stronger than finding one good code

The construction does not merely identify:

one subset
of binary strings
with good separation.

It partitions every binary string into:

n+1

valid single-deletion-correcting classes.

178. But class quality differs by rate

Every class corrects one deletion, but:

|VT_a(n)|

varies.

Thus one can have the same correction capability with different codebook capacities.

179. Why VT0 is normally selected

If the only objective is maximizing the number of information messages at fixed block length:

choose largest syndrome class.

Since:

VT_0(n)

is largest, it is the canonical choice in many theoretical comparisons.

180. Other syndrome classes can still be useful

Different constraints may make another class convenient for:

  • systematic encoding;
  • concatenation;
  • balanced constraints;
  • application-specific forbidden patterns.

Maximum cardinality is not always the only implementation objective.

181. Adding constrained sequence requirements

Suppose the channel also forbids:

long runs

or requires:

balanced composition.

The usable code becomes:

VT_a(n)
∩
constraint_set.

This can reduce the codebook size.

182. Correction guarantee survives subsets

Any subset of a single-deletion-correcting code remains single-deletion correcting.

Therefore imposing additional constraints cannot destroy pairwise deletion separation among retained codewords.

It only reduces rate.

183. This is useful in DNA coding

A quaternary synchronization code can be intersected with biochemical constraints such as:

  • GC balance;
  • homopolymer limits;
  • forbidden motifs.

The engineering challenge becomes retaining sufficient codebook cardinality after filtering.

184. VT-style codes remain a benchmark for synchronization coding

Modern synchronization strings and multiple-deletion constructions are much more general.

Nevertheless VT codes remain the benchmark for the simplest nontrivial synchronization problem because they combine:

near-optimal redundancy
+
simple construction
+
exact correction
+
linear-time decoding.

187. Final interpretation

Varshamov-Tenengolts codes are one of the clearest demonstrations that synchronization errors require fundamentally different redundancy from ordinary bit flips.

A deleted bit hides two quantities:

its value

and:

its position.

Ordinary parity can help with the first but not the second. VT coding solves both using a weighted modular checksum:

Σ i xi
mod (n+1).

When one symbol is deleted, every surviving one to its right shifts its coordinate weight by exactly one. Levenshtein's decoding argument converts that aggregate checksum change into a simple dichotomy:

deficiency <= received weight
->
deleted bit was 0

deficiency > received weight
->
deleted bit was 1.

The same deficiency then reveals enough positional structure to restore the unique transmitted codeword.

The construction is equally striking from an information-theoretic perspective. The largest syndrome class contains at least:

2^n/(n+1)

codewords, so only about:

log2(n+1)

bits of redundancy are required. Levenshtein's asymptotic bound shows that the maximum possible binary single-deletion code has size on the order of:

2^n/n,

making VT codes asymptotically optimal.

The finite-length problem is subtler. VT optimality has been established computationally through block length 10, but universal exact optimality for every n is a stronger unresolved combinatorial claim. The difficulty comes partly from the nonuniform geometry of deletion space: different codewords have different numbers of deletion descendants.

Levenshtein's later perfect-code theory reveals an even more unusual property. Every binary VT syndrome class is a perfect single-deletion code, even though different classes can contain different numbers of codewords. This is possible because their deletion balls have unequal sizes.

The most important historical point is equally precise. Varshamov and Tenengolts supplied the modular construction. Levenshtein recognized and proved its extraordinary synchronization-error capability and embedded it in a much broader theory of insertion/deletion correction. The result is why modern literature sometimes speaks of the Varshamov-Tenengolts-Levenshtein tradition of deletion coding.

More than sixty years later, VT codes remain a canonical example of how the geometry underlying Levenshtein distance can be used not merely to measure sequence corruption after it occurs, but to design sequences that make the corruption exactly reversible.
