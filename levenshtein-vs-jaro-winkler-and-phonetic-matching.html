Levenshtein vs Jaro-Winkler and Phonetic Matching

Levenshtein distance, Jaro-Winkler similarity, and phonetic matching are frequently used for the same practical task—finding names, words, or records that “look similar”—but they model three fundamentally different kinds of resemblance.

Levenshtein:
How many sequence edits separate the spellings?

Jaro / Jaro-Winkler:
How strongly do nearby characters correspond,
and how much of their ordering is preserved?

Phonetic matching:
Do the spellings map to similar pronunciations
under a phonetic representation?

These are not interchangeable questions.

The strings:

MARTHA
MARHTA

illustrate a local ordering error. Jaro gives high similarity because almost every character can be matched inside its positional window, while its transposition component detects the changed order. Jaro-Winkler increases the score further because the strings share the prefix MAR.

By contrast:

SMITH
SMYTH

illustrates a spelling difference that preserves pronunciation especially well. Soundex deliberately maps both surnames into the same phonetic code.

And:

ABCDE
ABXDE

is naturally described by Levenshtein distance as one substitution, without requiring assumptions about names or pronunciation.

The appropriate method therefore depends on what variation the application wants to tolerate:

orthographic edits?

near-position character rearrangement?

shared prefixes?

pronunciation variation?

transliteration?

nicknames?

aliases?

real-world entity identity?

This article develops these distinctions rigorously, derives the Jaro and Jaro-Winkler formulas, explains their historical connection to record linkage, compares them with Levenshtein geometry, examines Soundex, NYSIIS, Metaphone, Double Metaphone, and phoneme-level edit distance, and shows why none of these techniques alone establishes that two records represent the same person, organization, place, or other real-world entity.

1. Three different similarity spaces

It is useful to begin by separating three spaces.

Orthographic edit space

spelling
->
insert/delete/substitute
->
minimum edit distance.

Character-correspondence space

characters
->
nearby matching positions
+
ordering consistency
+
optional prefix emphasis.

Phonetic space

written form
->
phonetic representation
->

2. They produce different invariances

Method family What it tries to tolerate What it directly preserves
Levenshtein Insertions, deletions, substitutions Global sequence order
Jaro Nearby character displacement and partial ordering variation Character identity within positional windows
Jaro-Winkler Jaro variation plus favored common prefix Beginning-of-string agreement
Soundex/NYSIIS/Metaphone Selected spelling differences associated with similar pronunciation Rule-defined phonetic classes

3. “Name similarity” is not one mathematical problem

Suppose a customer database contains:

Jon Smith
John Smith
J. Smith
Jonathan Smith
Jon Smyth
Smith, Jon
Sean Smith.

Different pairs involve different transformations:

  • missing character;
  • abbreviation;
  • nickname;
  • phonetic spelling;
  • token reordering;
  • possibly entirely different names.

No single character comparator models all of these transformations correctly.

4. Levenshtein distance

Classic Levenshtein distance allows three primitive operations:

insertion

deletion

substitution.

Under unit costs:

dL(x,y)
=
minimum number
of those operations
needed to transform x into y.

5. Dynamic-programming recurrence

For:

X = x1...xm

Y = y1...yn,

initialize:

D(i,0) = i

D(0,j) = j.

Then:

D(i,j)
=
min(
 D(i-1,j) + 1,
 D(i,j-1) + 1,
 D(i-1,j-1)
 + [xi != yj]
).

6. Levenshtein produces a true edit distance

Its score has an explicit transformation interpretation.

For:

JOHN
JON

one deletion is enough:

JOHN
->
JON.

Therefore:

dL = 1.

7. Levenshtein does not know these are names

The exact same recurrence can compare:

  • DNA symbols;
  • source tokens;
  • event IDs;
  • ordinary words;
  • surnames.

This generality is one of its greatest strengths.

8. The same generality is also a limitation for names

Unit-cost Levenshtein does not know:

  • which name positions are especially informative;
  • which spellings sound alike;
  • which abbreviations are conventional;
  • which nicknames correspond;
  • which names are common in a population.

9. Uniform substitution costs

Classic Levenshtein treats:

SMITH
->
SMYTH

and a substitution between two completely unrelated characters as the same one-unit event.

10. Weighted edit distance can improve this

A domain model can use:

c_sub(x,y)

c_ins(y)

c_del(x).

See weighted Levenshtein distance.

But even weighted orthographic edits do not automatically create a pronunciation model.

11. Jaro was developed in record-linkage context

Matthew Jaro's work addressed matching records where identifying text fields such as names may contain errors or legitimate variation.

His 1989 paper describes record-linkage methodology used around the 1985 Census of Tampa, Florida.

See Jaro, 1989.

12. Jaro does not compute a minimum edit script

This distinction is fundamental.

Jaro asks approximately:

How many characters
can be matched between
the two strings
within reasonable positional windows,

and

how consistently ordered
are those matched characters?

13. Jaro therefore belongs to a different family of comparison models

Levenshtein:
optimization over edit paths

Jaro:
heuristic/statistical-style
character correspondence.

14. Jaro matching window

In the widely used modern formulation, a character is eligible to match an identical character in the other string only when their positions differ by no more than approximately:

w
=
floor(
 max(|X|,|Y|) / 2
)
-
1.

Implementations normally clip negative windows to zero for very short strings.

15. Matching is not unrestricted

If an identical character occurs very far away in the other string, Jaro may not count it as a match.

This reflects the record-linkage intuition that:

small positional displacement
can plausibly arise from data-entry error,

large displacement
is less convincing.

16. Define the matched-character count

Let:

m
=
number of matched characters
within the allowed positional window.

Each character occurrence should be matched at most once.

17. Repeated characters make matching nontrivial

Consider:

ANNA

NANA.

Several identical letters occur.

An implementation must identify which occurrences correspond.

18. Jaro's “transposition” terminology is easy to misunderstand

After identifying matching characters, extract those matches from each string in sequence order.

Compare the two matched-character sequences.

Let the number of positions where those matched sequences disagree be:

q.

Then Jaro uses:

t = q / 2.

19. Jaro transposition is NOT a Damerau transposition

This is one of the most important distinctions in this article.

Damerau-Levenshtein transposition:
one primitive operation
swapping two adjacent symbols.

Jaro transposition quantity:
half the number of out-of-order
matched-character disagreements.

They should not be interpreted as the same object.

20. Jaro does not search for a minimum number of swaps

The variable:

t

is part of its correspondence score.

It is not a shortest edit-script length.

21. Jaro similarity formula

If:

m = 0,

define:

J(X,Y) = 0.

Otherwise:

J(X,Y)
=
1/3
[
 m/|X|
 +
 m/|Y|
 +
 (m-t)/m
].

22. Three components

The terms represent:

m / |X|
=
coverage of X

m / |Y|
=
coverage of Y

(m-t) / m
=
ordering agreement
among matched characters.

23. Jaro returns similarity rather than edit count

Conventionally:

0
=
little/no similarity

1
=
maximum similarity.

This direction is opposite to ordinary edit distance:

Levenshtein:
smaller = closer

Jaro similarity:
larger = closer.

24. Be careful with APIs named “distance”

Some libraries return:

similarity J.

Others define:

distance
=
1 - J.

Always inspect the API.

28. Compare with Levenshtein

Classic Levenshtein does not contain a transposition primitive.

For:

MARTHA
MARHTA,

two substitutions suffice:

dL = 2.

29. True Damerau-Levenshtein would treat the adjacent swap differently

If adjacent transposition is one primitive operation:

dDL = 1.

The detailed distinction is covered in Levenshtein vs Damerau-Levenshtein and Hamming distance.

30. Jaro does not say “one edit”

It says:

very high partial character agreement
with limited order disagreement.

31. This is why comparing raw Jaro and Levenshtein numbers is meaningless

Levenshtein = 2

Jaro = 0.9444.

The units are completely different.

32. Jaro-Winkler adds common-prefix emphasis

William Winkler extended Jaro-style comparison for record linkage by increasing scores when the beginnings of strings agree.

The 1990 paper String Comparator Metrics and Enhanced Decision Rules in the Fellegi-Sunter Model of Record Linkage describes the approach in the U.S. Census matching context.

See Winkler, 1990.

33. Common modern Jaro-Winkler formulation

Let:

J
=
Jaro similarity

l
=
common prefix length
usually capped at 4

p
=
prefix scaling factor.

Then:

JW
=
J
+
l p (1-J).

34. Typical scaling value

A commonly used value is:

p = 0.1.

For the simple form with:

l <= 4,

keeping:

p <= 0.25

prevents the prefix term from pushing the basic expression beyond one.

35. MARTHA/MARHTA common prefix

They begin with:

MAR.

Therefore:

l = 3.

36. Jaro-Winkler calculation

With:

J = 17/18

p = 0.1

l = 3,

JW
=
17/18
+
3(0.1)(1-17/18)

0.961111.

37. Prefix agreement raises the score

Jaro:
0.944444

Jaro-Winkler:
0.961111.

That difference is intentional.

38. The prefix boost encodes a domain assumption

It assumes agreement at the beginning of a string deserves additional confidence.

This was motivated by name/record-linkage behavior, not by a universal theorem of string similarity.

39. Prefix weighting can improve name matching

If errors frequently occur later in a name, two strings sharing their initial characters may be more plausible variants.

40. Prefix weighting can also hurt

Suppose a corpus contains many identifiers sharing a standard prefix:

ACME-ACCOUNT-...

ACME-ASSET-...

ACME-ACCESS-...

Prefix similarity may contribute little discriminative evidence.

41. Common prefixes can generate false confidence

If thousands of unrelated entities begin with:

Mohamed

or:

International

or some standardized corporate prefix, initial agreement should not automatically dominate identity decisions.

42. Jaro-Winkler's prefix assumption is field-specific

It can be useful for:

  • short personal names;
  • surnames;
  • some standardized textual fields.

It may be inappropriate for:

  • random identifiers;
  • cryptographic strings;
  • suffix-important fields;
  • codes where every position is equally significant.

43. Historical Jaro-Winkler and modern implementations are not always identical

This point deserves explicit attention.

Winkler's original Census work combined partial string agreement with record-linkage weighting procedures and documented empirical comparator values.

Modern software libraries often expose a simplified, standardized-looking formula:

J
+
l p (1-J).

44. Library results can therefore differ

Differences may arise from:

  • matching-window convention;
  • greedy matching of repeated characters;
  • prefix scaling;
  • prefix caps;
  • additional historical adjustments;
  • whether a boost is conditional;
  • normalization and preprocessing.

45. Do not assume “Jaro-Winkler” uniquely identifies one implementation

For reproducible research, record:

library

version

matching-window rule

prefix cap

p value

preprocessing

similarity/distance convention.

46. Jaro-Winkler is not phonetic matching

This is another major conceptual boundary.

Jaro-Winkler examines characters and their positions.

It does not convert letters into pronunciations.

Jaro-Winkler
=

231. Common failure mode: Jaro-Winkler is Levenshtein with different weights

False.

Jaro uses positional character matching and an order-disagreement term rather than minimum edit-path optimization.

232. Common failure mode: Jaro transposition equals Damerau transposition

False.

Jaro's transposition quantity is derived from out-of-order matched characters.

Damerau transposition is an explicit adjacent swap operation.

233. Common failure mode: Jaro-Winkler is phonetic

False.

It compares orthographic characters.

234. Common failure mode: Soundex is a distance metric

Classic Soundex primarily produces a code.

Code equality is not a graded edit distance.

235. Common failure mode: same Soundex means same pronunciation

Soundex is a coarse rule system.

Collisions occur.

236. Common failure mode: different Soundex means different pronunciation

Rule boundaries, first-letter preservation, and language mismatch can separate genuinely similar pronunciations.

237. Common failure mode: Metaphone solves every language

It is a rule-based phonetic model with language assumptions.

238. Common failure mode: Double Metaphone means two independent similarity scores

It typically produces primary and optionally secondary phonetic encodings for plausible pronunciations.

239. Common failure mode: phonetic equality proves one person

It proves only agreement under the phonetic coding model.

240. Common failure mode: Jaro-Winkler 0.95 means 95% same person

It does not.

241. Common failure mode: normalized Levenshtein 0.95 means the same thing as Jaro-Winkler 0.95

The score spaces are constructed differently.

242. Common failure mode: thresholds transfer across comparators

A threshold calibrated for Levenshtein similarity should not be reused automatically for Jaro-Winkler.

243. Common failure mode: thresholds transfer across fields

A good threshold for surnames may be poor for street names or organization names.

244. Common failure mode: thresholds transfer across languages

Different orthographies and name distributions produce different score distributions.

245. Common failure mode: prefix agreement is always informative

Common prefixes can be extremely frequent and weakly discriminative.

246. Common failure mode: suffix differences are always less important

That is not universally true across naming systems or identifier types.

247. Common failure mode: the first four characters are intrinsically special

The four-character prefix cap belongs to a particular Jaro-Winkler design convention, not a universal property of text.

248. Common failure mode: every Jaro-Winkler library implements the same algorithm

Matching rules, prefix handling, preprocessing, and historical adjustments can differ.

249. Common failure mode: Jaro-Winkler is a mathematical metric because it is called a distance

The commonly used transformed dissimilarity should not be assumed to satisfy metric axioms such as triangle inequality.

250. Common failure mode: higher lexical similarity always improves record linkage

Two different people can have nearly identical names.

251. Common failure mode: phonetic preprocessing should replace original names

Keep the original representation for downstream evidence and explanation.

252. Common failure mode: case folding is always safe

It depends on the application and identifier semantics.

253. Common failure mode: removing diacritics is always safe

Diacritics can carry lexical and phonological distinctions.

254. Common failure mode: transliteration equals phonetic transcription

They solve different representation problems.

255. Common failure mode: phonetic algorithms remove the need for multilingual evaluation

They make multilingual validation more important, not less.

256. Common failure mode: exact name equality proves identity

Duplicate names exist.

257. Common failure mode: different names prove different entities

Aliases, name changes, transliteration, and data-entry corruption exist.

258. Common failure mode: one similarity function should make the final linkage decision

Strong entity resolution combines multiple independent fields.

263. Reference pseudocode: Jaro similarity

function jaro(A, B):

    if A and B are both empty:
        return 1

    if exactly one is empty:
        return 0

    radius =
        max(
          0,
          floor(
            max(len(A), len(B)) / 2
          ) - 1
        )

    matched_A =
        boolean array len(A)

    matched_B =
        boolean array len(B)

    matches = 0

    for i in A:

        search B positions
        from i-radius
        through i+radius

        find an unmatched
        identical character

        if found:
            mark both matched
            matches += 1

    if matches == 0:
        return 0

    sequence_A =
        matched chars from A
        in original order

    sequence_B =
        matched chars from B
        in original order

    mismatched_order =
        count positions
        where sequence_A[k]
        != sequence_B[k]

    transpositions =
        mismatched_order / 2

    return
        (
          matches/len(A)
          +
          matches/len(B)
          +
          (matches-transpositions)
            / matches
        ) / 3

265. Reference pseudocode: common modern Jaro-Winkler

function jaro_winkler(A, B, p=0.1):

    J =
        jaro(A, B)

    prefix = 0

    while prefix
          < min(
              4,
              len(A),
              len(B)
            )
          and
          A[prefix] == B[prefix]:

        prefix += 1

    return
        J
        +
        prefix
        * p
        * (1-J)

283. Final interpretation

Levenshtein distance, Jaro-Winkler similarity, and phonetic matching are powerful precisely because they model different forms of variation.

Levenshtein distance is the cleanest of the three mathematically. It defines a sequence geometry through insertion, deletion, and substitution. When name variation can reasonably be described using those edits, it provides an interpretable answer:

the minimum number
of configured sequence edits
between the two spellings.

Jaro changes the problem. Instead of searching over edit scripts, it identifies identical characters within positional windows and combines three quantities: the proportion of each string that was matched and the degree to which matched characters preserve order. The quantity historically called a transposition inside Jaro is therefore not the adjacent-swap operation used by Damerau-Levenshtein. It is an order-disagreement statistic over matched characters.

Jaro-Winkler then adds another assumption: agreement at the beginning of the strings deserves additional weight. In many record-linkage settings this is useful. It can also be inappropriate when common prefixes carry little information. The prefix boost should therefore be understood as domain-specific inductive bias, not as a universal improvement to string distance.

Phonetic algorithms move the problem to another representation altogether. Soundex maps surname spellings into coarse pronunciation-oriented codes and was historically used to retrieve differently spelled census surnames such as SMITH and SMYTH. NYSIIS applies a different family of name-transformation rules. Metaphone uses richer English-oriented phonetic rules, while Double Metaphone can produce primary and secondary encodings for pronunciation ambiguity.

These encoders create invariance by deliberately throwing information away. That is both their power and their limitation. Orthographically different names can meet in the same phonetic bucket, increasing recall. Unrelated names can also collide in that bucket, reducing precision.

A more expressive phonetic system can transform names into phoneme sequences and then apply edit distance to those sequences. This illustrates an important general principle:

and

are separate design decisions.

Levenshtein over characters measures orthographic edits. Levenshtein over phonemes measures phonetic-sequence edits. The recurrence can remain unchanged while the meaning of the resulting distance changes fundamentally.

The strongest real-world architecture therefore does not ask which one of these methods should “win.” It assigns each one the job its assumptions justify.

Levenshtein can quantify ordinary spelling edits. Jaro-Winkler can provide a useful short-field correspondence feature for typographical name variation. Phonetic encoders can retrieve pronunciation-oriented spelling variants. Transliteration and alias dictionaries can handle relationships neither character nor pronunciation distance captures. Other record attributes can then determine whether the accumulated evidence actually supports an entity match.

For serious entity resolution and record linkage, that last distinction is decisive:

similarity algorithms
generate evidence.

They do not create identity.
